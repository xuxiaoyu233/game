# 放置主循环样板：采用方式与兼容映射（实施前冻结）

日期：2026-10-20。依据根 [PLAN.md](../../../PLAN.md) 最新活动顺序第 2 步“放置主循环样板”。本文件在编码前冻结采用方式；实施结果另见同目录交付文档。

## 1. 样板选择与依据（核对过源码的事实）

- `shared/sandbox/camp-skills.ts`：`CAMP_ACTIVITIES` 共 10 个作业。其中伐木 3 个、采石 3 个**没有任何 `building`/`research` 字段**；农事 2 个需 `WheatFarm`（精耕另需 `field-irrigation`），木工 2 个需 `LumberMill` + `wood-processing`。
- `shared/sandbox/camp-economy.ts`：`activityBlock` 与命令 `train` 分支共用同一判定（等级/研究/设施），输入库存与仓容只是运行时等待、不是锁。
- `src/scripts/sandbox/camp-training.ts`：`tickCampTraining` 注册在原 `postTickTiles` 边界，在线与离线同一条路径；产物直接入 HQ 库存，经验写入 `profile.skillXp`。
- 结论：**新档不建任何建筑即可完成“伐木/采石”从 Lv1 到 Lv10 的完整训练循环**（Lv3/Lv6 作业只要求技能等级）。样板技能取**伐木**（内容表第一项，产物木材是建设与加工的共有原料）。

## 2. 不动的部分（兼容映射）

| 项 | 处理 |
| --- | --- |
| 规则与数值 | `CAMP_ACTIVITIES`、`SKILL_XP_THRESHOLDS`、`planTrainingTick`、`tickCampTraining`、`skillYield` 等全部不改；不扩充技能或规则包 |
| 命令与队列 | `camp-commands.ts` 全部命令（train/build/upgrade/research/expand/promote/enter-workshop/gather/relief/pause/priority）不改；建造/研究/晋升/扩地/人口/求援保留可用 |
| 存档 | schema5 / content `d1-c-1` 不变；本批无迁移。目标建议顺序、默认页签都是 UI 状态，不入档（`camp-navigation.ts` 既有约定：tabs/selection 不持久化） |
| 既有入口 | 地块面板、研究页、民生页、设置页、资源定位与返回、缺项导航全部保留；农事/木工的设施前置不放松也不加严 |
| 旧档 | 打开后按新建议顺序显示，无需迁移；进行中的训练、库存、等级原样接续 |

## 3. 改动的部分（只做“主循环的组织方式”）

1. **`shared/sandbox/camp-goal-plan.ts`（纯决策）**：决策顺序从“建筑链优先”改为**成长优先**：
   1. 真实短缺（口粮/饮水不足，影响劳力与移入）——保持警告与合法动作不变；
   2. 训练状态——空闲且存在可立即开始的作业时建议“开始一项作业，自动循环积累”（动作：打开技能页，**不自动替玩家选择训练目标**）；进行中时展示当前成长与下一解锁；等待原料/仓容说明原因并保留进度；前置不满足给出原因与入口；
   3. 既有建筑链/研究/工坊/晋升逻辑整体后移，作为成长路线没有待办时的下一项可达成长。
2. **`shared/sandbox/camp-goals.ts`**：facts 增加训练快照（经 `camp-status` 的同一只读投影，不新建第二状态源）；`campNextGoal` 接受可选 stock 参数，与 HUD 共用一次聚合。
3. **`src/scripts/ui/sandbox/CampHud.tsx`**：focus strip 以“当前作业/成长进度”为主体直读；footer 去掉常驻“保存进度”按钮（正常保存收进设置页），保存失败仍持续可见并指明重试入口。
4. **`src/scripts/ui/sandbox/CampSkillsPage.tsx`**：训练空闲时在状态区显示样板建议（伐木·拾取枯枝：4 秒/次、+1 木材、+2 XP，带“开始”主动作），技能卡与缺口导航不变。
5. **`src/scripts/ui/sandbox/camp-navigation.ts`**：默认页签从 `camp` 改为 `skills`（打开游戏先看到成长主循环；点地图/选择地块仍回 `camp`，UI 状态不持久化）。
6. **CSS（`sandbox-tokens.css`）**：strip 与空闲建议的样式微调，不新建一套组件。
7. **`tests/camp-goals-contract.mjs`**：顺序断言按本采用方式更新（计划授权的方向变更，非规则变化）。

## 4. 影响评估（对应 PLAN 的硬性要求）

- **自动产出/资源来源**：伐木训练产物入 HQ 库存的路径不变；资源条读数与“定位来源”不变。移除“goal 催促建设”不影响任何自动产出。
- **作业条件**：农事/木工的设施与研究前置原样保留，并在技能页明示为“未解锁 + 原因 + 前往入口”，不构成隐形卡住——新档可立即开始的作业恒有 2 个（拾取枯枝/拾取碎石），Lv10 前全程可达。
- **不会软锁**：新档储备口粮 24、饮水 36，约 10 分钟（20 成人）后进入短缺分支；该分支仍警告并给出合法动作（建厨房/水井链或紧急求援），不会因不再催促建设而无路可走。
- **不新增**：第二套库存、第二份进度、自动建造 AI、奖励定时器、肉鸽选择、人口/食水规则变化——均不做。
- **审美/场景**：本批只做暖纸色界面内的信息组织（沿用 V2 已交付的 token 与外壳）；不铺满 11 槽、不新增素材；场景随真实进度自动完善属于 PLAN 第 3 步，本批不碰。

## 5. 验收对应（PLAN 第 2 步退出条件）

1. 不点地图、不建农田/仓库完成样板技能循环：新档默认技能页 → 开始拾取枯枝 → 自动循环（产物/XP 入账）→ 等级解锁后续作业。
2. 一份库存/进度：无新状态源；strip、技能页、资源条读同一快照。
3. 正常状态不重复提示：strip 一行摘要；详情只在技能页操作区。
4. 刷新与离线接续：tick 边界未动；浏览器实测刷新与短离线后训练继续、产物不重领。
