## 2. 本轮自查发现并修正的问题

1. **状态类目标误加“下一步：”前缀**：短缺时 strip 读作“下一步：口粮与饮水供应不足”，语义错位。改为按目标 ID 区分状态类（`shortage`/`reserve-falling`/`construction`/`workshop-blocked` 与 `training*`）不加前缀。
2. **strip 空闲文案与目标建议重复**：原为“选择一项作业…”+“训练空闲”，同一件事说两遍。改为右侧显示“可开始 N 项”，空闲时不再与建议重复。
3. **每渲染重复投影**：HUD 与目标顾问各自调用 `campTrainingStatus`、各自扫描可开始作业。改为 HUD 计算一次并传入 `campNextGoal`。

## 3. 自查中被排除的误判（如实记录）

- 过程中一度怀疑“从技能页切入地图后点击建筑选不中”，并观察到点击建筑区域内若干点后面板不切换。经开发构建读取真实相机（单一 Camera，position 0、pivot −185/−37、zoom 0.903）与 `camera.toGlobal` 计算、再用裁剪截图测量：小屋实际渲染在页面 (745,437)，与 `toGlobal` 完全一致；此前“小屋在画面中央”的判断来自缩略截图目测误差。
- 修正测量后实测：点建筑主体 (745,400) → 面板“小镇中心”；点建筑底部 (745,440) → “小镇中心”；点空地 (520,620) → 面板保持不变（正确行为）。**点击区与渲染对齐，`pickCamp` 轮廓命中与 tile 兜底均有效。**
- 结论：不存在点击错位缺陷。V2 交付中“点击区对齐”只凭截图核对、未做点击实测的表述不够严谨，本轮已用可复现方式补齐（测量方法留在 `.cache/v3-*.mjs`）。

## 5. 剩余判断（需用户/规划确认，不在本批擅自改）

- 技能页空闲时，状态区“开始××”与卡片内同一作业的“开始”按钮并存：前者是“推荐”，后者是“任选列表”。命令幂等、不会重复发奖；训练中卡片按钮变灰为“进行中”。若视为“重复承担同一任务”，可只保留一处，建议保留状态区（PLAN 要求空闲时给出一个明确开始动作），由用户定夺。
