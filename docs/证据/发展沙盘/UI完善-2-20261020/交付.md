日期：2026-10-20。执行方：CodeBuddy。依据 [UI 完善执行提示词](../../交接/CodeBuddy-UI完善执行提示词.md) 的 A/B/C 三项。只改展示层：技能页图标、键盘操作、反馈节奏；规则、数值、命令、存档、schema5/`d1-c-1` 未动。

## 1. 先说清楚工作树里已有的事实

开工核对时发现工作树中**已存在**一部分本批内容，来源不是本批写入：

- `public/icons/` 下 14 个自绘 SVG（4 技能徽记 + 10 作业图标）与 `src/scripts/art/sandbox-art-catalog.json` 中对应的 14 条资产登记（`sourceId: camp-ui-icons-20261020`，`integration: ui-2-skills-page`）。
- `CampSkillsPage.tsx` 中已有技能/作业图标映射常量与 `onSkillRailKeyDown`（方向键 + Home/End + roving `tabIndex`）。

本批没有重复实现这些，而是**校验、收敛与落实**：

| 动作 | 结果 |
| --- | --- |
| 素材与登记一致性 | 14/14 文件 SHA256 与 catalog 记录一致 |
| 映射收敛 | 原先页面内两份常量与 HUD 的资源图标表各自为政；收敛为 `camp-resource-icons.ts`（资源）与 `camp-skill-icons.ts`（技能 + 作业 + 回退链），页面内常量删除 |
| 显示落实 | 技能轨徽记 18→20px 并按技能着色（伐木绿/采石灰/农事金/木工褐），选中态白；动作行图标 15→17px、图标槽 26→28px 加对比；当前动作卡 17px |
| 回退链 | `activityIconKey(id, skill, resource)`：作业图标 → 技能徽记 → 资源图标，新作业未登记也不会空槽 |

## 2. A/B/C 三项目前状态

**A. 图标**：技能轨用 `skill.*` 徽记，动作行与当前动作卡用 `activity.*`，全部经 `CampArtIcon` 的 CSS mask 渲染，颜色由所在表面决定。逐项核对：4 个技能徽记解析到 `skill-woodcutting/mining/farming/carpentry.svg`，3 个可见作业行解析到对应 `activity-*.svg`，无 404、无第二份图。

**B. 键盘**：技能轨为单一 tab 停靠点（`tabIndex` 只有选中项为 0），`ArrowLeft/Right` 循环、`Home/End` 跳首尾，焦点与选中同步；焦点环 `outline: 3px solid #235f75`。实测：焦点/`aria-selected`/面板 `data-skill` 三者一致。

**C. 动效**：周期闪烁 0.42s→0.4s 且强度降低（底色更淡、外扩 4px→3px），飘字上浮 16px→14px、起始缩放 0.9→0.92，升级提示 1.4s→1.6s（读得完“升至 LvN · 解锁××”），徽章脉冲保持 0.9s。同一秒内只有一种反馈：闪烁在动作卡、脉冲在徽章、飘字在资源芯片，互不覆盖。

## 4. 已知限制

- 14 个图标是“粗轮廓单色徽记”，在 17–20px 下可辨但谈不上插画质感；若要接近 RuneScape/Melvor 的徽章厚度或手绘质感，需要重绘而非调尺寸。
- 方向键只在技能轨内生效，没有跨页面的全局快捷键；这符合当前“不引入全局快捷键”的约定。
- 满级仍无法在 200 仓容下自然到达，满级样式只能以注入样例验证。
- 动效参数（0.4s / 0.9s / 1.6s / 420ms）为本轮观察后的取值，**未经真人试玩**校准。
- 本批与工作树中并行存在的改动同处一文件，已在第 1 节如实说明；后续如有第二写入者，应先比对哈希再改。
