## 结论

F1–F4 全部按复核方向修复，并用受控时钟、合成 visibility、故障注入在浏览器中定向复现验证：

- F1：时间消费拆为「内存边界」与「磁盘边界」，隐藏保存失败不再重算已在线推进的区间（复现例从 124 tick 降为约 2 秒新增量）；补算后提交失败只保留待提交状态，后续恢复只算新增时间。
- F2：加载/恢复/恢复提交与在线推进共用生命周期屏障；恢复期间常规 tick 入口被阻断（146→146），首次提交失败显示可重试错误页且不启动 ticker。
- F3：只有键不存在才算无档；空字符串与非字符串值进入恢复页并保留，空字符串可导出。
- F4：`{"options":{}}`、缺 current、tiles 非法、城市非法四类结构损坏均在约 1.1 秒内进入恢复页，原值保留。

## F1 时间消费边界

**修复**（`Global.tsx`、`logic/ClientUpdate.tsx`、`Bootstrap.tsx`）：

- 新增 `memoryConsumedAt`（内存已推进到的时刻）与 `diskCommittedAt`（磁盘快照 paired 的 savedAt）；在线 tick 与离线补算完成后推进内存边界。
- `doSaveGame` 写入的 `savedAt` 改为 `memoryConsumedAt`，不再是保存时刻——磁盘快照与时间始终同源，重载按二者恢复。
- 后台恢复的补算起点改为 `memoryConsumedAt`（不再使用 `lastActivityAt`/保存 Promise 完成时间）：隐藏保存失败时磁盘保持旧的一致状态，恢复只补算内存边界之后的新增时间。
- 补算完成后先推进内存边界再提交；提交失败保留内存结果与待提交状态，重试只提交不再次领取。

**验证**（`.cache/d0r-fix-verify.mjs`，受控时钟 + 合成 visibility + put 注入）：

## F2 恢复互斥与首次提交屏障

**修复**（`Global.tsx`、`logic/ClientUpdate.tsx`、`Bootstrap.tsx`、`ui/SaveCommitFailedPage.tsx`、`css/Main.css`）：

- 新增生命周期 `loading → recovering → ready | failed`：`shouldTick()` 仅在 `ready` 且页面可见时为真；恢复期间常规 tick、WorldScene 动作与常规保存全部暂停，并显示恢复遮罩（`body.civ-recovering`）。
- 启动：补算前 `beginRecovery()`，补算后 `markSaveReady()` → `await commitSnapshotDirect()`（共享队列的内部提交，不经过自身屏障，避免死锁）→ 成功 `markGameReady()` 才启动 ticker；失败 `markCommitFailed()` 并路由到 `SaveCommitFailedPage`（重试提交/导出/重载/新档），`return` 不启动游戏。
- 后台恢复：`beginRecovery()` → 补算 → 推进内存边界 → 内部提交 → 成功 `markGameReady()`；失败进入 `failed` 态并弹出「Retry commit」模态，保留内存与磁盘旧值。
- `saveGame()` 在 `failed` 态拒绝写入；`markCommitFailed()` 会拒绝屏障期间挂起的保存调用方，避免永久 pending。
- 错误页/加载中不启动恢复：`visible` 分支先检查 `isGameReady()`。

**验证**：

| 用例                                                     | 结果                                                                                        |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 4 小时模拟后台（受控时钟）恢复期间调用同一常规 tick 入口 | 146→146 不推进；`isGameReady=false`；恢复完成后 `ready=true`、tick 14402、遮罩已移除        |
| 新档首次提交注入 savedAt 失败                            | 显示「Save Commit Failed」+ 重试项；调试钩子不存在（ticker 未启动）；游戏界面未进入可玩状态 |

## F3 无档判断

**修复**（`Global.tsx`、`ui/SaveRecoveryActions.tsx`）：

- `idbGet` 返回 `undefined` 才视为键不存在（`none`）；空字符串、非字符串内容都按坏档保留并进入恢复页。删除与 `SaveKey` 同值的重复「旧压缩档」读取分支，不再声称存在独立迁移。
- `readRawSaveBytes()` 对空字符串返回 `""`（仅缺键/读取失败返回 null）；导出操作改用 `raw === null` 判断，空档可导出。

**验证**：

| 点击导出                      | 出现「Raw save data exported」，不再提示无数据   |
| 现有值设为数字 `12345` 后重载 | 进入恢复页且原值保留                             |
