### 需要明确、不能夸大的边界

1. **后台保持打开的恢复**：`shouldTick` 在 `document.hidden` 时停止推进；新增监听器只在隐藏时保存，返回可见时没有复用加载补算。静态路径显示这类时间未被统一处理；本轮未进行真实后台停留实验。D0-R 要核对并补足，避免只支持“关闭再打开”。
2. **视觉兼容性尚未证明**：已确认 `Grid.ts:46` 使用 pointy 六角网格，`TileVisual.ts:93` 建筑锚点为中心。色块截图只证明场景能渲染，不证明底部锚点、建筑遮挡排序、点击和目标手绘斜俯视画面可直接兼容。应改为“逻辑网格可复用，表现层需小样验证”；不因而立即换网格或引擎。
3. **根工具隔离不完整**：根 `format:check` 使用 `prettier --check .`，`.prettierignore` 仅排除了 Profectus。本轮 `--file-info next/civ-idle/src/scripts/Global.tsx` 返回 `ignored:false`，上游文件会进入根格式检查/写入范围。补对应目录忽略并检查 ESLint 范围，分别使用各工程工具；不通过全仓格式化解决。
4. **UI 尚有后期和联机入口**：D0 保留原界面可以接受，但首版不应继续暴露云恢复、交易、转生、伟人和后期内容。尤其 `SaveCorruptedPage` 的服务器恢复函数先重置内存再请求已停用服务；D0-R 应替换不可用且影响恢复的入口，其他产品菜单在 D1 限定。
5. **Node 与构建记录**：CodeBuddy 的构建环境为 Node 20；本轮证实 Node 24 开发启动，修复交付时应以项目 Node 24 工具链做一次目标工程构建。初次沙箱内 SWC 原生绑定加载失败，授权环境同一源码启动成功，不能将前者判为 Node 24 不兼容。
