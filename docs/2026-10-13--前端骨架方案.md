# 前端骨架方案：以 Melvor Idle 为参照重建界面外壳（S2）

日期：2026-10-13
输入版本：`8fe7cb6`（P4-D-U3 完成）
决策（用户 2026-10-13 选定）：**全量外壳** + **最小窗口保持 360×480** + **骨架完成后再做真人试玩**

## 1. 为什么先做骨架

- 骨架决定内容怎么表达：技能页、银行、商店的容器形态，直接决定第三档配方、消费端与故事往哪里塞。当前内容只有 2 技能 / 6 物品 / 6 活动 / 3 工具提升，**此时改骨架成本最低**。
- 真人试玩排在骨架之后：现在试玩的是即将被替换的三页签结构，反馈会作废。

## 2. 参照依据

Melvor Idle 的界面结构（官方 wiki [Beginners Guide](https://wiki.melvoridle.com/index.php?title=Beginners_Guide)）：界面分**左侧菜单**（每个技能一个按钮 + 银行 + 商店 + 设置；当前训练的技能显示绿色）、**顶部栏**（当前页面、装备/药水）、**右侧 minibar**（熟练度、里程碑、快速装备）、**主区**（技能页 / 银行 / 商店 / 设置）。技能页结构为：顶部经验条 + 该技能可选动作的瓦片（名称、每次经验、耗时、熟练度）+ 选中后「开始」；加工类技能还需「设施」（如烹饪火，需燃料或商店购买）。离线推进上限 12 小时。

本轮只读了该页面的公开正文，未运行或试玩 Melvor；不照搬数值、物品数量与系统全集。

## 3. 目标信息架构（360×480 单列）

**结构同构，形态压缩。** 导航层级照搬 Melvor（技能为中心），空间形态从三栏并排改为纵向分区——360 宽放不下左菜单 + 主区 + 右栏。

```
┌──────────────────────────────┐
│ 标题栏：标题 + 简洁/置顶/收起        │
├──────────────────────────────┤
│ 当前活动条：活动名 + 周期进度 + 暂停   │  ← Melvor 顶部经验条 + 左菜单当前技能高亮
├──────────────────────────────┤
│ 下一步：缺料建议 / 解锁提示           │  ← 本项目差异化，Melvor 没有，保留
├──────────────────────────────┤
│ 主导航条：技能 · 银行 · 商店 · 装备 · 熟练 │  ← Melvor 左菜单压缩为一条
│   [采掘 Lv2] [金属加工 Lv1]          │    技能项显示等级，当前技能高亮
├──────────────────────────────┤
│ 主区（滚动）                        │
│   技能页：经验条 + 该技能动作瓦片        │
│   银行页：物品格 + 选中详情（来源/用途）  │
│   商店页：商品列表（占位，标注未接入）    │
│   装备页：装备槽（占位）              │
│   熟练页：每动作熟练度（占位）          │
└──────────────────────────────┘
```

## 4. 三条硬约束（防止外壳变成假实现）

用户选择"全量外壳"意味着商店、装备、熟练度都要用**占位数据**做出可交互界面。这是最容易滑向假实现的做法，因此设三条不可绕过的约束：

1. **占位数据不进 `src/content` 与 `src/domain`。** 占位值只存在于 app 层的显式 fixtures 文件（如 `src/app/shell/placeholder-data.ts`），文件头注释写明"非游戏内容，接入时删除"。正式内容定义与规则层不写任何占位项。
2. **占位交互不写存档、不改状态。** 商店购买、装备切换、熟练度增长在骨架阶段一律不产生 `dispatch`；交互反馈为"尚未接入"提示。
3. **外壳一律可见地标注"未接入"。** 每个占位页顶部有明确标识，避免把外壳误当作已实现功能。

## 7. 不做的事（有理由）

- **不重写 `domain/skill-loop`**：281 项测试覆盖的规则引擎是已有资产，骨架只需要它多暴露只读视图（按技能聚合的活动、缺料状态、当前技能）。重写等于丢证据。
- **不新增玩法与数值**：骨架阶段只重排现有 2 档内容。第三档、消费端、故事属于 P4-E 与后续内容阶段。
- **不做宽屏布局 / 不放弃 360×480**：挂机置顶场景是本项目定位，压缩形态是约束而非妥协。
- **不实现金币经济、装备加成、熟练度奖励**：这些是内容设计问题，外壳只占位。

## 8. 风险

| 风险                              | 缓解                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------- |
| 外壳空转（UI 好看但内容塞不进）   | 每个 UI 槽位必须对应内容模型字段；骨架阶段不新增玩法，先用现有 2 档内容验证容器成立   |
| 占位数据渗透进正式定义            | 第 4 节三条约束 + `check:architecture` 机械检查（占位文件不得被 content/domain 引用） |
| 信息密度过高（360 宽塞 5 个入口） | 主导航条可横向滚动 + 主区单列；420×600 与 360×480 双视口各验收一次                    |
| 拆件引入行为回归                  | 保持全部 `data-testid` 与 CSS 类名不变，`e2e` 11/11 作为等价性证据                    |
