# 无限副本生成与 LLM 事件契约

日期：2026-10-03。状态：目标设计草案；当前代码未实现副本抽取器、叙事模型接口或在线服务。

本契约把“副本世界要足够大”“多数剧情有可识别的共同节奏”“突发事件能由 LLM 临场丰富”拆成可以逐步实现的内容层和运行时层。本文不授权网络供应商、账号接入、密钥保存或机械状态生成；接入之前需要另行评审网络边界、费用、数据与存档影响。

作品整体背景、回响片段的统一定义和各文档权威边界见[大背景与副本总框架](大背景与副本总框架.md)；本文只细化素材组合与未来模型事件的运行时契约。

## 一、内容组合模型

一场可重复远征由下列素材组合，而不是由 LLM 从空白处创作：

| 层                 | 定义                                                       | 例子（候选）                                       | 谁负责确定                                   |
| ------------------ | ---------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------- |
| 世界类型族 `UF`    | 一组共享气氛/主题维度，不直接决定规则                      | 灾害生态、交通设施、异常规则、时间空间、记忆身份   | 作者与资料库                                 |
| 世界种子 `W`       | 有独立地理、历史、因果、角色关系和局部规则的地点或世界碎片 | 暴雪观测站、多站列车、镜像城区                     | 作者先定义；规则评审后入游戏                 |
| 任务骨架 `EP`      | 玩家熟悉的章节节奏和决策位置                               | 失联调查、护送撤离、修复设施、证据核验             | 作者定义，跨世界复用                         |
| 本局变化条件 `MOD` | 改变本次切入角度，不推翻世界真相                           | 通信延迟、关键设施失效、队员意见冲突、旧记录多一行 | 固定候选池筛选                               |
| 事件包 `EV`        | 触发时机、允许的异常范围、合法响应与机械后果 ID            | 停电、路线信号互相矛盾、撤离门提前闭合             | 机械效果预先审核；LLM 可现场编排本局事件表现 |
| 副本实例           | 以上内容与玩家本局状态形成的一次运行记录                   | W-04 + EP-02 + MOD-05 + EV-03                      | runtime/内容选择器选定并校验                 |

W-01 至 W-08 是素材样本，不是世界数量上限。后续可不断新增 UF、W、EP、MOD、EV；正式 ID 在审核后确定。不同 UF 可交叉标记同一世界，避免一个世界被限制为单一题材标签。

候选世界类型族可扩为：自然灾害与异常生态、城市制度与群体信任、移动交通与路线选择、遗迹与历史错位、海洋/轨道/地下设施、封闭机构与实验记录、时间循环与因果错位、记忆/身份与证词冲突、自主工业与失控维护系统、边境迁徙与资源交换。它们是创作维度，不是把现实作品设定搬进游戏。

## 二、共同剧情骨架与变化

“大部分剧情类似”落到**稳定节奏**，不等于重播同一谜底。每个副本可以采用以下六拍，具体拍数可按玩法缩短：

1. **进入与委托**：为什么去、这次要带回什么、失败的代价是什么。
2. **建立局部规则**：环境有何异常，玩家能通过观察什么来验证。
3. **资源/关系取舍**：时间、材料、队员分配或信任中的至少一项需要选择。
4. **突发变化**：新证词、设施故障、路线变化或意外求助，改变计划但不任意改写既有事实。
5. **验证与结算**：玩家可把线索和行动对照；基础目标与可选发现分开。
6. **回归与长期余波**：一条证据进入中转站档案，影响下一次可见回应或远征选择。

每个世界种子必须为这些拍子提供自己的局部规则、至少一个可观察证据、一个不同于其他世界的决策压力和一个能影响总主线的问题。不是每一场都必须揭开主线；普通副本可只补强伙伴关系、资源策略或世界类型多样性。

变化条件要覆盖不同轴，而非只替换怪物或加数值：进入时机、已知信息、队员配置、设施状态、证据来源、撤离路线、利益冲突。生成/抽取时排除前几场重复过度的标签；规则尚未实现的条件只能留在文案草案，不能假装是可玩的变化。

## 三、LLM 运行时职责

当前实现事实：`src/content` 定义稳定世界/目标/事件/选项 ID；`src/domain/expedition` 以纯函数判定触发与结算；`src/themes` 提供展示文字；`ExpeditionRuntime` 串行动作和保存。`PlatformPorts` 目前只有存档、独占实例和窗口接口，没有模型端口。现有事件不是 LLM 生成。

建议的目标流程：

1. 纯规则/固定内容确定触发时机、事件族和允许的响应 ID，不请求模型来判断奖励、死亡或规则是否合法。
2. runtime 在当前动作队列边界外向一个可替换的叙事服务请求**本局事件实例**，而非直接写存档或调用 domain。模型可在本世界事实白名单内创作一次性的现象、现场细节和突发语境，让相同事件族每次出现不同；它不能把临时现象升级为主线真相或永久证据。
3. 服务输入仅给生成所必需的最小白名单：世界种子 ID、当前事件包 ID、阶段标签、玩家已解锁且可用于叙述的证据 ID、允许使用的事实摘要和输出语言。不得上传完整 SaveBundle、文件路径、设备标识、其他应用数据或密钥。
4. 服务返回严格结构化的事件实例：标题、现场表现、可观察细节、队员反应，以及从事件族白名单中选出的响应 ID。模型可以为响应写短标签，但选项说明、效果 ID、成本和结算条件来自固定配置。文本长度、字符数、引用 ID、JSON schema 和事实边界均须校验。
5. 任何生成结果都作为不可信的展示数据。非法、超时、断网、配额不足或被拒绝时，直接显示同一个事件包的本地预写版本；不暂停核心模拟，不扣资源，不丢进度。
6. 玩家选择仍由 UI 通过 runtime 的 `dispatch` 发 typed command；domain 再校验阶段、条件、支付、去重和结果。模型不得发命令、修改 Profile/Run、产生任意数值、增加隐藏倒计时或绕开保存屏障。

LLM 可以改变：本局突发事件的现场表现和氛围、非关键对白措辞、在事件族许可的响应方式中选择组合。这样玩家看到的是新发生的局部事件，而非只把静态段落换几个形容词。

LLM 不可以改变：作者真相、世界硬规则、角色已知/未知、永久证据及其意义、任务目标、响应 ID 的实际语义、成本与奖励、战斗压力、解锁条件、结算结果、主线因果。动态事件产生的观察只属于本局临场表现；如要归档成永久线索或影响跨局状态，必须先进入正式内容定义并使用稳定 ID。

## 四、联网、保存与重复加载边界

- 本地预写事件是完整可玩基线；联网生成是明确可关闭的增强项。没有网络权限、用户关闭或服务不可用时，副本照常进行。
- 运行时 provider 未定；WorkBuddy 作者辅助调用与游戏内模型服务是两种用途，前者的登录或免费体验不能证明后者已接通或免费。
- 生成不得进入 `src/domain`。未来如果请求叙事服务，应评审是否增加 `NarrativeEventPort` 等适配器，并保持单一 runtime、动作队列、保存队列及导入/关闭屏障。服务响应不能在保存屏障期间抢先提交状态。
- 主题显示文案与即时生成段落不作为机械真相。SaveBundle 只存规则需要复现的固定世界/任务/事件/选项 ID 和必要选择事实；不把大段模型文本写入主题内容或存档。
- 同一触发点在当前会话内只生成一次，避免每次渲染重抽。若重新启动后重新生成的氛围文字不同，它也不得改变已经保存的选项和结果；需要跨重启固定原文时，必须另行评审本地叙事缓存格式、体积、备份和迁移，不能偷偷扩存档。
- 抽取组合需可追溯。若随机排序最终进入可保存的规则事实，必须保存足以重建的稳定选择 ID/选择种子，并有可测试的确定性；domain 接收显式输入，不直接取随机数。

## 五、开发顺序和验收门槛

1. 先不联网：整理 UF/W/EP/MOD/EV 卡片，用手工配置拼出至少两种世界 × 同一任务骨架的例子，确认共同节奏不会抹平世界差异。
2. 把一条突发事件做成固定事件包，验证触发、选项、成本、结算、失败恢复和主题文案分离。
3. 单独设计运行时生成 port 与请求/响应 schema，再审查用户开关、隐私最小化、网络超时、配额/费用、缓存和离线兜底。
4. 先接入只生成本局、无永久影响的事件实例；效果仍映射到固定响应包。通过内容审查后，再评审是否开放生成内容参与可保存的线索或跨局变化。
5. 任何新增保存事实或机械参数都执行正式 schema/content 版本迁移与验证；禁止把 LLM 自由输出用作 ID 或数值配置。

验收至少回答：断网时是否完整可玩；重复加载同一触发是否不会变更规则结果；模型无法选择未登记响应或发明效果；输出和输入都不泄露本地路径及完整存档；玩家选择经 runtime/domain/save queue 原子落盘；失败时既有存档和已归档证据仍可恢复；同一个世界/事件族能产生不同且不冲突的现场事件；生成内容确实改变本局经历，而不只是替换形容词。
