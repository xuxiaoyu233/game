## 最新平台取舍：先完成网页版

当前产品主平台为电脑浏览器和手机网页；“电脑宽窗布局”仍要适配，但不等于开发Windows原生应用。保留React/Pixi/原Grid、IndexedDB与单推进/命令/保存链；D3原生包装移出主线，金属/空间等内容无需等它。不追加Tauri/Rust/托盘/跨端迁移，也不因网页优先顺带引入PWA、账号和云同步。

## 网页文案、美学与玩法铺垫的采用

本节为2026-10-19定向补查，区别于下表历史调研。下面是适合当前项目的做法，不声称任何单款游戏构成普适“最佳”方案。

| 一手材料 | 可确认的做法 | 本项目采用 |
| --- | --- | --- |
| [Game Accessibility Guidelines：简明语言](https://gameaccessibilityguidelines.com/use-simple-clear-language/)及[上下文帮助/交互教程条目](https://gameaccessibilityguidelines.com/full-list/) | 避免不必要的长度/复杂度，帮助结合当下任务 | 首屏呈现可做动作和结果；需要时解释一个阻塞，完整帮助由玩家主动打开 |
| [Melvor v1.2官方更新](https://news.melvoridle.com/major-update-v1-2/) | 历史更新包含紧凑合并通知、重要错误保留、技能页指南入口、部分阈值无需悬浮即可读 | 成功反馈合并消退、保存失败持续可处理；关键数值直读，说明按需。该文是2023历史改进，不拿它穷举当前版本 |
| [Factory Town Idle开发者介绍](https://store.steampowered.com/app/2207490/Factory_Town_Idle/) | 点击起步、逐步自动化、研究/升级和供需瓶颈统计 | 建设后自动产出，发现瓶颈再升级/研究；只借发展组织，不照搬多城、货币、派工和Time Tokens |

**文案落地**只沿[语言合同](界面语言与信息层级.md)：名称/效果/成本/动作分层；研究摘要用“解锁农田2星”等实际效果；阻塞用“缺木材”并给来源入口；正常状态短标签。不是把文字全部清空或把必要费用藏进图标，也不为“讲故事”在每页加一段介绍。

**美学层次**依次解决：①内容可见且能操作；②资源/成本/进度可读；③土地/建筑身份与1→2星可分辨；④统一视角/色重/木石与暖光；⑤有限合并动效。不能跳过前两项只做夜景大图或滤镜。当前主全景继续作参考，不覆盖建设层；本批不以未生效的烟气/雪灾/居民动画充实画面。

**玩法按真实事实引出**，不是固定第几分钟强制弹教程，也不改变现资格/费用。玩家可自行换目标，已有合法入口不能被引导人为锁住：

| 发展事实/玩家疑问 | UI着重呈现 | 带来的下一步 |
| --- | --- | --- |
| 初始可建设，先了解一块土地 | 一个可做目标、选址和本次费用 | 农田建成，亲眼看到实际产出/结构 |
| 需要木石或想主动加快 | 相关技能/协助的实际奖励与一个入口 | 理解“专注一项，设施并行”；无需连点维持 |
| 基础链可用，出现食水/床位需求 | 口粮/饮水收支和对应设施；原粮→口粮用短配方表达 | 扩地、厨房/水井/住房有具体用途 |
| 生产瓶颈或成长目标出现 | 升级的费用/效果，已可达研究 | 研究打开作业/能力，材料有可见去向 |
| 进入工坊并完成对应许可 | 时代中心变化、对应建筑晋升入口/条件 | 逐座2星，主结构改变且仍可继续升级 |
| 后续C2上线且营地有准备能力 | 一条预警、可负担的应对、有限路线选择 | 发展方向出现差异；重大事件按既有暂停合同 |
| 更后续健康/生态/PvE | 已有原因、对策与结果摘要 | 继续单营地，不把所有风险一次塞进开局 |

上述是展示与内容引出的采用方向，不声称真实经济时长已验证。首次产出、下一研究、首次食水保障和进入工坊的等待/瓶颈，在补修真实新档与后续试玩中观察；快进或注入星级仅可证明外观，不能代替节奏判断。若实际早期供给/费用出现硬卡点，记录事实再单独修机械值与兼容，不在文案批中悄悄改经济。

当前先闭合[V1复核问题](../证据/发展沙盘/V1/复核-20261019/复核.md)，保留已有成果，局部补修。不把研究、工具收集、肉鸽选择、灾害和战斗同时上线作为“丰富玩法”的快捷方式。

## 内容进入游戏前最少说明什么

每项只需回答以下问题，不要求为每个按钮/词语建卡或新数据库：

1. **玩家价值**：增加哪种可观察选择/能力，能否沿现有内容解决？
2. **前置与闭环**：来源、用途、费用/持续消耗、AND/OR条件、最差状态恢复；资源不可只产出无用途。
3. **采用边界**：当前接线、已确定待实现，还是候选；参考了什么，与本作哪里不同？
4. **工程映射**：复用哪个定义/规则/命令/展示入口；无映射就明确写未实现，不能以文案或动画偷带规则。
5. **兼容与呈现**：是否改变机械含义/存档，是否需要迁移/旧离线边界；应显示的效果与素材工作量。

同一项的机械成本只在实际内容定义里维护；资料记录版本快照/设计理由。只有新规则/迁移等核心合同需要必要验证，资料整理、每级美术与每条文案不扩成独立测试阶段。

新增偏离这些选择的提案应明确比较成本/价值；不以“资料里有”作为已授权实现或发布的依据。
