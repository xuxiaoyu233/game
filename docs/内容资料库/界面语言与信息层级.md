# 界面语言与信息层级

更新：2026-10-19。本文为发展营地玩家文案的唯一编辑规则，是采用要求，不代表各页面均已落实；不记录阶段完成度。布局/交互仍见[适配规格](../设计/网页适配与视觉体验规格.md)，执行状态只看[PLAN](../../PLAN.md)。原适配规格3.1全文提炼至此，后续维护本文件，不在多处各改一份。

## 网页采用方式

优先用“对象名＋实际效果/数值＋可执行动作”组织信息；关键数值直读，解释按需。成功反馈同类合并、自然结束，保存失败等重要问题持续可处理。玩法引导跟随当前缺项和实际开放条件，不把教程/未来风险一次铺满五页。游戏一手做法与本项目取舍统一见[参考与扩展](参考与扩展.md)，以下预算与规则继续生效。

## 文字出现的必要性

每段文字必须直接帮助玩家**辨认对象、读取状态、比较收益/成本、理解当前阻塞、选择动作，或避免进度损失**。不满足其中一项就删除；先判断有没有必要，再决定是否放入详情，不能把所有废话集中到折叠面板。游戏页面常态不设介绍段、理念标语或机制免责声明。

**内部信息完全退出玩家界面**：S01/S02/E01、HQ、原生类型/资源ID、schema、content、prototype等内部标记不进入地图标签、标题、副标题、按钮、常规详情、tooltip或无障碍名称。分别用“农田”“林地”“空地”“营地中心”等玩家名称；稳定ID保留在代码、data属性、导出格式或明确的开发诊断中，不删除规则身份。等级/星级是玩法信息，可以显示。

| 界面位置 | 默认保留 | 删除或按需显示 |
| --- | --- | --- |
| 页头 | 页面名；有操作价值的计数 | “把生产成果投入长期改造”等介绍段、重复口号 |
| 地图 | 必要对象名/选中状态；选中后等级星级 | 内部编号、每块土地同样的说明；远景重复标签 |
| 建筑卡 | 名称/等级星级、关键能力、成本与主操作 | “自动运行、缺料会等待”等全设施通用解释；更多明细按需展开 |
| 研究卡 | 名称、确有必要的一条效果摘要、成本/缺项或已研究状态 | 已研究卡的红色缺料/历史费用/重复许可解释；完整规则只在需要时查看 |
| 技能卡 | 当前等级/进度、单次产物与实际XP、专注动作 | 默认同时堆本级/累计/剩余/名义/每分钟XP；更多数值点开查看，封顶或截断时才补必要提示 |
| 民生卡 | 人口/床位、劳力、食水供需 | 正常状态的成段运算说明、累计扣了几次等审计信息；短缺时才给原因/解决入口 |
| 离线摘要 | 实际结算时长、库存变化、重要完成/阻塞 | “只读统计、不重复结算”等工程保证；4h截断仅发生时提示 |
| 设置/保存 | 当前位置的保存范围、保存/导出、必要错误与恢复入口 | 时代规则说明书、正常状态重复提醒；来源署名沿制作信息保留 |

**默认文字预算**：页头介绍段为0；一张卡最多一条确有必要的效果摘要，通常12–20字，不再另加同义副标题/脚注。一个对象默认只显示一个主要阻塞原因及最直接的解决动作，完整缺项展开可达。按钮直接命名动作/目标，如“建设”“升至Lv5”“晋升2星”“前往农田”。这是表达约束，不允许截断名称、数字、单位或错误信息来凑字数。

建设/升级/研究等具体操作在执行前须呈现对应费用与关键效果；可以在选择目标后展开，不要求每座建筑常驻全部升级方案，也不能把本次扣费藏到帮助里。

**触发时机**：正常生产只显示“生产中”等短状态；实际短缺时再显示“缺木材”并提供入口；满级时再显示“已满级 · 继续产出”；切换会丢未完成周期时，在切换动作附近提醒一次。已研究卡只保留“已研究”和必要效果，不再反复说明费用历史/效果已生效。页面、卡片、页脚、toast对同一结果保留一个主要反馈位置；一次性成功提示结束后清空，不留常驻空白提示条。

以下例子来自本次读取的真实文案，替换时仍从规则读取具体对象/数值，不把例子硬编码成所有设施的状态：

| 原表达 | V1采用方向 |
| --- | --- |
| `S01 · Lv5` / `HQ · 营地` | `农田 · Lv5` / `营地中心` |
| “把生产成果投入长期改造。研究一次生效，建筑与训练可以继续并行。” | 删除，页面标题“研究”即可 |
| “自动消耗木材加工板材；缺料会等待，不凭空生产。” | 用输入→输出数值行表达；无新增解释段 |
| “许可类研究：需到对应设施本地晋升才会变成2星，不直接增加产量。” | 效果摘要“解锁农田2星”等实际目标；已完成可给“前往农田” |
| “补足原料后自动继续，未完成进度保留；暂不给出确定倒计时。” | 当前具体短缺，如“缺木材”；更多训练规则按需查看 |
| “经验已封顶：继续完成该作业仍有产物，不再增加经验。” | “已满级 · 继续产出”，奖励行如实显示0 XP |
| “食水配给满足。储备随供需变化，短缺会先影响劳力与移入。” | 正常状态“供给充足”，已有同义标识时直接删掉 |
| “已研究 · 效果已生效” | “已研究”状态标识，无动作时不用大禁用按钮 |

“本地晋升”“劳力口径”“共享缓存”等实现用语退出日常操作，分别采用“晋升”“劳动力”等自然用词。保存范围里的“当前浏览器”属于必要信息，应简短保留。产能预览可标“预计”，库存变化/总产量、原粮/口粮、床位/人口等差异必须保持准确，不能为了短而误导。

保存失败、坏档恢复、覆盖/清空进度等情况可以超出普通卡片预算，保留后果与可执行入口；例如“保存失败，刷新或关闭可能丢失进度”＋“重试”。不能只留图标、统一写“操作失败”，或把必要风险藏进帮助。首次功能确实需要引导时给一次相关短提示，后续机制不每天重复教学。

交付时附少量代表性的删减前后截图/文案例子，检查“删掉后玩家能否仍完成操作”。不新增逐句文案台账、全文字数门禁或逐文案测试；同一条V1主线核对即可。
