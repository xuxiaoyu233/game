## 编辑资料与运行时内容

这里的“资料库”先采用仓库内版本化文档，配合类型化 TypeScript 定义。现有规模不需要 SQLite、在线 CMS 或动态插件；没有建立运行时读 Markdown 的能力。

| 对象                           | 唯一责任源                      | 消费方式                          |
| ------------------------------ | ------------------------------- | --------------------------------- |
| 正史事实与批准记录             | 既有故事设定/评审文件           | 作者评审；进入代码前映射到稳定 ID |
| 类目、命名提案、来源与设计理由 | 本目录对应台账                  | 编辑参考；不决定产出或扣费        |
| 生效的机械字段                 | 当前版本的 `src/content` 定义   | 由组装入口注入规则/runtime        |
| 生效的显示文本                 | `src/themes`                    | 依 ID 取文案，不参与规则计算      |
| 生效的行为与事实校验           | `src/domain`、`src/persistence` | 有限联合类型、纯规则与版本校验    |

文档中的数值是有版本/状态的设计记录；生效数值以对应代码定义为准，不把两份可独立编辑的数据同时视为运行时真源。以后若建立生成流水线，必须先确定唯一输入与生成文件只读边界；目前没有该能力。

## 内容记录最小字段

每项记录至少含：稳定编辑/机械 ID、种类、通用名称、可选世界内名称、来源或设计依据、适用版本、批准状态、实现状态、可见范围、来源与消费端/前置关系、代码映射、兼容性影响。复杂项再增加人物关系或效果合同，不要求所有卡片填无意义字段。

- 批准状态：已批准 / 候选 / 历史。实现状态：未计划 / 规划中 / 已实现 / 自动检查通过 / 待人工验收；两轴独立。
- 无代码映射时写“无运行时映射”，不把计划路径标为已实现。
- 名称与别名服务检索/展示，不能自动映射存档 ID。相似名称、相同图标或相同类别不证明两个资源可互换。
- 世界、人物和隐藏真相继续遵守故事资料的可见范围；玩家文案不包含作者掌握但未揭示的事实。
- 展示类目如“原料/加工品/工具”默认不参与存档；若类别开始决定配方、背包限制或解锁，须升级为机械字段并审查兼容。

## 扩展与验证

每个阶段同时交付玩家路线、该档资源/解锁关系、适用实现和资料对照。P0 定下两档蓝图，P1/P2 已逐档验证；故事文献可并行深化，不需要等全部玩法完成才研究，也不要求玩法等待整卷小说。进度仅在 PLAN 维护。

知识/文献卡采用故事编辑 ID；机械前置/物料关系采用工程 ID；包外映射注明候选版本、批准依据、获取条件与玩家可见范围。知识依赖、解锁前置、物料流分别理解，不能把全部关系复制成第二份可编辑的运行时科技树。

1. 在对应唯一台账登记候选、来源、输入输出和玩家可观察用途；故事新增事实仍先走故事评审。
2. 已有规则支持的新物品/配方，修改类型化 content 与 themes；有限 ID 联合类型也可能需要同步扩展，不能声称“只改文档自动生效”。
3. 新行为如消耗品效果、科技互斥、战斗或特殊停点，需要 domain 合同、定义/存档校验和必要迁移。禁止用文案、任意函数或脚本偷带行为。
4. 在 `main.tsx` 组装并验证机械定义与展示映射；app 不直接导入 content 或 docs，不维护第二份解锁/用途真相。
5. 更新唯一 PLAN 的阶段证据。改文案、数值与状态形状分别审查，不为了改名字改 ID，也不因 schema 未变而忽略机械内容兼容。

**当前门禁：** `check:narrative-docs` 检查仓库根文档、`docs/` 与 `story-library/` 的 Markdown 本地链接，并检查既有故事编辑 ID/边界和历史交叉索引；启动校验覆盖既有故事投影。尚未覆盖本目录全部新候选的资源引用、生产图和成长环路。

**实现阶段待完成：** 机械 ID 唯一/引用完整、活动输入输出/周期、技能阈值/解锁、工具成本/效果和 theme 覆盖检查；任务接入时再校验成本/奖励/一次性领取。有意共享成本允许，悬空引用、解锁自锁和可见无用途物品要报告；物料回路不能与解锁环混为一谈。静态检查不替代真实新档可达性、经济体验或原生验收。
