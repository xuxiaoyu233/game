## 资料权威与使用顺序

1. 用户已明确的产品选择与根AGENTS决定任务边界；[PLAN](../../PLAN.md)决定唯一实施顺序和验收状态。
2. [首版规格](../规划/发展沙盘首版规格.md)、[C1采用值](../规划/C1食物与人口采用值.md)、[D1-C采用合同](../规划/D1-C工坊成长采用合同.md)解释对应机械版本；[生存合同](../规划/生存经营与事件体系.md)定义后续行为。
3. **当前实际执行值以当前工程定义/规则为准**；本库表格是注明版本的阅读快照。发现代码与已采用合同不一致时记录差异、判断影响，不能悄悄选一份当正确答案。
4. [适配规格](../设计/网页适配与视觉体验规格.md)管布局/交互；[美术规格](../设计/沙盘美术接入规格.md)管资产接入；本库语言文件管玩家文字，不再各维护一份完整文案政策。
5. 原始调研与旧交付保留时点，用于追溯，不自动覆盖最新选择。资料中有一项内容，不代表已进入游戏。

## 当前范围与资料状态

资料对应 schema5/content `d1-c-1`：一个营地、八类可建建筑/六资源、四技能/10作业、六研究、五Tab、食水人口、工坊与本地2星。当前源码和[D1-C交付](../证据/发展沙盘/D1/C/交付.md)能核对这些接线，长期经济平衡和真人体验仍待验收。

采用三类标识即可，不要求给每个词建审核表：**当前接线**（有代码映射）、**已确定待实现**（有合同/PLAN批次）、**候选/历史**（不约束当前规则）。实现、自动检查、浏览器/真人验收仍在PLAN与证据区分；“已确定待实现”不能写成“当前已生效”。

## 持续提炼方式

- 每类资料只有一个正文责任源，其余位置放摘要和链接；本库不是第二份产品规格或数值编辑器。
- 内容变动只更新受影响记录：名称改台账；实际数值先改唯一工程定义并处理兼容，再更新版本快照；文案改语言规则/展示；素材改唯一catalog和来源台账。
- 新机制先说明玩家选择、可达来源/用途、规则影响、代码落点和兼容边界，采用后才入对应实施批次。纯资料条目不需要虚构机械ID或排新测试阶段。
- 资料校验使用现有文档链接/路径检查；规则与UI实现交回对应大阶段，避免为逐条资料增加测试。
