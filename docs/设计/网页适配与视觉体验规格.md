## 1. 产品判断与证据边界

产品承诺是“同一处小镇逐步完善”：短时操作能解决一个瓶颈，离开后仍自动发展，回来能看出变化。固定场景建设、技能专注、研究许可、建筑等级/星级/时代是已有主干；人口供给与未来正向路线用于改变发展选择，致死风险留给自愿挑战。界面应让玩家回答：**哪里在生产、现在缺什么、下一步改哪里、改完有什么变化。**

当前具备玩法骨架。继续叠新机制前，应先交付一个完整的适配与美化批次 V1。新增内容路线保留，C2 接在 V1 后，不撤销 D1-C，也不重新验证一遍全部历史阶段。

本次实际读取根 PLAN、交付/发布记录、CampHud/CampTilePage/CampResearchPage、sandbox-tokens.css、WorldScene/main/SceneManager、catalog 和渲染绑定；查看 D1-C 的 desktop-lv20.png、mobile-camp.png。当前分支 `codex/p1-first-tier`、HEAD `98c2699af4bccbae4098cd300df92a8e6920c83e`；工作树含未提交内容，HEAD 不是完整交付快照。

Sites 原生部署成功有[发布记录](../证据/发展沙盘/Sites-20261019/README.md)，浏览器地址是 `https://development-camp.l0ya1er.chatgpt.site/`。**本轮未重新操控线上页面**；以下布局判断来自交付截图与当前源码，不是新一轮线上运行验收。历史浏览器用例不证明真实玩家完成从开局到工坊的经济平衡。

| 观察到的问题 | 当前依据 | 产品影响 | 处理优先级 |
| --- | --- | --- | --- |

## 2. 保留的主干、需要改善的体验

采用以下循环，所有界面服务同一个营地，不做新地图/第二游戏实例：

```mermaid
flowchart LR
    A[查看真实瓶颈] --> B[协助或选择技能]
    B --> C[建设与升级]
    C --> D[自动生产与供给]
    D --> E[研究/本地晋升/扩地]
    E --> F[可见的新结构与能力]
    F --> A
```

| 玩家处境 | 应看到的内容 | 本批改善 | 留给后续的机制 |
| --- | --- | --- | --- |
| 第一次进入 | 一个可执行目标、可建设土地、基础来源 | 目标条指向已有对象；默认收起说明；命名清楚 | 不加新手奖励币/强制教程流程 |
| 在线停留几分钟 | 专注作业、施工、缺料/仓容/食水原因 | 同源状态，短反馈与明确解决入口 | 不加自动连点/独立手工加工钱包 |
| 日常回访 | 离线结果、主要阻塞、可做的一步 | 摘要结果一眼可读，关闭后落回对应营地/对象 | 不重新领取已经入账的收益 |
| 冲击工坊与2星 | 当前收益、升后收益、许可与晋升区别 | 对比能力、结构变化、真实门槛导航 | 不改XP/成本/晋升曲线以制造UI成功 |
| 长期经营 | 更多可做的发展决策 | 先把现有成长呈现完整 | C2正向路线与收成节奏，D4后续时代；C3/C4生存生态和PvE可选 |

爽感的主要来源依次为：成功协助的即时反馈、订单完成的结构变化、许可→晋升的能力跃迁、设施落成后的场景完善、回访后的可执行下一步。V1 不靠额外红点、日常领奖、重复确认或每级弹窗增加点击。更深的组合增益沿 C2 已有三选一合同实现，不在视觉批次偷偷加入新规则。

## 3. 信息架构：五个Tab各有责任

| 页面 | 首屏要回答的问题 | 主要内容 | 放到二级详情 |
| --- | --- | --- | --- |
| 营地 | 哪里可建/可升，当前对象有什么用？ | 世界、当前目标、对象摘要、一个主要动作 | 成本明细、完整IO、运输/仓容口径 |
| 技能 | 正在练什么，为什么等待，下一作业如何解锁？ | 当前专注＋四技能/10作业，实际经验进度 | 累计XP/收益公式/完整前置 |
| 研究 | 哪项研究能解决当前发展问题？ | 现六节点、当前时代/路线、已满足与缺项 | 后续时代预告、完整依赖说明 |
| 民生 | 食水能否支撑人口，缺什么设施？ | 人口/床位/劳力与食水收支，设施定位 | 计算说明；C3上线后才有年龄/死因 |
| 设置 | 如何保存、查看范围、调整表现？ | 本地保存状态、手动保存/导出、署名/已有选项 | 技术版本信息，不放进建设面板 |

五Tab保留；手机可以移到底部，桌面保持横向导航。Tabs仍是语义化DOM和键盘导航，不能为统一外观改成只有canvas文字的按钮。切Tab不停止生产，不重置专注和选地；返回位置/选中/滚动继续沿现有 camp-navigation。

**常驻信息减量**：桌面六资源可以一行紧凑显示；手机常驻“口粮/饮水/木材＋资源总览入口”，原粮/石材/板材在总览中一次可达。总览必须展示全部六资源、完整名称和相关速率；发生短缺时常驻条同时给“食水不足/板材不足”等文字提示并直达对应详情，不用无意义红点。这是响应式信息分层，不删除资源或改变库存。若320宽时文字放不下，改成两行紧凑条，禁止继续缩字。

人口/床位在民生页给完整解释；营地可给单行民生摘要。未来C2只使用一条可收起预警，不再占一整排常驻假温度；未来更多资源沿总览分组，不扩展为十几张顶栏卡片。

**速率诚实**：当前HUD由原生产IO减人口需求得到每秒速率，未完整计入技能/施工等流量，不直接称“库存真实净变化”。玩家标签用“自动收支”，数值带“/秒”；点开给生产、加工、居民需求的简短分项和“不含训练、建造”等必要范围说明，不把整段计算解释常驻顶栏。若要显示全来源实测速率，须另行设计采样窗口与数据来源，不在本批造历史或新的模拟时钟。核心标签与单位不能只放hover。

### 3.1 文案出现的必要性（V1必做）

玩家文案的唯一编辑规则见[界面语言与信息层级](../内容资料库/界面语言与信息层级.md)。常态不设介绍段，内部编号完全退出玩家界面；必要状态/成本/效果/动作可读，异常时才补原因，重要进度风险保留。先删除无用内容，再组织必要详情。

本规格负责布局与交互，文案示例、文字预算和必要性判断仅在上述资料维护，不复制第二份。

## 4. 响应式与镜头合同

### 4.1 两种排布、一个游戏

断点按网页内容区的 **CSS像素**，不按设备品牌或物理分辨率。先采用宽度900px与高度500px作为布局阈值，实际测量后允许等价微调并说明；不把700px以下所有窗口压成同一种桌面缩小版。

| 条件 | 排布 | 世界与详情 |
| --- | --- | --- |
| 宽≥900且高≥500 | 紧凑资源栏＋导航；主区左世界/右300–360px详情 | 世界填满剩余主区；右侧独立滚动，主操作留在面板内 |
| 宽<900且高≥500 | 紧凑顶部摘要＋主区＋底部五Tab | 默认“看营地”；选中后底部摘要约72–88px；点“详情”后展开，点“返回营地”收起 |
| 高<500或长内容/放大字体 | 单一任务视图，世界和详情切换 | 保留资源/导航入口；详情占主区正常纵向滚动，不强制同时挤一张地图 |

手机详情展开时，允许地图让位给操作；收起后必须恢复清楚的营地。禁止默认打开占高140px的长文窗口并让地图只剩150px。展开用明确按钮完成，拖动不是唯一操作方式；展开/收起不改变规则、施工或训练。

```text
桌面                                 手机（看营地）          手机（看详情）
资源与时代 / 保存状态                 时代 / 资源摘要         时代 / 资源摘要
营地 技能 研究 民生 设置              当前目标                返回营地 / 对象名
┌────────────────┬───────────┐       ┌────────────┐          ┌────────────┐
│                │对象摘要    │       │            │          │状态与能力  │
│   可操作的营地  │收益对比    │       │  可操作营地│          │成本/缺项   │
│                │缺项/动作   │       │            │          │升级/晋升   │
│适应营地 / +/-  │详情折叠项  │       └────────────┘          │详情滚动    │
└────────────────┴───────────┘       对象短摘要/详情          └────────────┘
当前目标/结果提示                     五个Tab                 五个Tab
```

### 4.2 可执行尺寸目标

- 在420×600和390×844的**正常营地视图、无弹窗、摘要收起、100%缩放**下，无遮挡可操作世界高度至少为可用内容高的45%（420×600基准至少270px）。目标是世界容器大小，不把整个页面或被面板盖住的像素算进面积。
- 手机看营地时，当前已开放营地和紧邻可扩建边界应进入适配镜头；选中对象或扩地提示落在无遮挡区域。长按/hover不能是唯一读名称方式，列表/对象选择入口可作为小地块的替代操作。
- 横向短屏不硬保45%：走任务视图，页面/详情可正常滚动，不丢建设、研究、保存或返回入口。320px宽提供完整功能，普通文字/列表无页面级横向滚动；地图本身可平移缩放。
- 详情主动作在面板自身布局中保留空间，不能悬在另一个全局footer上；长中文标签允许换行。保存失败/恢复错误持续可见且有重试路径，不省略为一行截断。普通成功提示可合并轻量显示。

45%是本项目的产品目标，不是可访问性规范；若字体放大/软键盘使空间不足，优先让阅读和操作可达，转任务视图，不能通过缩字或禁用缩放满足数字。

### 4.3 技术落点

1. 保留React18.3.1、Pixi7.4.2、原Grid/Camera/WorldScene。沿 CSS Grid/Flex 定义顶部/主区/导航，替换营地HUD多份固定top/bottom相互补丁；仅地图和确实需要的浮层定位，不改根旧技能工程的全局样式。
2. 已有 `resizeTo: canvas`、ResizeObserver、autoDensity 与初始 devicePixelRatio；问题不能归结成“缺少resize支持”。补的是**实际可用画布矩形＋营地包围盒＋选中对象可见性**。沿原相机加适配营地/缩放按钮，不创建第二Camera。
3. 首次进入及“适应营地”按当前开放地块/实际sprite范围和边距求fit，不按45×45整世界或固定570/620算；正常resize保留玩家手动缩放/平移意图，只修正明显越界。底部摘要展开/收起后定位不得落在被覆盖的区域。相机/面板状态不写机械存档。
4. 根容器按实际内容区设置动态高度，考虑 `dvh` 和 `env(safe-area-inset-*)`；已有观察器复用，监听销毁成对，避免resize循环。不要使用外层桌面屏幕尺寸去推算Site内容区。移动地址栏/软键盘变化须在真实设备补确认。
5. 不以固定4K画布解决清晰度；核对浏览器缩放/跨显示器后DPR变化。默认优先清晰，必要的渲染倍率上限/低特效选项按实测决定，像素量随DPR平方增长，未测前不承诺FPS提升。

## 5. UI图素与整体美学

### 5.1 画风取舍

| 路线 | 优点 | 代价 | 本次结论 |
| --- | --- | --- | --- |
| 当前Kenney体系＋统一微缩营地表现 | 投影、现有接线与许可可复用；原包有矢量源 | 细节少，矢量拆分导出仍待验证，不能只提高DPR | **当前可玩基础，优先验证清楚导出** |
| 全项目切16×16像素 | 单件精简、可形成清楚风格 | 要重配透视/落点/图标/缩放规则；离已认可工坊插画更远 | 保留候选，不作为本批任务 |
| 手绘微缩样板，成立后再扩展 | 靠近已认可夜间工坊图，可形成自己的建筑身份 | 一致透视、透明边缘、缩小辨识需验证 | **V1先比较农田/木工坊样板**，不先做全套，不混入半套 |

目标为**深蓝环境中的简化微缩营地**：土地低饱和、建筑清楚、木石材质有区别、少量暖色窗灯、主操作暖金。不是每个时代换绘画风格：开拓→工坊改公共构件/木石与设备，工业再加真实机械，电气再加真实供能特征。视角、尺度、光向、图标和中文可读性保持一致。原全景不铺在可建土地下面，不新增移动居民。

V1先做同一真实营地中的农田1星/2星＋木工坊1星/2星对照，按[最新调研](../规划/网页画质与点击体验调研-20261019.md)先验证现SVG派生，再比较手绘候选；在可玩页面查看缩小后效果，再补其余在用设施。不得用另一张完整插画替代可操作样板。没有合格位图也可用清楚的程序结构交付，但必须标明prototype，不能写“正式原画完成”。若要切整套手绘，先留下可比较样板再由用户决定，不在执行时重新选择底座。

### 5.2 字、图标、颜色、动效

- 中文正文14–16px，按钮至少14px，重要库存16–20px，辅助标签12–13px；使用系统中文字体，不用像素字体承载长说明。技术上原Main.css根字号62.5%，必须核对rem实际换算，不能直接写1rem假定16px。局部营地字阶覆盖，保留上游必要样式。
- 移动主要点击目标44×44 CSS px，桌面主要动作高至少36px；图形可小，命中框不能一起缩小。键盘有清楚焦点、Tab切换与Esc/关闭返回；说明不只靠hover。canvas对象有等价DOM定位/选择入口。
- 六资源继续一义一图：原粮/木材/石材/板材/饮水/口粮；资源用现game-icons与两枚SVG体系，动作沿已采用线性图标体系。统一各体系的光学尺寸和色重，不在同一类资源里混emoji、线图、照片。归属记录逐来源保留。
- 普通正文对底色目标≥4.5:1；不可只用红/绿区分缺料/完成。金色用于主动作/选中，蓝灰用于中性，警示附图标＋文字。原图的强光/花纹不能进入阅读区。
- 统一8px主间距、4px细间距与有限圆角/描边；营地tokens收敛为唯一语义来源，按token/布局/组件/响应式分职责，避免继续在一个900行CSS末尾叠修复。只拆当前责任，不重写全部上游UI组件。
- 协助成功轻量飘字，失败只解释原因；同一位置短时合并。施工完成更新结构＋短提示；升星强调主轮廓变化；时代切换强调HQ/公共装饰。自动生产不每秒飞一屏资源，不每级强制弹窗。减少动效尊重系统偏好，音效无许可时不补假资源。

### 5.3 资产预算与接入

当前有8类可建建筑，HQ另计。V1语义表现覆盖**8个1星身份＋五基础建筑的5个2星结构＝13种建筑结构视图**，另有HQ与有限空地/林缘/石脉/锁定/施工状态。这是视图预算，不等于必须新增13张PNG；House/水井/厨房不新增2星。连续等级沿已有分段，不新增逐级重画。

| 对象 | 1星身份锚点 | 2星/研究变化 | 复用原则 |
| --- | --- | --- | --- |
| 农田 | 田垄和作物，而非普通屋 | 围栏/棚架主体，灌溉独立水渠 | 不把灌溉科技等同2星 |

沿既有唯一catalog、camp-assets、camp-tile-art、源PNG→图集生成链，具体目录和来源合同见[美术接入规格](沙盘美术接入规格.md)。补齐采用资源的status/sourceId/anchor/尺寸/采样/用途与绑定；不要另建第二份运行manifest或把纯展示键存进游戏档。源文件保留，派生图标/贴图另记处理；图集产物继续忽略。

如后续由网页版生图：只给“风格参考＋当前真实同场景样板＋建筑用途＋相机/落点/透明背景＋不含人物文字UI”的单件制作单，先农田或木工坊，不生成全时代大全。真实alpha、半透明边缘、缩小轮廓和邻格遮挡检查后才能采用；AI生成不自动获得Kenney CC0署名。制作单不等于资产已生成。

## 6. 工程适配、性能与发布

**当前框架可继续使用。** React适合Tab/面板/可访问控件，Pixi适合地图，原Grid与单推进/命令/保存链已承载当前玩法。改框架无法直接解决固定偏移、信息密度或通用棚屋的问题。

重点收敛三处：营地Shell管理布局与浮层；共享投影提供状态/能力/成本；catalog管理展示引用。优先复用已有 camp-status/stock/preview/goals/navigation，不复制经济计算。HUD/研究/建筑内部可以按职责拆小组件，但不新增全局store、第二ticker或新的持久化框架。

V1记录一个代表设备/浏览器上的冷启动“加载到首个可操作对象”、切Tab、拖动/缩放、完成一次操作的实际观测，以及主包/图集字节。先确认当前bundle依赖，再对明显未使用入口或可延后详情进行小范围分割；不能为减包删存档/迁移/恢复链。沿现spritesheet，按状态变化更新结构/文字，避免每帧重建；滤镜/粒子/光照先限制在少量装饰。体积不等于速度，未测不写“流畅60帧/首屏2秒”。不单列性能平台建设阶段。

本地与Sites必须使用同一套玩法源码与资产引用路径，URL沿BASE_URL；不为Site重做演示逻辑。保持既有私有站点与namespace，后续更新沿原网址，保留发布证据；切网址/设备不会自动带档。当前仅导出、暂无导入。**V1交付默认只本地构建和走查，不自动发布、推送或改分享权限**；获明确发布指令后再核对产物与原站点。

## 7. V1实施包与验收

V1是一个完整体验批次，内含以下依赖步骤；不是四个需要反复停下的测试阶段：

1. **可用空间先成立**：Shell布局/资源摘要与总览/移动摘要和详情/相机fit/短屏fallback；复用原导航，主操作与保存失败可见。
2. **统一UI语言**：先按3.1删除不必要文字，再统一字阶、图标、按钮状态、数字与“自动收支”口径；五Tab按“摘要→动作→必要详情”收拢，六研究保留卡片，按前置可定位。累计/名义经验等保留查看能力，不全部默认展开；不为六节点加入图编辑器或铺满42个未来锁。
3. **同场景美化**：农田/木工坊先成套对照，再补齐当前8身份与5晋升的辨识；地形/比例/描边/阴影/标签/真实反馈统一。S01/HQ等内部标记完全退出玩家界面，主标签用建筑名/等级/星级；远景减标签密度，选中对象保留清楚名称。
4. **交付收口**：记录体积和一次真实新档操作路径/回访路径；阶段末集中类型、改动范围Lint、构建与一条UI主线，保留必要截图和未测项。不得为每张图/按钮/断点/等级扩测试。

| 验收面 | 本批退出条件 |
| --- | --- |
| 空间 | 960×720桌面、420×600及390×844手机营地视图符合面积目标；另抽查320宽和844×390任务视图；无不可达操作/页面级横向溢出 |
| 操作 | 同一主线贯穿选地→建设/升级→技能→研究缺项定位→返回→资源详情；地图拖动不协助，成功协助才发奖，展开/收起不丢状态 |
| 成长 | 同地块展示1星/2星差异与真实等级；灌溉/工坊时代只改变应变的层；当前8建筑身份可区分。测试快照与真实发展截图分别标注 |
| 文字 | 常态无页头介绍段/重复机制说明，内部编号在标签/详情/tooltip/无障碍名称中均不出现；必要状态、成本、收益与动作可读，资源单位/可用库存/集中仓容/自动收支/实际XP准确；长中文与保存失败不被截断 |
| 键盘/触控 | 主要按钮目标尺寸、焦点可见、详情关闭与返回、无仅hover操作；浏览器缩放后可达；合成窄窗不冒充手机真机 |

一个真实新档可用来计时并发现理解障碍；工坊/2星视觉允许隔离样例状态辅助，但不得据此宣称经济时长已验证。真人试玩关注“能否说出当前瓶颈、找到解决入口、看出升级变化、回来后知道下一步”，不以用例数量代替产品达标。风格审美保留用户反馈，未批准的结构保持prototype标记。

## 8. 可借鉴的现成做法与来源

以下已于2026-10-19查阅；采用结论是本项目判断，不是来源要求本项目这样实现：

- [W3C Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow)：窄窗口重排保持内容/功能可达；本项目将地图与可重排面板分开处理。地图可平移不能成为文字区横向溢出的理由。
- [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)：AA基线含24CSS像素与例外；本项目主要触控目标采用44px是更宽松的产品目标，不把44px说成AA强制值。
- [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)、[Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)：用于文字、浮层、焦点和导航语义，不引入一套新UI框架。
- [MDN长度/动态视口](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)、[安全区env](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)、[devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)：分别处理内容尺寸、安全区和渲染清晰度，不能混成“调高像素”。
- [Pixi v7性能建议](https://pixijs.com/7.x/guides/production/performance-tips)、[ResizePlugin源码](https://api.pixijs.io/@pixi/app/src/ResizePlugin.ts.html)：复用图集/现有resize，先度量、控制频繁文本/结构更新；不抄v8 API升级当前底座。
- [Kenney Hexagon Pack](https://kenney.nl/assets/hexagon-pack)、[UI Pack](https://kenney.nl/assets/ui-pack)：继续复用同系列/CC0输入与控件状态思路，本轮未下载新包。实际采用文件/作者/哈希仍以工程台账为准。
- [Melvor入门与技能说明](https://wiki.melvoridle.com/index.php?title=Beginners_Guide)：借鉴专注作业、技能进度和长期目标的清晰展示；不追加独立熟练度货币或照搬第二经验系统。
- [文明VI官方介绍](https://civilization.2k.com/en-GB/civ-vi/)：借鉴时代与土地发展的可见反馈；本项目保留连续时间、单营地和自动生产，不移植回合/多城管理。既有玩法取舍继续见[文明式扩展规格](../规划/文明式放置沙盘扩展规格.md)。

后续C2先交舒适节奏、路线选择和对应设施反馈；C3/C4仅在自愿挑战排期后交健康/生态。D2负责固定场景、时代风貌与全局一致性，不再承担修复基础手机布局或首次制作可辨识建筑的职责。
