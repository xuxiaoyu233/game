# 产品形态与窗口契约

更新日期：2026-10-17。本页是产品三态窗口形态的唯一权威规格；后续 UI 工程改造以本页为准。本页只定义规格，不含实现代码。

依据文件：`src-tauri/tauri.conf.json`（窗口现状 420×600，min 360×480）、`src/app/skill-prototype.css`（令牌与固定区实测值）、`src/content/data/activities.json`（106 活动，金工 18 为最长列表）。

## 1. 三态定义

| mode     | 用途                                       | 交互权限                                 | 进入/退出                                                   |
| -------- | ------------------------------------------ | ---------------------------------------- | ----------------------------------------------------------- |
| `active` | 主动决策：比较活动、升级工具、卖买、查记录 | 全部操作                                 | 默认态；从 idle 点迷你窗主体返回；从 tree 经面包屑/页签返回 |
| `idle`   | 挂机迷你窗：只读监视 + 一键暂停            | 仅暂停/继续、点主体回 active             | 从 active 主动切换；不自动进入                              |
| `tree`   | 画布式树视图：看技能树/工具线依赖          | 浏览、缩放、平移、聚焦；节点点击跳训练页 | 从 active 左栏树列表进入；面包屑返回                        |

三态共用同一运行时、同一动作队列、同一存档；挂机逻辑在任何态下持续运行（idle 的暂停键走 `GameRuntime.dispatch` 现有暂停命令，不新增命令类型）。

## 2. 窗口契约表

单位 px（1rem=16px）。chrome = 固定区高度之和；滚动区不参与加总。布局算术约束：**固定区之和 + 滚动区最小可见高度 ≤ 窗口高度**。

| mode   | default | min     | max      | chrome | mustSee（0 点击必须可见）                                                              | basis  |
| ------ | ------- | ------- | -------- | ------ | -------------------------------------------------------------------------------------- | ------ |
| active | 960×720 | 360×480 | 960×720  | 184    | 状态栏（当前活动+进度+速率）、4 页签、当前技能名与等级、活动列表滚动区 ≥4 行、存档入口 | 见 2.1 |
| idle   | 280×72  | 236×72  | 384×72   | 0      | 动作族插画 64×64、活动名+进度条、产出速率、暂停键 28×28                                | 见 2.2 |
| tree   | 720×640 | 480×560 | 1280×900 | 148    | 左栏树列表 ≥5 项、面包屑、画布中当前可解锁节点及其直接前置节点                         | 见 2.3 |

### 2.1 active 算式

chrome（固定区，实测值源于 `skill-prototype.css`）：

- 窗口壳 padding 上下：0.35rem+0.3rem = 10.4（L97）
- header：min-height 2.35rem = 37.6（L394-397）+ margin-bottom 0.4rem = 6.4
- 常驻状态栏：padding 2.4+4.16 + 状态行 16 + 进度条 6（--progress-height-md）+ meta 行 16 + 边距 ≈ 52
- 页签栏：min-height 2rem = 32（L711-712）+ margin/border ≈ 4
- 存档区：margin 0.65rem + border + padding 0.65rem + 一行 body ≈ 48（L1738-1744）
- 合计：10.4 + 44 + 52 + 36 + 48 = **190.4，取 184**（存档区在 min 档允许折行压缩一行，见 §3 compact）

滚动区最小可见高度：活动行高 56 × 4 行 = 224。

**min 高度算式：184 + 224 = 408 ≤ 480 ✓（余量 72，供 ReturnReportCard 出现时使用）**

min 宽度算式：活动卡 2 列 × min 156 + gap 6.4 + 壳 padding 左右 22.4 = 341 ≤ 360 ✓。

max 依据：960 起启用三列（左技能/树列表 240 + 中详情 400 + 右上下文 240 + gap/padding 80 = 960）；超过 960 列宽不再增长，滚动区吸收余量；超过 720 高度只增大滚动区。

### 2.2 idle 算式

单行迷你卡，无 chrome：

- 高度：插画 64 + 上下 padding 4×2 = **72** ✓
- min 宽度：padding 4×2 + 插画 64 + gap 8 + 文本列 min 120 + gap 8 + 暂停键 28 = **236** ✓
- default 宽度：文本列 164（活动名一行 body + 速率一行 caption 不折行的中文最长场景实测余量）→ 280
- max 宽度：文本列上限 268 → 384；高度恒 72，禁止出现第二行内容

mustSee 四项之外的信息（经验值、等级、队列、存档）一律不回迷你窗，需要时点主体回 active。

### 2.3 tree 算式

chrome：页签栏 36 + 面包屑 28 + 常驻状态栏 52 + 边距 32 = **148**。

- min 高度算式：画布纵向最小可见 = 节点高 64 × 3 + 层间距 24 × 2 = 240；148 + 240 = 388 ≤ 560 ✓（余量 172 供 TreeFilter 展开）
- min 宽度算式：左栏树列表 152 + gap 8 + 画布 min 280 + 壳 padding 40 = **480** ✓
- max 依据：1280×900 以上节点与侧栏尺寸不变，画布平移空间吸收余量；TreeMinimap 在节点数 >300 或画布超出视口 2× 时出现（见 `树契约.md`）

## 3. 断点体系（统一 min-width）

现状两条兜底（`skill-prototype.css` L1903-1928 `@media (max-width:380px)`、L1930-1942 `@media (max-height:520px)`）只压缩不裁切。新体系把它们反转为基准样式，断点统一 `@media (min-width:)` / `@media (min-height:)`：

| 断点                         | 作用域        | 内容                                                                     |
| ---------------------------- | ------------- | ------------------------------------------------------------------------ |
| 基档（无媒体查询）           | compact       | 吸收旧两条规则的压缩样式作为默认                                         |
| `@media (min-width: 381px)`  | active 标准宽 | 恢复壳 padding 0.7rem、按钮 min-height、活动标题字号、活动卡标准 padding |
| `@media (min-height: 521px)` | active 标准高 | 恢复 header 间距、页签 min-height 2.5rem、section 间距                   |
| `@media (min-width: 720px)`  | active 双列   | 训练页主从双列（左技能列表，右详情）                                     |
| `@media (min-width: 960px)`  | active 三列   | 加右侧上下文栏（升级/记录摘要）                                          |

模式切换不经过媒体查询：idle/tree 由 `<main data-mode>` 驱动，宽度断点只在 `data-mode="active"` 内生效。

### 迁移对照（旧规则 → 新体系）

| 旧规则（删除目标）                                   | 新归属                                 |
| ---------------------------------------------------- | -------------------------------------- |
| max-width:380px 的壳 padding/按钮/网格/字号/换行压缩 | compact 基档默认样式                   |
| max-height:520px 的 header/页签/section 间距压缩     | compact 基档默认样式                   |
| 标准样式                                             | 对应 min-width/min-height 断点内的增强 |

验收：迁移完成后全仓不存在 `max-width` / `max-height` 媒体查询（详见 `acceptance.md`）。

## 4. 三态切换约束（架构条款）

1. 单一 React 根：三态由同一棵组件树的 `<main data-mode="active|idle|tree">` 表达，禁止卸载重建根。
2. 面板裁剪用 `display:none`（或等效属性），不用条件卸载；切换后滚动位置与选中技能（`selectedSkillId`）原样保留，二者驻留运行时内存，不新增存档字段。
3. 模式切换本身不发出 dispatch、不改变游戏状态；idle 暂停键使用现有暂停/继续命令。
4. 时代、解锁、速率等全部复用现有派生事实（`src/domain/skill-loop/eras.ts`、`engine.ts`），不新增状态源。
5. 切换动画 ≤ --motion-slow（320ms），只动 transform/opacity，尊重 `prefers-reduced-motion`。

## 5. 不可实现清单（本轮权限外，移交工程侧）

以下条目是 idle/tree 形态成立所必需，但超出"不改配置、不写代码"的本轮权限，移交工程侧评估：

依据已核实的 Tauri v2 window API 文档（2026-10-17 核实，https://v2.tauri.app/reference/javascript/api/namespacewindow/ ）：下列方法均不在 `core:window:default` 默认权限集内，需逐条加 capability。

| 条目                   | 所需能力                                                         | 阻塞影响                   |
| ---------------------- | ---------------------------------------------------------------- | -------------------------- |
| 窗口常驻置顶           | `setAlwaysOnTop`（权限 `core:window:allow-set-always-on-top`）   | idle 态核心卖点            |
| 无边框/自绘标题栏      | `tauri.conf.json` decorations:false + 自绘拖拽区                 | idle 迷你窗观感            |
| 运行时改窗口尺寸/位置  | `setSize`/`setPosition`（`allow-set-size`/`allow-set-position`） | 三态切换时的窗口几何跟随   |
| 托盘图标与快捷切换     | Tauri tray 能力（当前 capabilities 未开启）                      | idle 态的常驻入口          |
| 迷你窗点击穿透（可选） | `setIgnoreCursorEvents`（`allow-set-ignore-cursor-events`）      | 非必需，仅在用户要求时评估 |

以上均不改变本页契约数值；工程侧落地后仅需在本页"实现状态"列回填。
