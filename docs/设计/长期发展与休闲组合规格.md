# 长期发展与休闲组合规格

**已由2026-10-20最新用户纠正替代**：本文件保留旧“院落建设＋设施组合”方案，以下内容不再是当前产品/视觉执行合同。当前主体是技能/作业放置成长，主页面随进度自动完善，不需要玩家选地建造；旧11槽/两类建设样板/C2顺序不再执行。唯一活动要求见 [PLAN](../../PLAN.md)，不在此另起新规划。

日期：2026-10-20。范围：当前 `next/civ-idle/`；本文记录产品、内容和视觉合同，进度与实施顺序只看根 [PLAN](../../PLAN.md)。这是规划交付，未改游戏、数值、存档或线上站点。

本轮最新范围只做桌面 ChatGPT Site，手机与其他平台暂不投入。视觉输入改为[桌面设计稿](ui-v3/README.md)与其可点击原型；下文旧蓝灰色样/手机目标不再用于本批交接，长期发展、真实状态与存档边界继续有效。

## 1. 已确定的目标与本次推荐

用户明确：**同一处地方长期发展，先有完整结构，再逐项建设升级；不要短局、不要副本。** 希望缩小框架、改善配色和操作，并具有休闲肉鸽的爽感。此前助手提出的短局、九格重开和副本方案均撤回，不能交给执行方实施。

本次推荐：**固定单屏的 2D 小镇院落＋自动经营＋有限的随机成长选择与设施联动。** 长期经营是主体，随机选择增加发展差异，不引入局数、清图、强制转生或另一套家园。现有技能、研究、等级和升星保留，但围绕建筑能力变化组织，先停止扩展大时代清单。

“完整结构”包括完整空间构图、资源用途、成长路线、操作与反馈闭环；不等于开局全建好，也不要求现在做完六时代。小镇可以一直经营，后续内容沿同一结构加进去。

| 呈现方式                       | 对本项目的好处                                       | 主要代价                                                 | 本次取舍                         |
| ------------------------------ | ---------------------------------------------------- | -------------------------------------------------------- | -------------------------------- |
| 当前草地上分散摆建筑           | 改动少，可保留逻辑                                   | 整体结构和生活感弱，升级不容易形成场景变化               | 保留代码成果，调整构图与资产表现 |
| 横向长卷、纯侧视与角色行走     | 建筑轮廓、行走和扩张直观                             | 设施要反复横移寻找，手机信息更分散；场景与素材工作量增加 | 不作为本轮方案                   |
| 横向构图、轻景深的单屏 2D 院落 | 能同时看清设施关系、建设前后与下一步，适合鼠标和触屏 | 需要重新安排视图锚点、统一比例与界面层次                 | **推荐，先用真实状态样板验证**   |

这里的 2D 指场景呈现，不更换引擎。建筑正面偏侧，地面略俯视，以前后层次分区；不做纯侧视长街、3D 相机或新的自由编辑地图。

## 2. 先设计完整院落，再逐座完善

主场景沿用中心＋六个初始位＋四个待整修位，共 11 个逻辑位置。中心是公共地标，八类可建设施各有身份，另留空位供后续内容；不再任意追加一批新建筑。

| 场景层     | 空间作用                   | 建筑与变化的建议                                             |
| ---------- | -------------------------- | ------------------------------------------------------------ |
| 远层       | 交代院落边界、降低背景干扰 | 林缘、石壁、远山；自然资源身份不冒充新设施                   |
| 中层       | 提供稳定的中心与生活区     | 中心、住房、厨房与水井；建设后出现门廊、炊烟或提水部件       |
| 前层与两侧 | 看清生产与加工活动         | 农田、伐木、采石、木工与仓储；田垄、堆料、工作台表现用途     |
| 连接层     | 让设施组成小镇             | 预留土路与场地边界，完成相关建设后逐段整理；首批只作视觉投影 |

上表是构图建议，不重新规定每块地能建什么。林地/石脉资格与通用地仍由原规则决定，玩家已有建筑不能被移动、改类或锁死。通用位必须能展示其全部合法建筑，不因背景画了住宅就只能建住房。

旧[结构线框](长期发展单屏结构示意.png)保留历史，用户已否定其UI观感，不再作为施工依据。新的[桌面主界面与组件稿](ui-v3/README.md)用于视觉评审；数值留空，不代表真实玩家状态或正式游戏已经接入。

- 开局看得出道路骨架、可建空地和待整修院落；没有建成的建筑不出现在背景里。
- 空地、施工、完成、升级部件和升星主结构五种状态可分辨；等级段只增有限部件，升星明显改变轮廓或材料。
- 同一座建筑沿原锚点成长，关键部件不被树、浮层或其他设施遮住；固定背景与独立设施分层。
- 道路、居民小剪影、烟气和旗帜只能表现现有事实；装饰居民不成为逐人模拟、派工或独立存档系统。关闭动效不改变产出。

## 3. 爽感来自什么

```mermaid
flowchart LR
    A[看见一个可做的建设目标] --> B[投资建设或升级]
    B --> C[结构变化 自动产能变强]
    C --> D[研究或发展选择]
    D --> E[设施组合 产出连锁]
    E --> F[材料支持下一项改造]
    F --> B
```

| 层次          | 玩家感受           | 要做的反馈                                   | 不用什么替代             |
| ------------- | ------------------ | -------------------------------------------- | ------------------------ |
| 每次操作      | 我点的动作成功了   | 选中轮廓、真实扣费/订单、一个明确结果        | 重复弹窗、满屏飘数字     |
| 一次建设/升级 | 这处地方变好了     | 完工显形、部件增加、产能现在→之后            | 只有等级文字变动         |
| 一条生产链    | 我搭出的组合在工作 | 农事供给、加工、仓储之间的真实联动与结果摘要 | 所有建筑独立加同样百分比 |
| 一次晋升      | 能力有明显跃迁     | 新主结构、可见工作部件、真实上限/能力变化    | 全场景一起换滤镜         |
| 一次回访      | 离开也有进展       | 已结算收益、完成项与下一个可做目标           | 再点一次才能领到离线收益 |

随机只是带来不同的可比较选项；**选择、组合、兑现**才是爽感。不给无用选项、稀有度彩票、随机扣资源或离线惩罚。每次获得新能力都能在当前小镇找到受益对象。

## 4. 首批成长内容：三条路线、六个候选

先组合现有农田、伐木场、采石场、木工坊、仓库，以及既有民生/研究。以下是 C2 的设计输入，**不是当前游戏效果，也不是已冻结的经济数值**。先在 V2 记录真实节奏，再冻结费用、倍率、触发次数和版本；不得把示例百分比直接抄进生产定义。

| 路线          | 候选能力                                   | 与别的设施怎样形成组合                   | 画面如何体现                       |
| ------------- | ------------------------------------------ | ---------------------------------------- | ---------------------------------- |
| 农事·稳定供给 | 食水供给稳定时，提高农田有效产出           | 厨房/水井从维持供给变成发展支持          | 灌溉/田垄部件，状态明确可查        |
| 农事·丰收接力 | 每累计若干次真实农田产出，额外获得一批原粮 | 与农田产能提升叠加，在一次丰收时集中反馈 | 对应田块一次收成反馈，库存真实入账 |
| 木工·标准作业 | 提高木工坊每批有效产出，原料费用清楚       | 木材供给支撑板材，板材推动建设           | 锯台与成品架出现，短配方可读       |
| 木工·边角再用 | 每累计若干次真实加工，返还有限木材         | 降低木材瓶颈；返还本身不再触发返还       | 一次加工结果合并显示产物与返材     |
| 仓储·扩容整理 | 增加真实集中仓容                           | 长离线更容易保留产出，大额升级有去处     | 货架/附棚变大，容量预览同步        |
| 仓储·备料协作 | 仓库和供料条件满足时，提高施工供料效率     | 生产支持建设，完成后继续投资产线         | 材料已送达才推进施工，不凭动画造料 |

可解释的组合例子：稳定供给让农田单位产出变高，丰收接力让某次收成再放大；标准作业增加板材，边角再用缓解木材消耗；仓容留下更多离线积累，备料协作把材料更快转成建筑。倍率不是当前实测结果。首批不同时增加贸易币、装备、英雄、战斗、季节或新人口需求。

**发展机会的推荐边界**：

1. 在实际建设/研究里程碑提供有限三选一；首批最多两个机会，条件沿真实可达性冻结，不按每天登录或等待固定分钟发放。
2. 首个机会应在基础自动链成立后可达，第二个结合工坊/首次晋升；精确条件先核对 V2 的新档节奏，不要求先完成整个时代清单。
3. 候选一经生成立即保存，刷新不重抽；选择和能力生效一次提交。同一里程碑不得重复领奖，旧档已满足条件也只能补发一次机会。
4. 选项至少有当前可用的能力，其他选项须能通过已有内容到达，并给出受益对象和条件。不能为了凑三张塞未实现内容。
5. 已建建筑、等级、技能、科技和已选成长永久保留。未选择的能力不宣称永远绝版；首批允许在中心调整该次机会的已保存备选，只改变未来收益，不返还/重领一次性资源，不重新随机。
6. 机会待选期间自动生产、离线继续；关闭面板可稍后决定，不做强制全局暂停。选完后说明哪个设施变强，并可直接定位。
7. 触发型能力仅统计真实完成的基础生产/加工，不统计飘字、预览、返还、离线摘要展示或其他额外奖励；有限次数结算，禁止互相递归发奖。

这一小包服务长期小镇，不能被实现为闯关、每日重置或副本。后续有实测依据再扩现有路线或补一个新生产能力，不先建立完整肉鸽装备和天赋框架。

## 5. 视觉、配色与操作

**场景采用清楚的 2D 插画轮廓，保留木石与暖光。** 先统一农田/木工坊及中心周边的小样，再成套推广；不强制全项目改像素画，不直接拉伸现有微缩图充当侧视素材。草地降低细碎纹理与对比，建筑比背景更容易辨认。

| 用途            | 推荐色样               | 使用原则                                            |
| --------------- | ---------------------- | --------------------------------------------------- |
| 场景            | 木石、麦田、林缘与溪流 | 世界为主体，背景纹理/对比服从建筑辨识               |
| 面板            | `#F8F0DD` 暖纸色       | 以纸色表面和细木金边饰承载阅读，减少后台大面板      |
| 主文字 / 次文字 | `#403C2B` / `#6C654F`  | 正文14px起、必要辅助12px左右；精确值只维护在新稿CSS |
| 主操作          | 林绿渐变＋浅色字       | 明确一个主动作，检查渐变两端的文字对比              |
| 选中与点缀      | `#D5AC58` 麦金         | 小范围强调，状态同时有文字/形状，避免整屏染金       |

色样以[新稿styles.css](ui-v3/styles.css)为唯一细节源，不覆盖根旧技能原型主题。关键色对已在设计核验中检查，正式游戏接入后的实际背景、悬浮和异常状态仍需核对，不能据此声称整屏可访问性通过。

- 桌面：一条紧凑资源栏＋主场景＋按需出现的对象侧栏；保存状态在角落，正常保存按钮移入设置，失败时持续提供处理入口。
- 手机与其他平台移出本轮，既有实现保留，不追加本批适配、截图或门禁。
- 当前对象默认只给名称、状态、关键效果与一个主操作；升级前看费用和现在→之后，缺料直接定位来源并能返回。
- 六资源仍完整可达；选中对象时突出相关资源，不把原粮/口粮合并，不隐藏保存失败、真实阻塞或费用。
- 点击对象先选择；建设、升级、晋升、采集必须是明确动作。拖动/缩放不能误扣费，建筑遮挡重叠时有清楚的轮廓和等价对象列表入口。
- 复用既有键盘/焦点、44px 主要触控目标、减少动效；无须悬浮才能获得必要信息。文字仍只按[语言合同](../内容资料库/界面语言与信息层级.md)维护。

## 6. 工程落点与兼容

V2 仅改变呈现：`src/scripts/art/{sandbox-art-catalog.json,town-scene-layout.ts,camp-tile-art.ts}`、`WorldScene.ts` / `TileVisual.ts` / `Camera.ts` 中必要视图接线、`ui/sandbox/` 与营地 CSS。保留 CivIdle、React/Pixi/Vite、原 Grid/tile、合法命令和单推进/保存链；不新增工程、不迁移建筑、不重写生产与存档。

C2 才引入成长能力：数值/稳定 ID 放唯一内容定义，纯条件/触发计算进入 `shared/sandbox/`，命令进入既有 `camp-commands.ts`，UI 只读快照并发命令。已有 `camp-economy` / `camp-growth` / `camp-stock` 是必须核对的接入点，不新建第二库存、游戏实例或独立奖励定时器。

C2 的选项、选择凭据、已生效能力、触发计数和随机状态均需可验证地持久化；具体 schema/content 版本在采用表冻结。先按旧规则结清旧离线，再迁移/应用新能力，禁止以新能力补发旧时间收益。在线、后台恢复与离线走同一计算，切换方案先结算旧区间；失败不部分扣费或改方案。保留坏档、未来版本与保存失败保护。此处是必须满足的合同，未声称已经实现或已确定所有技术细节。

## 7. 交付如何判断

- 完整院落的新档、基础链、工坊/2星三种状态可对照；真实状态驱动画面，注入样例仅标为外观检查。
- 农田和木工坊分别展示空地→施工→完成→等级部件→2星，不看标签也能分辨重要变化。
- 用真实新档记录首次建设/升级、基础链、食水稳定、工坊/首次晋升的主动动作与等待；不把设计目标分钟数写成实测。
- 当前仅桌面 `960×720` / `1440×900`：关键操作可达，选中与返回有效；手机/短屏为保留的历史目标，不作为本批门禁。
- C2 首次机会、刷新保持、选择一次、方案调整、条件失效/恢复与离线重载成立；证据说明组合为什么生效、实际新增多少，不能只提供卡牌截图。
- 美术审美、组合是否有趣和长期节奏由用户试玩确认；类型/构建通过不等于这些体验已通过。
