## 当前活动范围：Melvor Idle 式放置成长 MVP

从 Melvor Idle 借鉴的是技能互相提供用途、动作持续推进、离线回来能看到进度与收获；不照搬其内容、文字、美术或规模。官方商店介绍列出 20 多项技能、离线推进、银行/物品管理，以及技能间互相服务的设计。[Melvor Idle 官方页面](https://store.steampowered.com/app/1267910/Melvor_Idle/)

首版围绕现有“岗位持续产出 + 单配方制作队列”闭合技能联动：回收提供原料，工程加工原料并解锁新用途，制作物至少服务一个明确目标。暂不新建通用动作引擎，也不要求一次只运行一个动作。聚焦回收与工程的内容关系；不扩展医疗玩法，不增加共享队员、驻地袭击、运输容量、复杂随机事件和多世界内容。

当前源码已有驻地岗位、生产、制作和经验基础；驻地人口为 3，远征岗位预设合计为 4。这是两套现有实现的配置差异。只有把驻地和远征人员合并时才需要决定人数；本 MVP 不合并它们，也不把 3 人或 4 人定为产品规则。

当前版本仍为产品 0.8.0 / 内容 14.0.0 / schema 9。先按实际状态改动判断是否需要内容版本或存档迁移，不预设 0.9.0 / 内容 15.0.0 / schema 10；任何新增权威存档字段仍须显式迁移、保留原档并验证恢复。

### 阶段 2–4 细化

- **阶段 2：** 复用 `advanceExpedition` 对驻地和副本做同一时间推进。利用已有生产/制作核对计数推导“自上次查看以来”的专业经验与升级，不新增存档字段；经验阈值采用有限精度累计，避免理论满级仍差浮点误差。现有离线与分段推进测试覆盖生产和 XP，存档恢复及 UI 仍由阶段 4 集中验收。
- **阶段 3：** 只接已存在的失籍城救援目标。工程等级 2 解锁屏障组件；玩家在界锚稳定度不足上限时可消耗 1 套，将稳定度恢复最多 18 点，精确受世界容量限制。该行动可帮助玩家在提前迎战后恢复进入现场复核区域的稳定度；不添加通用运输系统、故事事实或新的永久奖励。
- **阶段 4：** 集中验证资源守恒、动作解锁、完成/切换边界、离线切片一致性、存档恢复、救援产物用途和页面尺寸。一个完整切片结束后再跑 .\scripts/project.ps1 check、受影响的 E2E、Web/desktop 构建；修改 Rust/Tauri 时才加 native 检查。试玩记录玩家是否能说清当前动作、下一解锁和产物用途。
- **版本处理：** 版本号在阶段 1 的持久状态形状和兼容范围确认后再定。兼容变化显式迁移；不为了“一个阶段一个版本”机械升版。
- **实现节奏：** 实现期间做必要的类型/领域定向检查；不对每个文案或布局微调重复跑整套测试。完整纵向切片通过后集中做一次门禁。

### 本轮切片进度

- **已实现：** 扩建回收货栈消耗 8 块回收合金、4 枚蓄能芯和 1 块结构板；单批按钮支持精确投入。工程等级 2 解锁屏障组件；副本内用 1 套加固失籍城界锚，稳定度最多 +18，达到世界上限时只恢复缺口。
- **离线与成长：** 岗位和配方继续经现有 Runtime 离线补算；自上次查看的生产/制作计数可推导各专业 XP 增量和升级提示。工程进度条显示当前 XP 与下一等级配方；不增加权威存档字段。
- **数值边界：** 80 分钟的工程自动作业应累计 8 XP。首次定向运行暴露二进制小数误差造成 7.999999999999988、无法解锁的问题；生产经验现按 1e-6 有限精度归整，避免“显示已满但仍锁定”。
- **资源可达性：** 开局 12 块合金、10 枚蓄能芯；制作首块结构板预留 3 合金和 1 蓄能芯，工程人员转入制作期间，回收岗位仍持续生产。完成后可支付扩建成本，扩建增加 100 仓储容量及每种物资 +40 上限。没有引入手动采集门槛。
- **兼容性判断：** 本轮仍未改 `SaveBundle`、存档 schema 或内容 ID；新增能力只消费现有驻地库存并更新副本已有的界锚稳定度，自动/离线推进规则不变。已有 schema 9/content 14.0.0 存档保留原状态，新能力按当前库存自然可用，因此保持产品 0.8.0、内容 14.0.0、schema 9，不做无必要迁移。
- **本轮集中门禁：** `./scripts/project.ps1 check` 通过，15 个测试文件共 250 项；Web 与 desktop 前端构建通过。Chrome 首次全套 E2E 为 9/11；两条失败来自严格要求初始 XP 必须为 0、以及夹具设置了事件选择却未记账。修正 UI XP 格式/夹具后，两条原失败用例分别定向通过；新救援流程也在 420×600 和 360×480 检查按钮宽度，并通过制作屏障组件、加固、保存重载。救援浏览器夹具从工程等级 2 开始以避免等待 80 分钟；领域测试另验证自动作业 80 分钟可累计 8 XP 并到达等级 2。回访摘要用例验证 XP 与“升至等级 4”。未在定向修正后重复整套 E2E，因此不记为一次干净的 11/11 全跑。

## 可扩展边界

波次、环境节点、发电机完整度、目标条件、事件选项、资源费用、阶段门槛、派队项目和线索由机械内容与封闭的领域合同驱动；UI 用稳定 ID 取主题文案并只经 runtime 派发命令。增加已有规则积木不复制运行时或存档队列；新机制仍需纯规则、迁移与验证。当前没有任意脚本执行器、随机副本生成器或 LLM 事件服务。

内容 ID 和机械配置进入存档兼容约束；增删或改变既有 ID/条件时需要显式迁移。主题颜色、背景和展示文案不进入存档。

## 后续方向：第三个世界加入独立玩法（历史候选，仍需另行规划）

默认方案“暴雪观测站”，衔接序章坐标。新增燃料与温度，让取暖、生存、生产竞争资源；以修复观测站、拼接下一段记录作为阶段目标。

先实施一个完整任务模式：资源事实→设施→环境节点→基础/可选目标→安全回归→主空间后果。新增规则需要明确存档兼容与测试。不要仅换背景、改怪潮数值就计作完成新玩法。

后续候选：多站护送列车、搜证与规则验证城区。当前只列内容路线，尚未实现。

## 后续方向：重玩变化与持续扩展（历史候选，仍需另行规划）

- 每局契约/事件组合，带来资源压力、建筑限制、不同可选目标。
- 世界的后续版本与故事分支，因已带回证据改变任务与角色回应。
- 永久能力扩展不同玩法路线；避免无限倍率把决策消除。
- 各卷给阶段答案，下一卷保留新问题；重复进入有不同目标与可见后果。

机制组合提供重玩，固定章节提供故事连贯。两者都需要内容与数值迭代，架构本身不会自动产生无限可玩性。

## 后续方向：音效与美术（历史候选，仍需另行规划）

玩法和首卷结构稳定后补采集、建设、事件、战斗、回归的声音反馈，以及主空间、各世界背景与角色表现。支持静音和简洁视图，继续服务桌面角落使用场景。
