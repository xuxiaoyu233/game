## 编辑资料与运行时内容

这里的“资料库”采用仓库内版本化文档，配合类型化 TypeScript 定义。现有规模不需要 SQLite、在线 CMS 或动态插件；没有建立运行时读 Markdown 的能力。

| 对象                           | 唯一责任源                                | 消费方式                       |
| ------------------------------ | ----------------------------------------- | ------------------------------ |
| 类目、命名提案、来源与设计理由 | 本目录对应台账                            | 编辑参考；不决定产出或扣费     |
| 生效的机械字段                 | `src/content/data/*.json`（经加载器组装） | 由组装入口注入规则/runtime     |
| 已冻结的历史内容               | `src/content/data-v5                      | v6                             | v7  | v8/_.json`+ 对应`skill-prototype-v_.ts` | 只作 content `5.0.0`–`8.0.0` 迁移源，不随 `data/` 变化 |
| 生效的显示文本                 | `src/themes`                              | 依 ID 取文案，不参与规则计算   |
| 生效的行为与事实校验           | `src/domain`、`src/persistence`           | 有限联合类型、纯规则与版本校验 |

文档中的数值是有版本/状态的设计记录；生效数值以对应代码定义为准，不把两份可独立编辑的数据同时视为运行时真源。

## 内容记录最小字段

每项记录至少含：稳定编辑/机械 ID、种类、通用名称、来源或设计依据、适用版本、批准状态、实现状态、可见范围、来源与消费端/前置关系、代码映射、兼容性影响。复杂项再增加效果合同，不要求所有卡片填无意义字段。

- 批准状态：已批准 / 候选 / 历史。实现状态：未计划 / 规划中 / 已实现 / 自动检查通过 / 待人工验收；两轴独立。
- 无代码映射时写“无运行时映射”，不把计划路径标为已实现。
- 名称与别名服务检索/展示，不能自动映射存档 ID。相似名称、相同图标或相同类别不证明两个资源可互换。
- 展示类目如“原料/加工品/工具”默认不参与存档；若类别开始决定配方、背包限制或解锁，须升级为机械字段并审查兼容。

## 扩展与验证

每个阶段同时交付玩家路线、该档资源/解锁关系、适用实现和资料对照。进度仅在 PLAN 维护。

1. 在对应唯一台账登记候选、来源、输入输出和玩家可观察用途。
2. 已有规则支持的新物品/配方，修改 `src/content/data/*.json` 与 themes，并跑 `check:content-json`；不能声称“只改文档自动生效”。
3. 新行为如消耗品效果、燃料离线上限、科技互斥、战斗或特殊停点，需要 domain 合同、定义/存档校验和必要迁移。禁止用文案、任意函数或脚本偷带行为。
4. 在 `main.tsx` 组装并验证机械定义与展示映射；app 不直接导入 content 或 docs，不维护第二份解锁/用途真相。
5. 更新唯一 PLAN 的阶段证据。改文案、数值与状态形状分别审查，不为了改名字改 ID，也不因 schema 未变而忽略机械内容兼容。
