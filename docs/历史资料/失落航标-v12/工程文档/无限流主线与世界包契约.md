## 世界观与主线

作品主线《失落航标》（早期工作名“航标零号”）：玩家在没有出口的中转站醒来，值守员岑声称返航坐标遗失。每个副本是被事故切开的世界片段，生存任务维持片段稳定，稳定之后才能带回记录。主空间每次收到证据，逐渐改变对事故的解释。

玩家有两条并行目标：积分兑换让下一次更容易生还，线索拼接让下一次有新的目的地与问题。岑是跨世界持续存在的人物，负责连接任务，并且自身也是谜题的一部分。玩家的选择记录下来，改变后续远征补给及未来的叙事回应。

序章的确定事实与悬念：

1. 森林信号指向古城：完成基础生存并回归，带回 `forest-signal`。
2. 主空间首次汇报：选择追查信号或援助幸存者；两路均开放古城，分别提供石材或木材补给。
3. 古城年代比森林更晚：成功回归带回 `ruins-record`，发现世界顺序存在问题。
4. 对话拼出第一段坐标：完成 `keeper-revelation`，序章的小闭环完成，引出暴雪观测站。
5. 隐藏支线：森林修复烽火台后调查残刻，古城支付木石调查石碑。两份证据都成功带出后，可核对航标重启与岑身份的矛盾。

调查消耗当前生存资源，会挤占防守预算；找到的证据暂存在副本，必须成功回归才能永久保留。重复进入可以补此前错过的证据，已经永久收集的证据不重复发放。失败保留既有档案，丢失本轮尚未带出的发现。

| 第一卷后段：暴雪观测站   | 是谁重排了顺序，为什么？   | 燃料在取暖、校时和生产间竞争；预告寒潮带来环境压力 |

| 第三卷：镜像城区         | 玩家与值守员有什么关系？   | 搜证、规则验证、阵营信任；线索组合改变可选任务     |

每卷给出可理解的阶段答案，同时保留下一卷问题。重玩变化由不同契约、事件组合和任务目标提供；章节不能依靠无限增加敌人生命或重复点击填时长。本版两个世界仍共用生存基础规则，后续应优先加入真正不同的资源和任务模式。

### 开放式副本池（候选方向）

W-03 暴雪观测站、W-04 多站列车、W-05 镜像城区是主线锚点草案，不是整个游戏的副本上限。未来的副本实例可从**世界种子 + 重复任务骨架 + 本局变化条件 + 已审核突发事件包**组合；一部分远征推进《失落航标》主线，其余可补充伙伴关系、世界类型或资源策略。共同剧情只复用进入、验证、取舍、突发、结算、回归的节奏，不复用同一个谜底。当前原创候选点子见[候选世界种子池](../副本资料库/候选世界种子池.md)，素材规则、小说结构观察和具体世界文案以[副本资料库](../副本资料库/README.md)为准。

### LLM 临场叙事（未实现的目标设计）

当前世界、事件和选项均来自固定配置，`src/domain/expedition` 纯规则判定，`src/themes` 保存展示文案；当前没有游戏内模型 provider。后续若接入，LLM 可在审核过的事件族中为本局编排新的临场表现，并只能使用该事件族的固定响应 ID；不能改动作者真相、永久线索、目标、选项效果、资源数值或存档状态。合法响应和结算仍由 typed content 与 domain 校验，玩家操作仍经 runtime 命令/保存队列。

本地预写事件必须独立完整可玩；断网、模型关闭、超时或响应校验失败时回退本地文案，不等待远程服务、不丢状态。生成文本视为不可信展示数据；不上传完整存档或本地路径。运行时端口、请求白名单、响应 schema、费用/隐私开关与缓存策略都要先评审，再决定是否实现。详细流程见[无限副本生成与 LLM 事件契约](../副本资料库/无限副本生成与LLM事件契约.md)。

## 本版数据契约

机械配置在 `src/content/story.ts`，文案在 `src/themes/story-copy.ts`。纯规则不读小说、网络或 UI。

| 类型                                    | 责任                                                    |
| --------------------------------------- | ------------------------------------------------------- |
| `StoryClueDefinition`                   | 稳定 ID、来源、世界、波次/建筑/烽火台条件、调查资源成本 |
| `StoryDialogueDefinition`               | 必需证据、合法选项、授予线索、每次远征开局补给          |
| `Profile.discoveredClueIds`             | 已成功带出的永久证据，唯一 ID 去重                      |
| `Profile.dialogueChoices`               | 一次性对话选择，不允许文本随意改规则                    |
| `Run.recoveredClueIds`                  | 本轮调查发现，失败/放弃清除，成功回归原子转入 Profile   |
| `WorldDefinition.unlockAfterDialogueId` | 世界需要的回归对话，和前置世界通关条件共同校验          |

调查与对话使用 typed commands；规则校验阶段、条件、支付与重复领取。运行时先成功写入同一个 SaveBundle，再显示结果，失败不虚报解锁或发现。NPC 当前没有自由文本 AI 接口；当前对话是可配置分支，选择带来真实玩法变化。未来的临场叙事目标设计见上节，不能据此声称已经接入。

旧格式迁移默认建立空的叙事档案，不虚构玩家经历；原型旅程完整保留。v0.2 尚未交付时加入该合同，仍属 schema2/content2.0.0；未来已发布内容变化必须制定兼容方案。

## 新世界包的最低要求

新增内容必须同时给出：为何进入、独立的规则或任务变化、基础/可选目标、退出与失败规则、能带走的证据、对主空间的影响、下一步悬念、文案与素材出处、可执行的规则测试。只改名称、背景或敌人强度不能计为完成一个有独立玩法的新世界。

现有条件表达只覆盖波次、建筑与修复选择。温度、护送、搜证等下一批规则需要新增相应事实与命令；不把尚未支持的玩法塞入任意字符串或脚本。先增加一个完整的新任务模式，再考虑通用世界包编辑器。

## 内容制作与验收

我们的聊天可提出新世界、剧情和规则；先整理成世界包草案、指出故事与机械成本，再变为校验过的配置和代码。离线 AI/WorkBuddy 可辅助起草候选资料，但调用成功、账号免费与游戏内实时模型接通是不同事实，分别核验。正式版本有固定内容 ID、明确版本、审核后的规则；运行时模型只生成受约束的展示变体，不自由生成奖励。

验收需确认：两个世界通过线索连接；真实回归才保留发现；选择改变下次开局资源；未完成条件无法开启对话或调查；同一选择/线索不能重复领；失败不丢旧档案；切主题和重启不丢叙事状态。完整长期剧情和耐玩度仍需持续内容制作与试玩，代码架构本身不能产生无限内容。
