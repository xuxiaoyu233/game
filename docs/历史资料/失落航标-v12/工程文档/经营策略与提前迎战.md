# v0.3：经营策略、提前迎战与资源总览

日期：2026-10-03。针对“玩法单一、缺少物资图表”的实施合同；验证结果记录在工程验收记录。

## v0.6：安全返航与追加冒险（阶段自动门禁通过）

满足本局必做目标后，玩家有两种决定：立即回归领取全部当前回报，或先执行一次“锁定战果”，把当前可得积分、已完成目标与证据写入本局存档，然后挑战下一波。锁定后撤离或失守只结算锚定内容；锚定之后取得的积分、目标和证据仍有风险。若成功结束整局，结算会合并已锁定和新获得的条目，避免重复计分。三波都属于必做目标的契约，在必做条件达成前不会开放锚点。

挑战面板需同时展示下一波预计损伤、守住后可新增的最终波次/可达目标奖励、已锁定与未锁定积分，以及提前出战会舍弃的木石产量。主动挑战的额外早战积分仍显示在开战按钮上，成功回归才结算。`secure-rewards` 是唯一新增命令；事实存入 RunState，由同一 Runtime 队列保存，v6 旧档按冻结 v6 规则补算后进入 schema5/content7.0.0。

阶段集中门禁已通过：198 项单测、14 项浏览器流程、Web/desktop 构建、11 项原生测试及隔离标识桌面构建。四条规则样本见[原子能力与验收](../../../规划/玩法原子能力与验收.md)。这是一套有安全兑现点的风险选择，不代表奖励数值已平衡；规则推演、浏览器流程和打包成功不能代替实际玩家试玩或 Windows 托盘/置顶验收。

## 本轮玩法

| 原子能力 | 操作与限制                                                                     | 结果                                                                                          |
| -------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 人员调度 | 四人，均衡 1木/1石/2守、伐木 3/1/0、采石 1/3/0、守备 0/0/4；准备或待迎战可调整 | 每人自动产出木 0.06/秒或石 0.055/秒，守备每人基础防御 +3；自然产出仍保留                      |
| 本局路线 | 首波前选择一次；未选择则首次战斗固定均衡；之后不可切换                         | 均衡产出/防御 ×1；开拓 ×1.35/×0.85；坚守 ×0.8/×1.25。防御向下取整，永久采集训练仍乘入自动产出 |
| 提前迎战 | 准备中、已有避难棚；单次确定性战斗，不并发推进                                 | 舍弃剩余生产时间，怪潮随提前比例增强，成功后记录临时加分                                      |
| 资源账目 | 开局物资、实际自动入库、手采、事件获取、累计消耗分别记录                       | 当前库存 = 开局 + 自动 + 手采 + 事件 − 消耗；满仓溢出不算收入                                 |
| 资源总览 | 当前总件数、各资源/容量、累计获得、累计消耗、收支条形图、产出来源、建设预算    | 图表来自真实账目；木石合计是件数，不能互相替代支付。预算超过剩余生产阶段时不显示虚假等待承诺  |

提前比例 `r = 本阶段剩余时间 / 本阶段完整时间`。额外积分为 `floor(5 × r)`，早战强度为 `ceil(通常强度 × (1 + 0.2 × r))`。通常强度先应用可选末波强化。越早奖励越高、压力越大；接近到时可能加分为零。

早战积分规则沿用每波最多 5 分、三波最多 15 分；失败的那波无新增早战积分。没有锚定的本轮奖励在失败/撤离时全部失去；v0.6 执行返航锚后，已锁定部分会结算，之后新增奖励仍会失去。提前清掉第一波只能开始第二段准备，不能重复领取同一波或自动直接完成下一波。

例：首段剩余 60/180 秒，森林首波强度从 20 变为 22，守住暂记 1 分。剩余的 60 秒不再补产；临时 1 分尚未进入主空间余额。

## 存档与兼容

存档 schema3/content3.0.0 新增人员、路线、临时早战积分、战报早战信息、收支账目。schema2/content2.0.0 使用冻结的旧内容定义先校验，再按旧自然与建筑产量补算旧离线段，停于旧待迎战边界；完整消费旧时间间隔，随后启用新规则。

旧档保留积分、兑换、已通世界、剧情线索、选项、建筑、生命、阶段、真实旧战报和原型归档。已经作战的路线固定为均衡；尚未首战可选择一次。无历史账目可恢复，所以以升级后库存作新账目开局，明确显示“收支自升级起统计”。不倒算不存在的历史收入，不把旧伤害改写成有人员加成的新伤害。

未知格式/内容、非法资源或不一致账目明确拒绝，不静默重置。启动迁移保留单一候选与保存屏障，写入失败重试不重复补算；新重要动作仍经单一运行时队列，保存成功才发布结果。

## 参考与设计归属

- [A Dark Room 官方工种源码](https://github.com/doublespeakgames/adarkroom/blob/master/script/outside.js)：借鉴有限人口分配工作、自动执行的方式。本项目先用四个预设降低角落小窗的操作负担，当前没有工人个体 AI。
- [Kingdom Rush 官方 Steam 成就](https://steamcommunity.com/stats/246420/achievements)：存在提前呼叫全部怪潮的成就，为“玩家掌握开战时机”提供参考。本项目的积分与压力公式是自定规则，来源不证明该游戏采用相同公式。
- [Against the Storm 官方介绍](https://store.steampowered.com/app/1336490/Against_the_Storm/)：借鉴短局经营与跨局成长组合；本局路线用于形成不同建设倾向。当前没有完整随机天赋池。

## 验收重点

无需持续点击即可通过自动调度积累建设物资；不同路线产生不同产出/防御；早战预览与结果一致，额外分失败清零、回归只发一次；图表账目平衡、仓储溢出不虚增；旧档补算使用旧产量，保存失败不丢进度。

0.6 本轮继续沿用两种木石生存世界，不包含新世界规则、随机契约、音效、具名伙伴或自由文本 AI 对话。后续顺序以[当前 Plan](../../../../PLAN.md)为准：先验证成长与返场回应，再单独设计温度/燃料等新模式，并按[故事线设定集](../故事线设定集-v12.md)衔接章节。
