# 游玩体验自检与改进

日期：2026-10-07。检查对象为当前产品 0.7.1、schema 7、机械内容 12.0.0。本文区分规则推演、自动化测试、产品判断和真实试玩；前三者都不能代替玩家试玩或完整 Windows 桌面验收。

## 结论

当前版本已形成一条可理解的纵向切片：主空间选契约 → 副本自动经营与任务决策 → 安全回归或承担额外风险 → 永久成长和故事档案 → 返场。森林与古城负责经营/防线选择，雪站引入燃料、温度和设备修复；F-01 又让 17 条已实现故事线索通过经校验的 TypeScript 投影供档案与任务 UI 使用。资料库仍是人工维护的编辑资料，隐藏作者真相和候选世界不会被投影到游戏。

作为可中断、能短时回访的桌面游戏原型，循环方向合理；作为已经验证耐玩、能长期扩张的“无限流”游戏，还不成立。现在有一卷可回访内容，但真实玩家试玩未完成，森林与古城仍共享波次生存底层，返场内容数量有限。v12 加入事件与难度组合后增加了局内变化，仍需玩家反馈证明这些变化读得懂、值得重玩。不能用自动测试证明玩家会持续投入。

## 本次走查发现与处理

| 发现                                                 | 证据与影响                                                                                                                                                     | 处理                                                                                                           |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 首次出发没有把自动生产和基础任务说明放在主要入口附近 | 新玩家需要从下方故事/规则卡自行拼出“做什么、是否必须手动点击”                                                                                                  | 已在首航主空间提示中增加值守员岑的简短说明：队员自动采集；搭建避难棚并守住前两波即可回归；手动采集只补资源缺口 |
| 开放的可选项目/调查藏在“任务”页签中                  | 副本首页原先只提示阻塞事件和烽火台；河岸项目开放时没有页签标记或跳转入口，玩家可能漏掉需要资源与人力的故事选择                                                 | 已将可执行项目和调查纳入任务待办提示；点击提示可直接进入任务页。浏览器流程覆盖项目开放场景                     |
| 快速回归可能压过经营路线                             | v11 样本曾得出 72 秒/28 分；v12 复算加入转岗损失与早战零分边界后，零手采锚点路线为 92 秒/27 分，10 次补采为 110 秒/26 分。规则样本不是玩家偏好或全策略最优证明 | 已实施 20 秒转岗期和 10 秒手采冷却，并保留早战收益/压力上限；后续由无引导试玩判断是否还有单一路线压制其他玩法  |
| 难度条款需要显示“选了什么、值多少、何时结算”         | 三条条款可组合；若总难度、世界适用性和奖励档位在局前不可见，玩家无法判断额外收益是否覆盖本局风险                                                               | 局前展示条款效果、合计难度和 4/8/12 分档；仅成功完成基础契约时发放一次                                         |
| 随机事件不能成为离线惩罚或不可读暗骰                 | 每世界两条事件，一局最多抽一条；需要满足世界/契约/阶段条件，事件选择期间暂停推进并展示选项成本/结果                                                            | 运行时注入并保存种子；待选事件冻结时间推进，提供零成本退出；随机只选事件，不暗骰损失或永久故事事实             |
| 森林、古城重复使用波次生存骨架                       | 两个世界的资源、强度、契约与故事不同，但建设和迎战的基础循环相同；雪站才有明显独立机制                                                                         | 接下来新增内容优先验证是否改变资源与决策结构，而不把改背景、改波次数字计为新玩法                               |
| 长期耐玩性和桌面行为尚无玩家/设备证据                | 自动测试覆盖规则和浏览器流程；真实玩家游玩、Windows 置顶、收起/托盘恢复、关闭保存和重启仍未完成                                                                | 不宣称已验证耐玩或原生桌面完整交付；把两类验收作为下一阶段的独立证据                                           |

## v12 规则复算

- 零手采锚点路线：92 秒、27 分；10 次补采路线：110 秒、26 分；两者均能完成基础目标。
- 河岸调查路线：180 秒、32 分，额外花资源和项目工时并带回河道证据。
- 生产投资路线可完成第三波并得到基础与可选回报；路线不代表最优策略。
- 领域测试覆盖八种条款组合、奖励档位、早战零奖励不加压、20 秒转岗暂停产出/防守、事件种子稳定和待选暂停。

## 本轮验证

- 本轮领域/存档与故事档案投影测试：13 个测试文件、227 项通过，其中 F-01 的 5 项校验覆盖遗漏线索、错误世界、错误对白授予和缺失主题文案。
- 浏览器：完整 25 项用例通过；新档森林→古城→雪站→答案归档→森林返场，以及随机事件、研究工具、返场变体和强化挑战均覆盖。最终全套复跑使用 Playwright `--trace off`；一次保留 trace 的运行在 Windows 清理临时 trace 文件时出现 `ENOENT`，关闭 trace 后所有用例通过，项目默认 trace 配置未改。运行需要本机回环访问 Vite，沙箱先拒绝访问，提升执行权限后通过。
- Web 与 desktop 前端构建：均成功。主 JS 包约 532 KB，有 Vite 的非阻断分包提示。
- 原生门禁与 v0.7.1 exe：本轮 `native-check`（rustfmt、Clippy、11 项 Rust 测试）通过。当前源码 release 编译成功，但 `native-build` 包装脚本在覆盖被占用的标准版本化 exe 时失败；旧文件保留，另存独立当前源码 QA 候选包。Windows 原生窗口、置顶、托盘、保存和重启仍待人工交互验收。

## 最佳实践如何转成项目检查项

- Sid Meier 在 GDC 的设计演讲把游戏讨论为一系列有趣决策，并重点讨论决策节奏以及玩家所需的信息和反馈。本项目因此检查每个高后果按钮是否在点击前展示成本、收益、损伤/放弃项；任务入口也应在决策开放时提示，而不能只把内容放进深层页签。[GDC Vault：Interesting Decisions](https://www.gdcvault.com/play/1015756/interesting)
- Against the Storm 的开发者曾把宏观层缺少结构、风险、目标视为问题，并用地图、周期、世界事件和最终目标串联多次经营。这里借鉴的是“局内循环之外仍有清楚的跨局目标和风险”，不是复制其地图或机制。[Eremite Games：Cycles Reforged](https://eremitegames.com/cycles-reforged-update/)
- 一项 FDG 2019 论文以 11 款放置游戏为样本，概括了主动参与、非活跃推进、回归奖励的常见循环。样本有限且研究用途偏社交运动游戏，因此只作为检查框架：离开时能稳定推进；危险节点不会在离线时替玩家作不可逆决定；回归后能看见具体收获。[Drexel University：Enhancing Social Exergames through Idle Game Design](https://researchdiscovery.drexel.edu/esploro/outputs/conferenceProceeding/Enhancing-Social-Exergames-through-Idle-Game/991019168835504721)

## 下一步验证顺序

1. 邀请少量玩家从新档完成第一次森林回归，观察是否能独立说出当前目标、自动生产规则和回归条件；记录卡点，不给出试玩引导答案。
2. 对比四种路线：零手采速回、手动补缺、投资防御后挑战、调查/项目取证；同时测试有/无难度条款和事件选项。记录真实游玩时间、奖励、损失、人力/木石机会成本和玩家选择理由，再校准数值。
3. 完成 Windows 隔离数据目录验收：置顶开关、收起/托盘恢复、关闭保存、重启恢复。浏览器测试不替代这项验收。
4. 根据证据扩展第二卷或返场机制：每新增世界至少改变一项关键资源竞争、危险响应或目标结构，并给主线带回一条可验证的新事实。

音效、更多美术、手机接续、云同步和 Sites 发布都不影响本次判断，继续留在各自的后续范围。
