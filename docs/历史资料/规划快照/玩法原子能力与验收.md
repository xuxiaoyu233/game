## 先确认玩家在玩什么

推荐核心是“用有限资源与人力完成世界契约”。资源增长是支撑，真正的决策包括：投入生产还是防守、是否占用队员探索、何时迎战、是否承担额外目标、带回的证据如何影响下一次准备。

手动点击保留为补缺口和反馈，不应是基础任务唯一通路。自动经营需要玩家设定目标与分配，后续可解锁有限的自动调度规则；不把“自动连点”当成进阶玩法。

每个新增机制必须说明：它改变哪次决策，和谁争夺预算，玩家如何理解结果，重复进入怎样变化。如果只增加等待、数字或一个每局必须照顺序点的按钮，先不进入实现清单。

## 玩法层次与组合

| 层次          | 内容                                 | 玩家得到的变化                                   |
| ------------- | ------------------------------------ | ------------------------------------------------ |
| 局前准备      | 世界、任务契约、有限装备/能力槽      | 本局目标和可用方案不同，不能所有永久能力无脑叠加 |
| 自动经营      | 人力、生产设施、预算目标             | 以规划替代反复采集；能看清缺口和产出瓶颈         |
| 节点决策      | 探索、事件、开战时机、环境分配       | 同一库存下也可能有不同选择                       |
| 基础/追加目标 | 基础回归、调查、纪念工程、困难条款   | 区分能安全结束与值得继续冒险                     |
| 跨局成长      | 新准备选项、世界解锁、证据、人物回应 | 下局策略/目标变化，不只倍率增加                  |
| 返场变化      | 不同契约、受控事件、已知情报         | 已读剧情不反复刷奖励，同世界有不同合理解法       |

## 能力合同的统一格式与依赖

定案时每项能力都用同一张卡：玩家问题 → 触发/输入 → 前置与可用状态 → 成功事实 → 时间边界 → 失败与恢复 → UI 反馈 → 验收例 → 依赖与版本影响。这样产品条目可以直接转成工程任务，避免仅有“新增探索”“优化界面”的泛化需求。

共同失败约定：输入不存在或前置不足时给出具体原因，不扣成本；关键动作写入失败时不展示动作已成功，保持可重试屏障；已经合法推进的时间按运行时语义保留。重复提交靠阶段/项目/轮次事实拒绝或返回既有结果，不依赖按钮临时禁用。费用、占用、结果和去重记录属于同一次提交。

| 组合           | 必需依赖                                      | 完成后能评审什么                                     |
| -------------- | --------------------------------------------- | ---------------------------------------------------- |
| 局前契约与准备 | G-01 → G-02/03 → G-04；G-30 保障提交          | 玩家能否在进局前理解规则、目标、成本与可用方案       |
| 经营与项目     | G-05/07/09/29；G-06 → G-11 → G-12             | 是否存在真实人员和资源竞争，零手采是否仍可达基本任务 |
| 事件与挑战     | G-13 → G-14；G-15 → G-16/17 → G-18            | 代价预览是否足够，提前挑战和事件是否改变路线         |
| 回归与故事     | G-19/20 → G-21/22 → G-23/26/27                | 临时成果如何转永久事实，成功/失败/返场是否能连贯     |
| 长期重玩       | G-24/25 的选择事实 → G-28；复用上述经营与挑战 | 新任务与旧知识是否带来新行为，而不只是数值上涨       |

箭头表示规划依赖，不规定具体函数调用或 UI 直接串联写盘。系统型能力在目录中是责任入口，例如 G-30 下已有加载、迁移、写入、导入与恢复合同；以后只为确实新增的行为拆子卡，不借本轮重新实现保存底座。

## 重点合同一：人员与探索需要真实机会成本

玩家意图：安排一部分队员去调查，在“更快获得证据”和“留下更多人守营地”之间选择。

规划合同输入：项目 ID、派出数量、确认后的物资成本。当前实现简化为内容定义固定人数、一名队员选择工种、资源成本和工时；没有个人身份、主动取消或中途召回。后续若扩展这些能力，再补明确状态转换。

原子结果：费用扣除、占用记录、项目进度和该项目轮次标识一起生效。有效人口满足“采集 + 守备 + 工程/探索占用 = 总人口”；待回报队员是否可回防在任务卡明确写出。危险前将采集工改守备可以保留，但不能凭一个按钮把正在外出的队员拉回来。

失败反馈：缺队员时说明谁被什么项目占用、预计何时返回；资源不足列出缺口；存档失败仍维持旧分配。验收场景：两人外出时，最多两人可守备；两项目不能重复占同两人；完成与重启后只归队一次；离线遇回报选择停在节点。

当前已经实现单项目占用一名工种队员；个体身份、多项目、召回等仍未实现。占用不自动等于有效策略：外派守备在无战斗的等待窗口可能没有实际损失，须按 B-04/B-05 验证项目互斥和阶段机会成本。

## 重点合同二：提前迎战

玩家意图：缩短本局、争取额外回报，承担更少建设时间及更大危险。

输入：下一危险节点，当前已经结算到操作时刻的库存、人员、设施、任务和生命。需要一起预览：正常强度与早战强度、预计战后生命、放弃的生产/项目进度、额外奖励、是否还有未完成基础条件。

当前内容版本保留每波最多 5 分、敌方强度最多 +20% 的早战奖励/风险上限。若某次早战的预览奖励为 0，不再提高该波敌方强度，避免只承担额外伤害却没有早战收益。v12 路线样本已比较零手采锚点、10 次补采、河岸调查和经营投资路线；这些只说明规则里存在不同成本/结果，玩家偏好仍待试玩。

限制：同节点不重复解决；早战不把舍弃的准备时间补到后阶段；临时积分不直接算主空间余额；项目没完成时不能通过台词视为完成；接近到时额外分为零时明显提示。

验收场景：同一局分别早战/等候，结果符合预览；成功基础回归加分只发一次；失守/撤离按确认后的奖励边界结算；早战触发保存失败可重试，旧生命/波次/积分不部分改变。

0.6 采纳的风险边界：必做目标完成后可锁定当下积分、目标与证据；继续获得的目标/积分仍有风险。锚点必须形成存档事实并经过校验，不能只在界面显示“已保底”。当前自动规则用例将对比快速回归、生产投资、调查取证以及锁定后失败/成功；实际玩家是否理解和偏好仍需后续试玩。

## 重点合同三：任务与事件

基础任务、可选目标、事件选项分别管理。基本任务必须能通过规则事实完成；可选目标明确额外投入；事件改变资源竞争、项目路线或信息，不只有随机送/扣资源。

第一批任务条件限于少数类型：设施/阶段达成、指定项目完成、证据带回、环境安全、护送到点。组合采用可解释的“全部满足/任一满足”；拒绝任意可执行脚本条件。条件图必须可达，不能所有目标互为前置。

当前实现例：森林河桥损毁。修复消耗木 4、石 2 并解锁测绘项目；绕行免费且关闭本局测绘路线。项目再花木 4、石 4 并占用一名工种队员 45 秒。另有森林、古城、雪站各两条受控副本事件，每局最多抽取一条；事件只从满足世界、契约和阶段条件的候选中选出。每个选项展示确定成本与后果，并提供安全退出以避免资源不足时锁死。永久故事事实仍由固定线索 ID 与前置条件授予。

副本事件种子由 runtime 注入并与副本一起保存，domain 按种子确定性选择；重新加载不重抽。事件出现后暂停副本推进并等待选择，离线时间不会继续扣资源、处理危险或暗中判负。旧 v11 活动副本迁移后随机事件池关闭，不获得新规则。

难度条款首批为补给短缺（难度 1，木石各 -25%）、压缩准备（难度 2，生存准备/雪站阶段时间 -20%）、威胁升级（难度 2，波次强度 +15%/雪站燃料消耗 +20%）。三条可同时选择；总难度 1–2、3–4、5+ 分别在成功完成基础契约后奖励 4、8、12 永久积分。选条款不替代局内的末波强化选择。条款只在出发前锁定，旧进行中副本不追溯适用。

## 重点合同四：永久成长与返场

永久成长有两条轴：能力让基础操作更省力；内容/准备解锁让下一局有不同解法。避免永久倍率不断上涨到任何世界都没有压力。

建议先规划少量准备槽，例如在“调查工具”“应急物资”“施工支援”中有限选择。已拥有能力可以改变开局方案，未装备不能隐式全生效；具体预算与价格不在本稿写死。现有三项永久能力的语义与旧档须先保留或显式迁移。

返场例子：已获得森林信号后，主空间提出修复航标/带回残刻的新任务；已完成支线后则出现环境或工程契约。玩家是在熟悉的世界里解决不同问题，岑不再每次重新讲失忆开场。

结算展示“本轮获得什么、为何得到、失去什么、下局可以做什么”。线索/重要选择是永久事实，重复对话不得再次领一次性奖励；常规任务积分是否可重复，由对应任务定义明确。
