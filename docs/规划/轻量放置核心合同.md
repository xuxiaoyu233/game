# 轻量放置核心合同

更新时间：2026-10-11。产品方向已由用户选定：单主活动轻量原型，故事通过短任务接入。**以下是待实现的原型行为合同，不描述当前 v14 已运行行为。** 进度只维护在 [PLAN](../../PLAN.md)，内容编辑见[资料库](../内容资料库/README.md)。

## 单活动与状态职责

首版行为只有采集、制作两类；概念模型为 `CurrentActivity = gather(activityId) | craft(recipeId, remainingBatches) | null`。执行状态还需区分运行/暂停、周期进度与停止原因，P1 类型设计时明确表达，不能仅靠 UI 按钮文本推断。

- 一次只有一个主活动。工具购买和任务提交是同队列原子命令，不是额外持续活动。
- UI 浏览页与选中对象是本地展示状态；权威活动、技能经验、库存、已购工具和已完成任务是规则事实。
- 浏览/选择不会启动、切换或暂停。开始/切换/暂停/恢复均通过唯一 Runtime dispatch，不另存一份 UI 游戏状态。
- 类型允许有限扩展；不建立通用动作图、任意条件脚本或动态插件。新行为再扩合同。

## 周期、切换与消费

| 命令/事件 | 原型语义                                             | 资源与恢复边界                                  |
| --------- | ---------------------------------------------------- | ----------------------------------------------- |
| 开始      | 校验 ID、等级与制作材料/批数，从零周期开始           | 无效命令不替换现有有效活动、不扣料              |
| 暂停      | 停止推进，保留活动与已推进周期                       | 保存暂停事实；离线期间不推进                    |
| 恢复      | 继续同一周期，仍校验当前定义/状态                    | 重启不把已暂停活动隐式恢复                      |
| 切换      | 先按旧活动推进到命令时点，再替换活动；未完成周期清零 | 已完成收益保留；未完成周期没有半份收益或退款    |
| 周期完成  | 检查材料，在同一快照扣输入、给输出/XP、减批数        | 一次成功或整体不发生；经验只随真实完成授予      |
| 材料不足  | 不再开始下一制作周期，记录缺口与停止原因             | 不负库存、不补发失败周期；补齐后需明确恢复/开始 |
| 批数完成  | 记录完成停因，结束继续生产                           | 不借剩余离线时间产生额外批次                    |

首版以周期完成时消费材料，区别于旧 v14 的预留/取消退款合同。旧规则与冻结定义不改成新语义；原型独立校验，没有运行时“把旧 reservedInputs 当新库存”的转换。

暂停保留进度，而切换丢弃未完成周期，是减少误操作与提供明确活动成本的默认设计。按下同一正在运行活动的“开始”不应成为隐式重置；UI 提供暂停/恢复而非重复开始按钮。最终错误码与命令结构在 P1 落地。

## 时间、工具与离线

- domain 只接收调用者注入的时间/时长。在线、离线、命令前推进使用同一规则，不读真实时钟。
- 当前周期的有效时长在周期开始时确定；升级先结算旧规则，下一完整周期再用新倍率。若需持久化周期时长或修订号，在类型/codec 中显式定义并审查版本。
- 长推进与等价分段推进一致；精确覆盖周期边界、技能解锁、暂停/切换、批次耗尽和材料停点，避免浮点差异漏升级或多产一批。
- 离线上限是机械配置，P1/P3 登记具体值与摘要说明；停止后未使用时间不带入恢复后的新活动。
- 该原型没有仓储经营上限，但余额仍须有限、非负并遵守安全数值约束，不能产生 Infinity/NaN。
- 回访摘要由生产/制作/经验账目及确认基线派生。确认摘要不扣物品、不加经验；存档恢复和写失败重试不重复结算。

## 内容与解锁

机械包按技能、物品、活动、配方、工具、任务的有限类型组织，具体文件数量按规模决定。各记录只引用稳定 ID；配方/任务/工具输入输出、周期/XP 和前置在 content，名称和解释在 themes。组装入口验证后注入 runtime/UI；domain 不反向导入 content。

规则与存档的 ID 类型可先采用有限联合，新增条目可能要同步更新类型/验证器。新增采集对象不应复制推进算法；新增“治疗效果”则必须有新规则合同，不能仅新建物品卡。

定义检查要发现：重复 ID、缺失物品/技能/文案引用、无效周期或成本、XP 阈值逆序、不可达解锁和任务自我阻塞。原料→加工→工具/目标允许共享成本，不误报为重复定义。

## 任务与故事

- 功能性维修目标先消费现有修理包，扣料/完成标记/奖励原子提交，重复提交不得再次扣料或领奖。
- 浏览任务或读剧情不改变主活动。首版任务提交不耗持续活动槽；若未来增加任务时长，则需另行决定是否占用主活动。
- 接入故事时只引用批准事实。新对话、任务事实、线索与永久奖励先写入故事资料并评审；维修成功不能自动冒充原始正史救援/取证条件。
- 任务结果由纯规则判定，文案只解释结果。随机事件或运行时 AI 不授予新事实与奖励；首版不加入。
- 故事短任务消费已有经济，不启动另一套临时资源、人口、建筑或研究模型。

## 存档与旧版保护

原型先使用隔离 namespace；具体浏览器 DB/桌面目录在 P1-B 实现前登记。一个模式启动只实例化一个 Runtime，动作与保存仍各单队列；模式选择不能同时启动两个会话争写同档。

不读取/覆盖旧主档、备份或便携目录；原型导入拒绝不同合同的旧档且保留源文件。codec 验证 ID、版本、数值、周期、状态和领取关系。新字段与新含义显式版本化。

保留独占 lease、启动补算候选、保存失败重试、旧 ack 不清新 dirty、导入/退出屏障、坏档保留和恢复备份语义。正式采用显式迁移还是独立新产品档，待玩法冻结后比较并确认；本合同不预先宣布旧资源可无损转换。

## 集中验收

验收按玩家纵向切片推进，详细任务见 PLAN：

- 真新档完成金属→技能解锁→零件→结构件，不以手动设等级替代可达性。
- 用真实规则验证工具优先与目标优先，记录终态库存/XP；指定场景推演不冒充最优或试玩。
- 浏览不改活动；暂停/恢复/切换、升级跨周期、制作停点和任务幂等覆盖。
- 隔离档保存重启、在线/离线与长短推进一致，保存失败可恢复。
- 两种窗口首屏活动/主操作可见；原生托盘/置顶/关闭保存与无引导试玩分别记录。
