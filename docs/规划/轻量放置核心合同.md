## 单活动与技能职责

首轮有采集、制作两类有限行为；概念模型为 CurrentActivity = gather(activityId) | craft(recipeId) | null。技能是经验/解锁轴，活动是正在执行的行为，二者不混同；多个技能可以使用同类推进算法，但必须各有内容与发展职责。

- 一次一个全局主活动；同一活动持续自动重复。工具购买和任务提交为同动作队列的原子命令，不是持续活动。
- 首轮不含跨活动自动队列、自动补料或强制批数。以后增加限量制作时须明确停止目标、恢复与存档语义，不另起推进算法。
- 权威状态显式表达活动、运行/暂停/停止、周期进度与停止原因；不能仅从按钮推断。经验、库存、已购工具和已完成任务是规则事实。
- UI 浏览页/选中卡片是展示状态。浏览不启动/切换/暂停；命令只通过唯一 Runtime.dispatch，不维护第二份 UI 游戏状态。
- 不构建通用动作图、任意效果脚本或动态插件。新行为先扩有限合同。

## 周期、命令与消费

| 命令/事件  | 语义                                         | 原子性与恢复边界                          |
| ---------- | -------------------------------------------- | ----------------------------------------- |
| 开始       | 校验 ID、等级、定义与可用材料，从零周期开始  | 无效命令保留现有有效活动，不扣料          |
| 暂停       | 保留活动与已推进周期，停止时间推进           | 离线不推进，重启不隐式恢复                |
| 恢复       | 校验当前状态与材料，继续保留周期             | 缺料不制造收益；失败不吞已有进度          |
| 切换       | 按旧活动结算到命令时点，再替换；未完周期清零 | 保留已完成收益，无半份收益或虚构退款      |
| 周期完成   | 在同一快照检查/扣输入、给输出和 XP、派生解锁 | 整体成功或整体不发生；失败周期无 XP       |
| 材料不足   | 不开始下一制作周期，保留停止对象并显示缺口   | 不负库存；补齐后仍由玩家明确恢复/开始     |
| 同活动重复 | 成功周期后继续同一活动，新周期重新确定时长   | 不因重复“开始”隐式重置有效活动            |
| 食用       | 校验物品带 consumable 效果且库存 ≥1，扣 1 个 | 单一增益槽：重复食用刷新持续时间，不叠乘  |
| 购买       | 校验报价存在且硬币足够，原子扣硬币给物品     | 即时动作：不占主活动、不给 XP、不产生周期 |

首轮在周期完成时消费材料，与旧 v14 的预留/取消退款合同不同。开始和每个下一周期也检查材料是否可供一次完整制作，避免明知缺料仍显示运行。旧 reservedInputs 与新库存不能混用。

暂停保留进度，切换丢弃未完成周期。规则持久化足以恢复的周期信息，P1 明确错误码/状态结构；概念模型不是现成代码或迁移承诺。

## 消耗品增益与离线上限燃料（schema 3）

- **熟鱼/药水（consumable）**：`consume` 命令扣 1 个并在状态内写入单一增益（`speedMultiplierPermille` 或 `xpMultiplierPermille`，以及 `durationMs`）。重复食用刷新持续时间，不叠乘；没有第二个增益槽。
- **周期时长定格**：增益只在周期开始时影响下一完整周期的时长（与工具升级同时刻语义一致）；进行中的周期不因增益生效/失效而改变，已保存的 `cycleDurationMs` 是权威。
- **增益计时**：在线 tick、命令前推进与离线结算按同一 `creditedMs`（实际结算的游戏时间）递减；到期即从状态移除，不补、不退、不结转。
- **木炭（offlineFuel）**：仅当离开时长超过基础离线上限时，按 `ceil(超限部分/extensionMs)` 从库存扣减（封顶 `maxExtensionMs/extensionMs` 份），扩展本次结算窗口；在线推进与短离線不扣减。扣减写入回执库存增量。
- **回执口径**：`settlementWindowMs` 与“已达离线上限”提示按实际燃料覆盖计算；燃料覆盖的离开时长不报告为封顶。
- **校验**：组装与 codec 校验消耗品倍率范围（速度 500–1000 周期倍率、经验 1001–2000）与正值时长、燃料物品存在且 `maxExtensionMs ≥ extensionMs`、存档 `buffs` 至多一项且倍率与物品定义一致；schema 1/2 存档不得携带 `buffs`。
- **迁移**：content `2.0.0`/schema `2`（及更早）显式加法升级到 `3.0.0`/schema `3`：保留库存/经验/工具/当前活动/回执语义，新物品/技能/工具键零值初始化，`buffs` 初始为空；不可解释 ID 拒绝并保留原文件。

## 展示层派生数值（rates.ts，2026-10-14）

界面显示的速率与预测不是规则，而是对当前状态与版本化内容的**只读投影**，全部实现在 `src/domain/skill-loop/rates.ts`：

- **唯一时长公式**：`getEffectiveCycleMs` = 基础周期 × 工具 × 增益 × 全局加速（permille 三级相乘后 `Math.ceil`）。引擎的 `makeActivityState` 调用同一个函数，因此界面展示的周期永远等于真实结算的周期；`buffActive` 参数保留“进行中的周期不因增益生效/失效而改变”的语义。
- **速率投影**：`getActivityRate` 给出周期、每小时产出/消耗与每小时经验（经验按生效增益换算，与引擎同一取整规则）。
- **升级预测**：`getSkillEtaMs` 用“当前剩余 XP ÷ 每周期经验 × 周期时长”估算，制作活动还要受库存可支撑周期数限制；已达内容上限时返回 `null`，界面显示破折号而不是 0。
- **离线规划**：`getOfflinePlan` 按基础上限与库存燃料算出可覆盖窗口、可完成周期、产出与经验（经验同样按技能上限截断）。
- **不变式**：这些函数是纯读，不写状态、不参与结算、不进入存档、不新增状态源；规则与存档形状完全不变，因此本轮不需要迁移。

## 商店与技能全局效果（content 5.0.0）

- **商店报价（shopOffers）**：固定硬币价格的即时兑换，`purchase` 命令扣硬币给物品；价格不随库存浮动，不产生周期、不给 XP。硬币是普通库存物品，只能由偷窃等活动产出——商店因此是硬币的唯一消耗端。
- **敏捷全局加速**：`SkillLevel.effect.globalSpeedBonusPermille` 描述"达到该等级后全局生效"的周期倍率，取当前等级值（不跨等级累加）；周期倍率 = 工具 × 消耗品增益 × 全局加速，三级 permille 相乘后 `Math.ceil` 取整。进行中的周期仍按开始时定格的时长结算。
- **药水经验增益**：`ConsumableEffect.xpMultiplierPermille` 在周期完成时作用于该周期的 XP，`max(1, round(xpPerCycle × permille / 1000))`，再按技能上限封顶；同一物品与加速可共存或不共存，至少一种效果由校验保证。
- **校验扩展**：技能等级效果范围 1001–2000 permille；商店报价 ID 唯一、物品存在、数量与价格为正；codec 的周期时长校验枚举工具 × 增益 × 可达全局倍率组合，避免误判合法存档。

## 出售与等级效果扩展（content 7.0.0，schema 仍为 3）

新增命令与内容字段**不改变状态形状**：`sell` 与两个新效果字段都只读既有状态（库存/技能 XP），不新增存档键，因此只 bump `contentVersion`（6.0.0 → 7.0.0），不新增 schema，复用 `extendSameSchema` 迁移路径。

- **出售报价（sellOffers）**：`profile.json` 的固定价格表，`sell` 命令原子扣物品给硬币（`updateMaterials` 同一原子路径）：先校验报价存在（否则 `UNKNOWN_SELL_OFFER`）与库存足够（否则 `INSUFFICIENT_RESOURCES`），再整体扣给；数量溢出走 `NUMERIC_LIMIT`。价格固定、可重复兑换、不占主活动、不给 XP。硬币是普通库存物品，出售因此成为硬币的第二个来源（偷窃之外）。
- **反套利不变式**：同一物品若商店同时买卖，出售单价必须严格低于商店买入单价，否则「买入再卖出」可无限造币；由内容校验把关。
- **等级效果扩展**：`SkillLevel.effect` 从单一 `globalSpeedBonusPermille` 扩为三个可选字段，语义与既有全局加速一致——**取当前等级值，不跨等级累加**；要让加成持续生效，内容必须在后续等级重复声明该值：
  - `globalXpBonusPermille`（1001–2000）：周期完成时的技能经验倍率，与消耗品经验倍率相乘（`max(1, round(xp × 消耗品 × 全局 / 1e6))`），公式唯一实现在 `rates.ts`，引擎同源调用；
  - `offlineCapBonusMs`（正整数，≤24h）：离线结算窗口加成，`getOfflineCapMs = min(maxOfflineMs + 各级加成之和, 24h)`；燃料在封顶后的窗口上继续延长（自身 `maxExtensionMs` 上限不变），回执的「已达离线上限」按同一函数计算。
- **展示层**：`rates.ts` 相应导出 `getGlobalXpMultiplier`、`getOfflineCapBonusMs`、`getOfflineCapMs`；`getXpPerCycle` 改吃 definition 并合并消耗品与全局两级倍率，删除引擎内重复的 XP 公式（时长与速率公式只允许存在于 `rates.ts`）。技能详情展示当前等级的全部效果行；离线规划卡在等级加成 >0 时标注来源。
- **迁移**：content `6.0.0`/schema `3` → `7.0.0`/schema `3` 走 `extendSameSchema`：库存/经验/工具/当前活动/回执/增益全部保留，只更新 `contentVersion` 并补齐新内容键（本批无新物品，记录键集不变，`keyset-manifest` 新增 6.0.0 与 7.0.0 两条同指纹条目）。

## 精通系统（content 8.0.0，schema 4）

第三批玩法进化。**本批第一次提升 schema（3 → 4）并新增两个存档键**，因此显式加法迁移：`masteryXp`（每活动）与 `masteryPool`（每技能）在旧档上一律零值初始化，禁止静默重置已有进度；旧 schema 存档携带这两个字段必须被拒绝。

- **精通 XP**：每个完成周期给该活动累计 `max(1, round(活动基础 XP × 精通系数))`，系数随该活动的精通等级提升（系数表集中在 `src/domain/skill-loop/mastery.ts` 并注释来源，不散落在引擎里）。精通等级复用既有技能等级经验曲线（`getLevelFromXp`），不另写一套；达到技能顶阶后精通 XP 停止累计，与技能 XP 封顶语义一致。
- **精通池**：每次获得精通 XP 时，`MASTERY_POOL_SHARE_PERMILLE = 250`（25%）注入该活动所属技能的精通池；池上限 = `MASTERY_POOL_BASE_PER_ACTIVITY × 该技能活动数`（常量集中在 mastery.ts）。池内 XP 只降不升之外的所有变化都来自 `spend-mastery-pool` 命令。
- **检查点（纯派生）**：池填充率达到 `MASTERY_CHECKPOINTS_PERMILLE = [100, 250, 500, 950]`（10%/25%/50%/95%）时对应档位生效；判定是纯函数（池 XP 与上限的比较），**不存「已解锁」状态**，因此把池 XP 消耗到跌回阈值时加成自动失效，读档后永远与事实一致。
- **检查点效果只做两类**：该技能全部活动的周期速度倍率、该技能的经验倍率；取当前最高生效档位的值（不跨档累加），数值表集中在 mastery.ts。最终周期倍率 = 工具 × 消耗品增益 × 全局（敏捷/全局经验另有其表）× 精通，四级相乘后 `Math.ceil`；不变式「最终倍率 ≥ 0.5」由组装校验枚举工具 × 消耗品 × 可达全局和 × 精通档位保证，避免逼近 1 秒周期触发 `NUMERIC_LIMIT`。
- **`spend-mastery-pool` 命令**：`{ kind: 'spend-mastery-pool'; activityId; amount }` 把池 XP 按 1:1 兑成指定活动的精通 XP，原子提交（池扣减与活动入账一起成功或一起不发生）。三类边界必须拒绝并给明确错误码：池余量不足（`INSUFFICIENT_MASTERY_POOL`）、目标活动不是当前已知活动（`UNKNOWN_ACTIVITY`；命令从活动反推所属技能，因此「活动不属于该技能」在结构上不可能出现，由未知活动校验覆盖）、兑换后越过该活动的精通 XP 上限（`MASTERY_POOL_CAP_EXCEEDED`）。命令不占主活动、不给技能 XP。
- **展示层**：周期时长与速率的精通部分只允许出现在 `rates.ts`（`getMasterySpeedMultiplier` / `getMasteryXpMultiplier` / `getOfflinePlan` 之外的新导出），UI 不得自行乘精通倍率；活动行显示该活动的精通等级与进度，技能详情显示精通池填充率与 4 档检查点状态（生效 / 未达成 / 因消耗失效），记录页签增加精通总览。全部派生，零新增第二份状态源。
- **校验与迁移**：`validateSkillLoopDefinition` 允许 schema 4 并枚举倍率组合保证 ≥0.5；codec 对 schema 4 要求两个新字段存在且键集分别是「已知活动 ID / 已知技能 ID」的非负安全整数，schema <4 携带这两个字段即拒绝；同版本补齐（repairSameVersionRecords）对 schema 4 只零值补齐缺失键。content `7.0.0`/schema `3` → `8.0.0`/schema `4` 走显式加法迁移：库存/经验/工具/当前活动/回执/增益全部保留，新键零值初始化；ID 集合不变，`keyset-manifest` 新增 8.0.0 条目（指纹与 7.0.0 相同）。

## 时间、工具与离线

- domain 只接收注入时间/时长，不读时钟。在线、离线、命令前推进使用同一规则。
- 当前周期有效时长在开始时确定；工具升级先结算旧规则，下一完整周期采用新倍率。必要周期时长/修订号在类型与 codec 中显式表达。
- 长推进与等价分段一致，覆盖恰好周期边界、解锁、暂停/切换、材料耗尽与离线上限；避免浮点误差漏升级/多产。
- 工具首轮采用永久提升；P0 候选工具 II 将采掘周期设为基准的 0.8，工具 III 设为基准的 0.65（绝对倍率，不连乘），仅从下一完整采掘周期生效。候选具体成本见[资源与生产链](../内容资料库/资源与生产链.md)。无耐久/维修、装备栏、随机省料等隐含效果。
- 离线上限为机械配置，在 P0 设计、实现时记录。停止后剩余离线时间不转移到其他活动，也不带入未来恢复。
- UI 可基于当前材料/周期估算可制作次数与时间；这是展示预估，不能越过规则授予收益。预估假设明确，停止原因由规则给出。
- 仓库首轮无经营容量，但余额/经验须有限、非负并在安全数值范围内；不能产生 Infinity/NaN。
- P3 将一次启动补算的库存/XP差额、解锁、结束活动和时长写成存档内待确认回执。确认只清回执，不扣物品、不加经验、不重跑结算；失败重试沿用已准备的启动候选，不重复发放。
- 启动恢复的基础补算随 P1 正确落地；P3 的回访展示已实现。Windows 实机保存、托盘与重启验收仍须在正常可写入的桌面环境完成，不能推迟数据安全。

## 内容、发展图与技术资料

七技能生产蓝图已进入运行时：P1 历史快照在 `src/content/skill-prototype-v1.ts`，两档在 `src/content/skill-prototype-v2.ts`（均仅作迁移源），当前 content `3.0.0` 在 `src/content/skill-prototype-v3.ts`；达到当前最高技能门槛后停止 XP，生产继续。当前 profile 仍为 `skill-prototype-v1`，schema `3` 保存待确认回访回执与消耗品增益；更早 schema 均经各自显式迁移升级。资源、成长与命名对照见[资源台账](../内容资料库/资源与生产链.md)、[成长图](../内容资料库/成长与科技.md)及[命名台账](../内容资料库/类目与命名台账.md)。

有限机械定义包括技能、物品、活动、配方、工具、消耗品效果与离线上限燃料，以及接入时的任务。ID、参数、输入输出、等级/工具前置在 content；显示名/说明在 themes。组装入口验证后注入 runtime/UI；domain 不反向导入 content，app 不另存前置真相。

新增同类对象应复用算法；增加精通、互斥研究、装备或战斗则需要相应状态与行为合同。

- **解锁前置图：** 等级/已购工具等事实 → 可用活动/配方/能力。区分 AND/OR 与必要条件，首轮先用明确的有限前置；不能把物品名称当解锁条件。
- **物料图：** 获取 → 加工 → 工具成本/后续配方/已支持的目标。旧材料可跨档使用，不能所有来源只服务一次故事交付。
- **知识/故事图：** 文献依据、技术认知、人物和证据因果，正文在题材选定后另建独立入口。它们不自动成为解锁图，入游戏必须由工程在内容台账中维护包外审核映射。

机械校验覆盖 ID 唯一、引用/文案完整、正周期/有效成本、XP 阈值与前置有效。解锁自锁和不存在的资源来源需报告；实际数值下的新档可达性用规则旅程验证，静态图不能冒充经济或时长证明。图可由同一机械定义派生，不另建可独立编辑的生效树。

## 任务与故事

常规技能成长独立于阅读剧情和委托。首轮生产/工具路线先成立；任务在批准后复用已有物品与事实，不预设“维修目标”是唯一消费端。

- 消费/完成/奖励同一原子命令；重复提交不重复扣料或领奖。
- 浏览任务或读故事不改变主活动，提交首轮不占持续活动槽。
- 故事事实、证据、对话、奖励先评审；名称和题材不能推导规则行为。
- 任务结果由有限纯规则判定；不以随机事件、运行时 AI 或文案授予事实。
- 独立故事库可以解释社会配额/技术史等背景，但配额惩罚、截止时间、工具磨损等机械规则须另行评审。
- 新增叙事不能要求第二套资源、人员、建筑或研究经济。

## 存档与重构

新原型使用隔离 namespace/profile 与显式 codec；目录、当前/目标路径和职责统一在 S0 的[架构说明](../架构说明.md)登记，P1 实现路由与隔离校验，P0 只补新状态/规则版本需求。浏览器主/备份 DB 与独占 lease 同时隔离；桌面复用保存接口，只允许固定、受限 profile，不接受任意路径输入。

P0 给 P1 的状态/codec 要求：新状态以经验、库存、工具等级、当前活动 ID、运行/暂停/停止状态、停止原因和当前周期进度为权威；技能等级与解锁从版本化 content 和 XP 派生，不另存第二份解锁真相。当前周期的生效时长须随周期快照保存，以便工具升级与增益只影响下一完整周期；浏览选择不写进存档。codec 必须校验 profile/schema/content 版本、已知 ID、库存非负及安全范围、经验/时长有限、活动和停止状态相容、增益槽与物品定义一致。新原型分配独立 schema/content 版本，不复用或静默迁移任何旧产品 schema；用户存档保留和 profile 路由按 P1 验收。

当前入口和 Tauri 外壳保持单一，一次一个 Runtime、一条动作队列与一条保存队列。不读取/覆盖旧主档、备份或便携数据；不兼容旧档导入须拒绝并保留源。版本、ID、数值、周期、领取关系均需校验。

允许重构旧 domain/runtime/app 的实现，不要求把新模型嵌进旧人口/岗位状态。必须保留独占、补算候选、失败重试、旧 ack 不清新 dirty、导入/关闭屏障、坏档保留与备份恢复合同。历史 codec/冻结内容仍需能解释旧存档；“拆错结构”不授权删除用户存档。

## 集中验收

阶段完整验收见 PLAN；阶段内部采用必要的定向检查。

- 真新档采集→制作→工具提升，无调试灌 XP。
- 十二技能均真实可达，跨技能物料流闭合（种子↔作物、草药→药水、硬币→商店、敏捷→全局加速）；旧材料继续服务后续生产。
- 浏览不改活动；连续制作、缺料停机、暂停/恢复/切换与跨周期升级正确。
- 熟鱼/药水食用刷新单一增益、周期时长定格、到期移除；木炭只在超限离线时按需扣减并计入回执；商店购买原子扣费且不占主活动。
- 出售原子扣物给硬币，未知报价与库存不足分别报错且不部分扣减；买卖同物时出售单价严格低于买入价；草药学/农业等级效果取当前等级值，离线窗口加成后总窗口不超过 24 小时。
- 隔离档保存重启、长短推进一致、失败可恢复；新增同类内容不复制算法。
- 回访明确所得/解锁/停因/下一步；两窗口与 Windows 实机证据分别记录。

七技能、消耗端与迁移已进入主入口；阶段末 `check`（13 个测试文件/80 项）与浏览器冒烟（4 项）通过。Windows 实机托盘/保存/重启验收仍待正常可写入的桌面环境。验收细目与限制见 [PLAN](../../PLAN.md)。

## 速度口径与 T3–T5 内容（content `10.0.0`，2026-10-16）

**周期倍率是唯一口径。** 引擎把工具、消耗品 `speedMultiplierPermille`、`globalSpeedBonusPermille`、精通速度档四个倍率全部乘在周期时长上（唯一实现 `getEffectiveCycleMs`），因此：

- 速度类字段一律 <1000 表示变快，1000 为基准，>1000 表示变慢；内容校验范围 500–1000（schema ≤3 的冻结快照沿用历史范围，因为它们要按原数值复现旧存档的周期时长）。
- 经验类字段（`xpMultiplierPermille` / `globalXpBonusPermille`）方向不变，>1000 表示更多经验，范围 1001–2000。
- 四者相乘受 0.3 地板约束（原为 0.5）：`validateSkillLoopDefinition` 枚举「工具等级 × 消耗品 × 全局 × 精通」全部组合，低于 0.3 即 `RangeError`。真正的崩溃守卫仍是 `scaled > 0` 与安全整数检查。

**T3–T5 内容合同。** 技能等级上限 Lv30（曲线 `Δ(L→L+1) = round(180 × 1.26^(L-1))` 续写），每档周期与 XP 取蓝图 5.3。新 ID 一律带层后缀，既有 ID 不改；内容必须满足 C4（输入的最早来源等级 ≤ 使用它的活动等级）、C5（每件非消耗品 ≥2 个去处）、C6（自环配方净产出 > 0 且有外部来源）、C7（工具升级材料的层 ≤ 工具等级所属层）。

**迁移合同（8.0.0 → 9.0.0，同 schema 4）。** 加法迁移：库存/经验/工具等级/当前活动/待确认回执/增益/精通全部保留，新键零值初始化。数值重调会让旧存档的两类派生事实失效，迁移按以下口径处理，不做静默重置：

- 增益的倍率按当前内容重读（倍率是内容事实，不是存档事实）；物品不再可食用时该增益丢弃。
- 运行中活动的 `cycleDurationMs` 若在新内容下不可复现，按唯一时长公式重算，部分进度截断到新周期内。
- 待确认回执的 `inventoryDelta` / `skillXpDelta` 按加法语义零值补齐缺失 ID，回执本身保留。

**迁移合同（9.0.0 → 10.0.0，同 schema 4）。** 加法迁移：曲线尾部由蓝图 5.2 续写改为公比 1.04 的等比续写（Lv1–Lv12 原样保留），上限由 563,004 降到 56,548；时代派生由「等级阈值」改为「累计曲线占比」七档（零存档状态，仅影响观感与文案）。冻结定义新增 `src/content/data-v9/` + `skill-prototype-v9.ts`，迁移槽位 p9；旧档经验/工具/增益/回执/精通全部保留，新键零值初始化；键集指纹与 9.0.0 相同（ID 集合未变），仅数值与曲线尾部变化。

错误码 `INVALID_MASTERY_AMOUNT` 表示 `spend-mastery-pool` 的数量非法（不是数值上限溢出）；`INSUFFICIENT_MASTERY_POOL` 与 `MASTERY_POOL_CAP_EXCEEDED` 分别是池不足与越过活动精通上限。
