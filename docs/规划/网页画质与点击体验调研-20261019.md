## 画质诊断：现在的问题不是一个分辨率开关

| 层次 | 当前证据 | 应采取的动作 |
| --- | --- | --- |
| 构图/可见性 | V1复核：已开放地块出界、功能页被86px折叠状态裁住 | 先修F1–F3；相机按真实可用区域和营地包围盒适配，UI不盖主要操作 |
| 画布密度 | main已设置 `autoDensity: true` 与 `resolution: window.devicePixelRatio` | 不重复加DPR开关冒充改善；用实际DPR/尺寸确认backing store，性能不足再按测量处理 |
| 纹理细节 | catalog世界源图宽18–120px，很多物件只有几十像素 | 按最大屏幕显示尺寸×目标DPR决定纹理预算；限制无意义近放大，优先矢量源或真正新原图 |
| 渲染比例 | tile size64，逻辑宽约110.85；农田56px原图显示0.48格，zoom1时约53.2 CSS px | 在DPR2、zoom1.4的假定场景约需149屏幕像素，等于每源像素约2.66屏幕像素。这是静态推导，不是当前手机DPR实测；抗锯齿无法补出缺少的细节 |
| 素材风格 | 当前通用棚屋/明绿土地，与已喜欢的暖光工坊插画不同 | 同一视角/材质/光向/尺度；减少全局染色造成的脏灰，先完成农田与木工坊对照 |
| 成长表现 | 2星程序结构继承D1-C，当前缺同场景清楚对比 | 同建筑/同等级比较1星与2星；等级改变经营布置，星级改主要结构，时代改公共环境，避免三者混淆 |

[Pixi 7官方建议](https://pixijs.com/7.x/guides/production/performance-tips)支持沿用图集和按真实瓶颈优化。当前图集脚本已有2px padding，不能再把“增加padding”写成本轮已完成优化；只有复现边缘串色时才补挤边。非像素画保留linear；不全局改nearest或无限提高渲染DPR。装饰不接点击，按真实状态变化更新，不为自动每秒收入制造满屏特效。

**现成素材还有未利用的矢量源。** 原Kenney包SHA-256复算为 `e4847bf2142e1d808b59bd3039579d21dcce3a871370659598e9cb9ffad1c92c`，与台账一致；包内有 `Vector/hexagonVector_objects.svg` 和 `Vector/hexagonVector_tiles.svg`，解析未发现嵌入位图。两份SVG没有显式根尺寸/单物件语义ID，需要先核对构件边界和现PNG对应关系，**还没有验证可无损替换每张现图**。下一步先做一组正确导出的对照，禁止把小PNG放大保存宣称高清新素材。

## 美术路径比较与样板要求

| 路径 | 收益 | 成本/限制 | 采用决定 |
| --- | --- | --- | --- |
| 同系列Kenney矢量派生 | 来源清楚、现成轮廓可用，可改善边缘与比例 | 仍是简洁矢量风；SVG拆分尚待验证，不能凭清晰度宣称接近插画 | 作为优先验证的复用路径与当前可玩版本基础 |
| 工坊参考的手绘微缩资产 | 更贴近用户已喜欢的材质/暖光与经营氛围 | 需统一镜头、缩小轮廓、透明边缘；AI多次生成易漂移 | 首先只制作农田/木工坊各1星与2星的同场景样板，质量成立再推广 |
| 全面转低分辨率像素画或3D | 可形成另一套鲜明风格 | 要重建现图/UI体系或引入模型/光照管线；不解决现裁切问题 | 当前不采用 |

推荐保持“**简化微缩营地＋清楚轮廓＋木石材质＋局部暖光**”的共同方向，避免一边厚重写实、一边扁平小图。先用更清楚的现成源完成可玩布局，再比较手绘样板的实际价值；不是把矢量与手绘随意混在同一世界。日常场景应读得清，夜景只取暖冷对比，不能让全部建筑长期陷入暗色。

样板放在现有世界与catalog链路中，使用同一镜头、同一地块、同一建筑等级，对照晋升前后。先看农田1/2星、木工坊1/2星，并包含空地、林地作为环境参照；不先生成所有年代×所有等级。

- 资产尺寸由显示预算确定；例如显示到128 CSS px、目标DPR2，就至少需要约256有效纹素宽度，留放大余量时再选512。画布512但主体只占50px仍不合格。
- 地面、建筑、研究附件分层；统一接地点和投影，保持原pointy Grid与逻辑占地，不为新图片改网格或拉伸建筑。
- 生图使用现有样板作参照，透明背景，无人物、文字、UI和未建成的固定建筑；成品看alpha、轮廓、邻格遮挡和缩小表现。AI产物单记来源，不继承Kenney CC0。
- 资源/动作图标继续现有SVG体系，按钮/进度/边框用DOM/CSS；不把中文文字烘进图片，不引入第二manifest。
- 场景之外的山林/水面可作背景氛围；原夜间工坊全景仍是参考/A0内容，不能把插画中固定工坊冒充玩家已建设施。

## 点击、交互与信息的采用落点

当前10秒共享协助是决策型放置节奏。先把可用、等待、成功和升级的感受做好，不为增加点击擅自改协助收益、经验或冷却。

| 玩家动作 | 推荐表现 | 规则与代码落点 |
| --- | --- | --- |
| 悬停/轻点地块 | 桌面轻悬停；点击清楚选中，展示该对象唯一主要操作；手机不依赖hover | 沿WorldScene/原Grid拾取，借鉴Cimulity分层，透明美术不另抢事件 |
| 拖动/双指缩放 | 拖图结束不触发选地/奖励；缩放围绕手势中心；面板滚动不拖地图 | 修Camera现输入边界，参考viewport的局部坐标/双指距离；只保留一个输入所有者 |
| 协助采集 | 明确按钮带可用/剩余冷却；成功短浮字显示实际资源和实际XP，冷却可视 | 复用现命令结果/状态投影；经验封顶不显示虚假+XP；失败不先播放收益 |
| 建设/升级 | 下单前可看目标外观和成本/效果；排单后施工状态，完工才换结构并轻提示 | 复用camp-preview和原订单；当前“材料不足可排供料单”不是一律禁建，预览必须匹配这种资格 |
| 研究/晋升 | 研究完成提示解锁的能力；晋升后再变化主要结构；每项只提示一次 | 从真实研究/建筑状态派生；不把许可完成提前当已经升星 |
| 自动生产/回访 | 自动收入安静更新；阻塞短句和解决入口；回访结果汇总一次 | 不逐tick弹Toast，不重放离线每次收获，不再次领取已入账收益 |
| 切Tab/返回 | 页面独立滚动/折叠状态，保留专注与对象；必要动作始终可达 | 先修F1；五Tab不增加一套游戏实例或日常暂停 |

动作动画以短暂按压、一次浮字/轮廓反馈、完工结构切换为主。约100–180ms按压、300–600ms奖励淡出仅是起始设计参数，待手感调整，不是外部标准或实测结果。`prefers-reduced-motion`下保留文字/状态、减少位移；保存失败继续可见。音效留作后续可选项，不用新音频系统阻塞本批。

触控主要按钮采用44×44 CSS px目标，参考[W3C增强目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)；这是我们选的易点目标，不宣称44px是全部网站AA最低门槛。正文和关键数字按[W3C文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)核对。细节缩进详情，遵循已有[语言合同](../内容资料库/界面语言与信息层级.md)，不新增一份文案规则。
