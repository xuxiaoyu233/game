## 2026-10-07 产品经理专项：缩短页面与收敛信息架构

### 产品判断

主要问题不是单张卡片太高，而是主空间把“看剧情、看结算、选世界、比较契约、买永久能力、读规则”连续放在同一条页面里。世界数量、契约目标、剧情回应和档案线索一增长，纵向长度就继续增长。副本虽然有经营/任务/账目分页，但常驻战况、资源、决策卡和所选页内容仍叠在一起。玩家打开小窗后需要先找“现在要做什么”，这与摸鱼放置场景下快速扫一眼的目的冲突。

现有“简洁”更像装饰/密度开关：它隐藏场景图和部分经济细节，却没有改变主空间的纵向信息结构；关键内容是否隐藏也必须以当前状态验收。不能把减少字号、压缩点击目标或把所有内容做成多层折叠当作解决方案。

外部依据支持先分组和适配，再考虑压缩控件：NN/g建议先显示少量高频选项、让二级内容入口清楚，同时警告过多层级会让用户迷路；微软的窗口布局指南建议随尺寸重排、收起次要元数据、把低频命令移入溢出菜单，并避免单纯缩小所有元素。上述原则是方向，不代表本游戏布局已经过用户测试。

### 目标信息架构

主空间改为三个稳定目的地，默认进入“出发”。页面切换只改变呈现，不新增游戏状态，也不触发游戏规则。

| 目的地 | 第一层必须回答                                                        | 移入二级的位置                             |
| ------ | --------------------------------------------------------------------- | ------------------------------------------ |
| 出发   | 下一段故事目标、推荐/已选世界与契约、本次回归带来的关键变化、进入副本 | 所有世界的完整说明、契约目标与完整奖励比较 |
| 成长   | 永久积分余额、已拥有能力、可兑换能力及其对下一局的效果                | 完整规则说明、详细数值解释                 |
| 档案   | 新线索/新回应未读提示、最近一次结算摘要                               | 完整结算、按世界整理的线索和长剧情         |

“出发”默认只突出一个推荐世界和一个主要操作；世界列表用“选择世界”入口打开同一目的地内的选择面板，不在默认页纵向铺开所有副本。上局结算先显示一条可展开的摘要；兑换与档案不再接在主操作下方。旅程规则改为上下文帮助入口。导航名称和入口可见，不超过两层下钻。

```text
┌──────────────────────────┐
│ 主空间       积分  12    │
│ 出发       成长       档案 │
├──────────────────────────┤
│ 上次带回：旧站线索 · +8分  │
│ 下一目标：确认雪站信号来源 │
│ 推荐副本：灰烬林地         │
│ 基础契约 · 守住两波即可回归 │
│ 木石临时重置 · 可选挑战 +… │
│       [准备并进入]         │
│ 选择其他世界 →             │
└──────────────────────────┘
```

副本保持现有“经营 / 任务 / 账目”三分页，精简的是每页首屏和重复叙述，而不是删掉经营能力：

- 顶部状态压成可扫读的紧凑区：世界/阶段、木石库存与产速、营地生命、下一波；细分统计进入账目。
- 当前最重要的一张“决策卡”靠前：待选事件、危险迎战、基础目标完成后的回归/继续选择优先级最高。高优先级事件不得被简洁模式隐藏，也不得要求玩家滚到底才能处理。
- 常用动作在当前决策区可达。目标、风险、代价、奖励和当前主行动必须相邻；长剧情、已处理事件、完整来源表和玩法说明放到相应分页或档案。
- 每个分页允许自己的内容滚动，但禁止把所有分页内容摊在一条主页面里；避免弹层套弹层或超过两层的深导航。

### 窗口适配与简洁模式

420×600 是日常小窗目标；360×480 是最低宽度/高度压力场景，需在真实 CSS 像素和原生窗口客户区分别记录。默认主题场景不占据副本首屏的主要决策空间；主题图作为主空间视觉点缀，小窗/简洁模式下收为窄横幅或隐藏。页头只保留品牌和窗口操作，主题切换等低频工具放到“更多/设置”；保存状态继续可见但不占整块卡片。

将“简洁”重新定义为“专注视图”：缩短装饰和叙事副文，隐藏不影响当前决策的元数据、重复解释和次要统计；保留目标、资源、生命/危险、选择代价、关键事件与主行动。字号和命中区域保持可读、可点，不通过全局缩放密度换取空间。缩窄窗口时先折叠元数据、改为两行资源条、把详情移到当前页，再减少同时展示的卡片。

### 按钮层级：一条主线、两类局部动作

界面上把按钮明确分成三种用途，并让外观、位置和文案保持一致：

1. **当前流程主行动**：每个游戏状态至多一个实心强调按钮，固定在决策卡/底部操作条中。它随状态变化为“处理事件”“确认迎战”“安全回归”或“结算并离开”。准备计时期间不伪造一个禁用的“等待/迎战”按钮；玩家若想抢时间，显示次级的“提前迎战”。
2. **对象局部动作**：采集按钮只在木/石资源卡内；建造/增建按钮只在对应建筑行内；兑换按钮只在对应永久能力卡内。它们统一用描边或柔和底色，不与当前流程主行动抢强调色。一个动作旁边必须有它操作的对象、结果和代价。
3. **导航/信息命令**：切页、展开说明、看账目、改主题、存档等低频命令用文本按钮、图标加清楚的无障碍名称或“更多”菜单，不套用实心 CTA 样式，也不散落在资源/升级卡中。

主行动不是全局唯一可点击项：经营页仍可采集和建造。规则是“一处只有一个最强视觉焦点”，局部动作始终靠近被操作对象。NN/g 指出相似颜色、形状、尺寸会让人认为操作同级或属于同组；因此把强调色留给流程主行动，局部购买/采集用稳定次级样式，选择组则有清晰的选中态。[视觉相似原则](https://www.nngroup.com/articles/gestalt-similarity/) 与按钮状态指导要求可点击、不可用、悬停、聚焦、按下等状态能被区分；禁用原因也要就近可读。[按钮状态](https://www.nngroup.com/articles/button-states-communicate-interaction/)

### 建筑、资源与永久能力卡片规范

**资源卡**：只服务一种资源，所有数量和动作都在同一块区域：

```text
木头                                    仓储 15 / 120
+0.20 / 秒                    ███░░░░░░░░░░░░
                       [采集木头 +1.5]
```

木头和石头卡的采集按钮位置、尺寸和样式相同；满仓时按钮显示“仓储已满”并解释原因，而不是留一个看不懂的灰按钮。详细累计获得/消耗不混进这两张卡。

**建筑卡**：每行固定阅读顺序为“名称/数量状态 → 本次新增效果 → 成本与缺口 → 动作”。当前建筑目标的进度靠近列表标题或目标项，不另隔一个面板。

```text
伐木营  1 / 4                    当前目标
再建一座：木材产量 +0.10 / 秒
费用 木 12 · 石 6       现有 木 15 · 石 5 · 还差石 1
                              [增建]
```

若机制是单体等级，才显示“升级 Lv.1 → Lv.2”；当前实现是同类型建筑数量递增，文案应使用“建造/增建”，不能用升级词制造错误心智。未解锁显示解锁条件，不画一个无操作价值的购买按钮；达到上限显示“已达上限”。资源不足时保留清楚的成本和“还差什么”，按钮禁用只是防止提交，不能承担解释任务。

**人员预设**：四项放进一个分段选择/单选组，明确“只能选一个”和当前选中项；选项下方显示调度结果，例如“伐木 3 · 采石 1 · 守备 0”。解释防御、产出变化只显示与当前预设相比的差值，长说明折叠。路线策略已固定后收成一行“当前路线：坚守阵地 · 查看/更改条件”，不重复展开所有选项。

**永久能力卡**：所有卡统一显示“能力名 + 已拥有/下一局生效 + 一句实际效果 + 所需积分 + 兑换”。价格和结果不拆到不同位置；积分不足时同一行写“还差 4 分”，已拥有显示效果和“已兑换”，不保留一个像能继续点的按钮。主空间的积分余额固定在成长页页头。

### 流程主行动的状态映射

| 运行状态          | 唯一高强调动作                     | 次级动作                    | 文案必须当场说清                                                |
| ----------------- | ---------------------------------- | --------------------------- | --------------------------------------------------------------- |
| 准备倒计时        | 不放置假按钮；显示倒计时和预计损伤 | “提前迎战 · +奖励”          | 提前会失去多少木/石产出，敌人强度与预估损伤，奖励是否需成功回归 |
| 有待处理事件      | “处理事件”入口，跳转到任务页       | 事件选项在同一事件卡内      | 每个选项的资源成本、人员占用、路线结果；资源不足时指出具体缺口  |
| 怪潮待确认        | “确认迎战第 N 波”                  | 允许时提供检查建设/调度入口 | 当前防御、预计损伤、战后生命；会不会失守                        |
| 基础任务已达成    | “安全回归 · +N 分”                 | “锁定现有战果并继续挑战”    | 哪些奖励已安全锁定、继续的新增奖励和失守损失                    |
| 全部挑战完成/失败 | “结算并回主空间”                   | 查看战报                    | 实际结算与保留/失去的临时进度                                   |

流程主行动不在战斗卡、页尾和弹窗各复制一遍。关键动作需要持续可达时使用一个稳定的决策条；其他页不重复同一命令，而是通过当前状态提示跳转。若待办事件阻止迎战，顶部任务入口必须直接可见，不能只在被禁用的迎战按钮里写一句“去任务页”。

### 主空间卡片与按钮具体排布

- **出发页**只显示一张推荐世界/契约卡和一个“准备并进入”；“选择其他世界”是次级导航。全量世界卡、每个世界各自重复的进入按钮和完整奖励比较放进世界选择页。换契约后，就在同卡更新必做目标、可选目标、基础回归回报与继续挑战收益。
- **成长页**统一列永久能力卡，兑换按钮全部靠右对齐，积分余额固定在页头；已兑换、积分不足、可兑换三种状态有明确差别。不会把故事、世界入口和商店继续接在一个长滚动页底部。
- **档案页**把上次结算做成摘要头（结果、积分、世界、已带回线索），展开后才看完整奖励拆解与长回应；线索按章节分组，未解锁内容不显示剧透文本。
- 全局主题、保存菜单和低频窗口操作从游戏动作区移入统一“更多/设置”入口；保存成功/异常状态仍以短状态常驻，不能把存档操作伪装成游戏进度按钮。

### 分阶段实施与验收

| 阶段                | 交付                                                                           | 完成条件                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 1. 主空间与按钮系统 | 出发/成长/档案导航；世界详情下沉；按钮主次规范、升级/兑换卡状态                | 每个状态只有一个高强调流程动作；建造/增建、成本、效果、缺口同卡；所有世界不再连续铺在出发页                         |
| 2. 副本重排         | 页签上移；压缩战斗状态；资源、人员、目标、建筑形成一条经营工作区；待办事件直达 | 不需滚过战斗区找页签；事件一键可达；采集按钮跟资源、建造按钮跟建筑、选择按钮在互斥组；迎战/回归按状态只显示必要决策 |
| 3. 适配与集中验收   | 主题、间距、状态样式和 420×600/360×480 自适应                                  | 读序明确、焦点可见、无横向溢出/遮挡/双层滚动；资源不足、已满、未解锁、忙碌均有明确状态；浏览器与原生窗口分别记录    |

全量 UI 验收集中在最后一个大阶段完成，避免为了每个间距反复跑全套测试。验收任务至少包括：进入推荐世界、改选契约、采集一种资源、建造可负担建筑、查看具体资源缺口、派遣人员、处理待选事件、提前迎战、回归与兑换永久能力。按钮验收逐一覆盖：可用、资源不足、未解锁、达到上限、运行时忙碌、键盘聚焦。420×600 首屏可回答“在哪个世界、当前目标是什么、下一危险/主行动是什么”；不需要滚过战斗区才能找分页；所有成本按钮都有动作动词和对象名称。360×480 可允许当前工作区滚动，但不得让关键事件入口或当前主决策消失。建议用 5 位目标用户做一次观察式走查；至少 4 位能在 5 秒内说出当前目标和下一动作，再据此调优，而非把这一比例当成已验证结果。

重构优先改呈现、导航和 UI 偏好；游戏命令仍统一通过 `GameRuntime.dispatch`。不改存档协议、不搬运机械规则、不把剧情/主题文案写入存档，也不为改版引入新的同步服务。完成主空间和副本两个大阶段后再执行本轮 UI 集中验收；真实 Windows 置顶/收起仍另做原生验收。

## 现状与目标

已查看现有原型的 420 宽完整截图。战斗、资源图表、调度、任务、全部建筑按纵向堆叠，完整内容超过三屏。问题主要是决定一件事要跨面板寻找信息，而不只缺少图表或不够漂亮。

新界面让玩家每次回看先回答：本局要做什么、目前缺什么、下一危险是什么、现在最合适的操作有哪些。详细图表与长剧情仍可访问，常用调度和建设不能埋在长页末尾。

采用[NN/G 的渐进披露原则](https://www.nngroup.com/articles/progressive-disclosure/)：常用信息留在第一层，较少用的详情在可发现的二级入口。本文在该原则上的具体布局是我方方案，不能只因引用该文就宣称界面已经验证。

## 统一导航

产品只保留两个大场景：主空间和当前副本；主空间内部用三个同级目的地，副本内部用三个工作页。不要把主空间的世界、兑换、档案继续做成同一页里的三个长区块。

| 场景/入口       | 第一层内容                                        | 下一级内容                     |
| --------------- | ------------------------------------------------- | ------------------------------ |
| 主空间 · 出发   | 最近带回摘要、下一目标、推荐世界/契约、准备并进入 | 选择其他世界、改选完整契约条件 |
| 主空间 · 成长   | 永久积分、能力效果与可兑换状态                    | 具体兑换规则/帮助              |
| 主空间 · 档案   | 未读提示、最近结算摘要                            | 完整战报、线索和长剧情         |
| 当前副本 · 经营 | 资源、人员、建设和局内策略                        | 逐项建筑说明、建设计划详情     |
| 当前副本 · 任务 | 必做/可选目标、待处理事件、派队项目、发现         | 已处理事件与完整故事说明       |
| 当前副本 · 账目 | 本轮木/石收入、消耗和来源                         | 详细统计范围说明               |

主空间三个入口的名称应固定为“出发 / 成长 / 档案”；远征三个入口固定为“经营 / 任务 / 账目”。选中状态与未读/待办数量可见。存档、主题、置顶等窗口功能不混进游戏动作组；保存状态常驻为轻量状态提示。

## S-03–07：关键节点低保真稿

沿用 S-02 的紧凑状态条与固定页签，只替换当前工作页和状态决策。下列是阅读顺序和信息结构，不代表像素稿；省略的常驻条不是取消。金额、损伤与时间统一取实际快照，不能硬编码示例值。

### S-03：事件待选

```text
┌─────────────────────────────────────┐
│ 任务 1/3 │ 木… 石… │ 事件等待选择    │
├─────────────────────────────────────┤
│ 桥梁损毁：旧记录在河岸对面           │
│ 本节点暂停自动推进；仍可查看任务物资 │
│ 修桥：木材成本 + 占用队员 → 开调查路 │
│ 绕行：不付木材 → 下一阶段再调查     │
│ 拆桥：得到材料 → 本局关闭这条调查路 │
│ [选中方案的完整代价与结果]           │
├─────────────────────────────────────┤
│ [确认该选择]                         │
└─────────────────────────────────────┘
```

映射 G-13/14、U-04/09/10。三个方案为候选，不预先保证当前有足够资源；不足方案给出具体缺口。事件来源、已知事实与角色推测分别表述。确认前不扣费，失败后保持原事件和原选择可恢复。候选通用事件建议在待选时停于节点；哪些经营动作仍开放须由玩法定案，不由界面放行。

```text
┌─────────────────────────────────────┐
│ 基础任务未完成 │ 生命… │ 第二波     │
├─────────────────────────────────────┤

│ 临时额外奖励…；成功回归才到账       │
├─────────────────────────────────────┤
│ 调度/建设作为当前页的次级入口         │

└─────────────────────────────────────┘
```

映射 G-15/16/18、U-03/06/07/11。同一时刻只显示与阶段匹配的迎战按钮：准备倒计时阶段可选“提前迎战”，到点阶段是“确认迎战”。不额外提供没有游戏效果的“继续准备”。可能失守用文字和数值说明，不能只涂红；外出项目的处理必须按规则说明。

### S-05：基本目标完成与追加选择

```text
┌─────────────────────────────────────┐
│ 基础任务完成 │ 可回归 │ 生命/库存… │
├─────────────────────────────────────┤
│ 当前回归：基本奖励… + 已获得证据…   │
│ 尚未完成：纪念工程 / 原始记录调查   │
│ 追加目标：成本… 人力… 风险…        │
│ 继续若失败：按选定损失方案明确列出   │
├─────────────────────────────────────┤
│ [安全回归 · +N分]                    │
│ [锁定现有战果并继续挑战]（次级）     │
└─────────────────────────────────────┘
```

映射 G-19/20/21/23、U-01/12/13。“安全回归”是已达成基础目标后的主行动；锁定奖励并继续挑战是风险路线，必须同卡对比新增奖励和失守损失，不作为同级的两个实心按钮。点击回归时显示结算处理中，真正提交后才进入主空间结算卡。挑战全部完成时移除继续挑战动作。

### S-06：失败与重试动机

```text
┌─────────────────────────────────────┐
│ 连接中断 │ 营地失守                 │
├─────────────────────────────────────┤
│ 直接原因：该节点压力与有效防守对比   │
│ 本轮失去：未归档证据 / 临时成果…    │
│ 保留：已有永久积分、能力与旧档案     │
│ 下次建议：项目占用/防线缺口的事实   │
│ [查看战报]                           │
├─────────────────────────────────────┤
│ [结束旅程，回到主空间]               │
└─────────────────────────────────────┘
```

映射 G-18/22/26、U-04/13/15。建议基于事实，不许生成“多点击即可获胜”的空泛结论。没有未完成基础奖励实际保留事实时，不显示保底到账。重试不重播首次开场；可以从主空间换准备再进世界，不能在失败快照继续生产。

### S-07：保存异常与恢复

```text
┌─────────────────────────────────────┐
│ 进度未确认保存 │ 出错动作：…        │
├─────────────────────────────────────┤
│ 当前运行时保留状态：…               │
│ 这次迎战/回归尚未生效                │
│ [重试保存] [导出保留的进度]          │
│ 恢复备份/导入：先核对版本与内容      │
│ 技术错误详情可展开                   │
├─────────────────────────────────────┤
│ 恢复成功前保持现有保存屏障           │
└─────────────────────────────────────┘
```

映射 G-30、U-19/20。需要区分“关键动作未提交”与“此前推进已保留但尚未写盘”，说明实际保存的快照，不声称自动回滚全部时间。坏档加载失败时改为加载恢复页，不能显示不存在的资源或用“新开一局”覆盖原档。重试和导出遵循已有运行时接口；具体可用入口由失败类型决定。

### 尺寸收缩与交互约束

420×600 优先在常驻条下留一个完整决策卡；360×480 时减少次要统计、取消图表常驻、资源条改两行，当前卡局部滚动。目标摘要、风险提示与主行动保留。规则未读完的选项能返回查看，键盘焦点与错误提示不会因刷新自动跳走。字号/DPI、原生标题栏、窗口实际尺寸和鼠标键盘可用性仍待以后 UI 验证，本次未作通过声明。

七种状态稿与一局/失败/返场的映射见[联合评审走查](联合评审走查.md)。

| -------------------------- | --------------------------- | ------------------------------------- | -------------------------------------------- |

| 何时够建目标？             | 预算与可达时间              | 缺口÷当前有效产出，考虑阶段/容量/锁定 | 经营页                                       |

## 状态与主行动

| 状态          | 常驻信息                       | 主行动                     | 次行动与风险                              |
| ------------- | ------------------------------ | -------------------------- | ----------------------------------------- |
| 主空间待准备  | 下个目标、世界规则、永久余额   | 选择并进入世界             | 兑换、档案、换世界                        |
| 准备中        | 缺口、有效人力、下一节点、资源 | 当前经营决策或查看早战对比 | 手采补缺口、探索、建设                    |
| 事件待选      | 事件缘由、代价、可见后果       | 选择结果                   | 查看任务/资源，时间是否停于该节点清楚标明 |
| 危险待确认    | 预计损耗、仍能做的建设/调度    | 确认迎战/处理环境          | 撤离；不在离开桌面后自动点确认            |
| 基础可回归    | 到账预估、追加目标、继续风险   | 回归                       | 追加目标与继续挑战                        |
| 挑战完成      | 已完成目标和实际临时收益       | 回归结算                   | 查看战报与证据                            |
| 失败          | 原因、本轮损失、已有成长保留   | 结束旅程                   | 导出/查看战报；不再显示可采集/分配按钮    |
| 保存/恢复异常 | 出错动作、保留进度、可恢复途径 | 重试或恢复/导出            | 不显示虚假的成功；原游戏状态保持          |

危险确认是否需要二次弹层按风险划分：普通待战已有充分预览时可直接确认；提前迎战首次、会失守或会放弃重要项目时建议显示对比确认。不要每次操作都弹“确定吗”。

## 对话如何兼容桌面节奏

任务目的采用一句话，结果回应两三句可折叠，完整故事在档案。首次必要教学由当前目标和可操作任务承载，不是短暂弹泡。新线索用持久未读标记提示，不强制滚动到底或自动播放声音。

自由文本 AI 对话只在以后另立范围：可解释已知规则和当前角色视角；有实际后果的行动需回到合法选项。当前不计划在这次界面重构顺带接模型接口。

## 设计与评审顺序

1. 用 G 能力和状态表列出第一屏必须显示的事实，不先改配色。
2. 为主空间及副本准备、事件、待战、可回归、失败、保存异常分别画低保真稿。
3. 串联“选契约→自动发展→人员占用→事件→早战→回归→新目标”的点击路径；同时走普通和零手采路线。
4. 对 420×600 和 360×480 检查第一屏、局部滚动、底部动作遮挡、缩放与长文案；旧版/候选截图作对照。
5. 根据真实交互评审再调整组件责任、信息密度和文案；任何运行时事实继续经统一 dispatch 派发。

后续可以进一步拆分 AppShell、StatusStrip、ObjectiveSummary、DecisionBar、CampView、MissionView、AnalyticsView、HubView。当前仍由既有 React 面板组织；派生数据从统一运行时快照获得，导航和折叠状态属于 UI 偏好，不能制造第二套游戏状态。
