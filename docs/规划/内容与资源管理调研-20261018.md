## 资源、图表、状态放在哪里

具体目标目录与引用合同见[美术规格](../设计/沙盘美术接入规格.md)，模块责任见[架构说明](../架构说明.md)。核心分为四层：

1. 原始来源：作者包/源图/生成记录与许可，不作为运行时 URL。
2. 运行素材：挑选好的世界 PNG、小 SVG、概览图；图集由既有工具生成。
3. 展示绑定：稳定 asset key → 图集帧或 Vite URL，并记录数字锚点、比例、状态、采样及归属。React/Pixi 共用引用，不在组件里拼路径。
4. 玩家状态：建筑等级/研究完成/时代/已开放区域，沿用同一 GameState 和保存链。图片路径、CSS token、节点布局不入玩法存档。

科技连线、资源图表由数据生成，不为每种科技状态保存一张 PNG。面板选中/悬浮/展开状态留内存；既有音量/语言偏好可沿 GameOptions 管理，不再新建玩家进度仓库。

## 成长、科技与数值推荐

推荐首版**没有玩家总经验/技能经验**：

- 建筑等级Lv1–20，复用原施工/批量目标；1星上限Lv10，晋升保持Lv10后继续到Lv20。星级等同阶级，不增加独立阶级条。这取代此前Lv1–3建议。
- 六研究各一次，开拓三项建立生产链，工坊三项开放本地晋升许可；不叠科技经验/计时器。
- 两时代，开拓三研究及建设门槛达成后主动进入工坊，保留营地/资源；工坊开启晋升研究，不用2星反卡时代。
- 进度条分别明确“施工”“材料是否齐备”“时代条件”，不能把材料条标为经验。

替代方案是生产获得建筑熟练度/营地经验，但会新增授予条件、离线经验、重复建造/拆除刷取与版本迁移问题；待发展循环确实需要长期成长时再设计，不提前套 99/100 级经验表。

研究优先复用 `IUpgradeDefinition.requireResources` 与 `GameState.unlockedUpgrades`，六项采用稳定自有ID；这是材料研究，避免直接走Science支付与自动批量补前置。建筑仍在tiles，新增最小星级事实，等级沿原字段。研究只有一个完成集合，基础引擎标记如确需兼容，只能是其投影。

时代必须有唯一机械来源（扩展当前 GameState，而不是另起 store/存档）。原引擎按科技列推时代的查询对本 profile 做一处映射；自有 UI 不再读取布局列数推时代。运行时不得通过改节点坐标触发时代变化。

科技字段、成长/晋升成本与土地清单统一见[首版规格](发展沙盘首版规格.md)。成本是设计起点，未做平衡验证，D1采用值从唯一配置导出。原成本为10×1.5^level；自有profile建议将增长因子适配为1.18，保留×10定义换算，UI不再乘一次。等级越多越需同步检查容量/人力，不能只增加上限。

**本地代码事实**：`GameTicker.ts` 在正常速度下每1000ms调用 `tickEverySecond`；`ClientUpdate.tsx` 与原内核执行生产，离线复用同路径。`IntraTickCache.getBuildingIO` 采用配方×等级×capacity×modifier，当前路径没有把产出统一截为整数；`produceResources` 保留数值加入原库存。因此0.2/s等小数起点可沿原路径适配，仍待D1真实运行验证。资源刷新动画不是授予收益的定时器。

`getWorkersFor` 汇总输入/输出后除以worker效率并向上取整；`Update.ts` 人力不足时记录 `NotEnoughWorkers` 并停止该设施，并不是按“实配/需求”线性打折。`Headquarter` 已定义 Worker 10；`getAvailableWorkers` 还受既有幸福系数和运输占用影响。新UI须区分总供给、生产占用、运输占用和空闲，不可仅隐藏上游界面后宣称劳力机制不存在。低需求建筑的“-25%人力”可能因取整没有收益，需实际换算后决定。

`GameState.city`、单一tiles与getGrid缓存表明当前不是多城并行引擎。此前曾据此推荐同世界分区视图；用户最新明确偏好单营地扩建，已撤回该产品建议。现采用同一连续地图相邻扩地，无独立营地/分区标签，正好复用原Grid/运输/离线。当前未发现自有天气/污染系统，均为新增规则，不因引擎限制反过来替用户决定产品。

调研时点的差距保留为历史依据：A/B后来已接图集、采集、四技能、五建筑与前三研究；后三研究、星级/时代仍待C。模块/实际结果以最新架构和[B交付](../证据/发展沙盘/D1/B/README.md)为准。
