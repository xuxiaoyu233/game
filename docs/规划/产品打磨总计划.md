## 产品定位与目标

面向工作间隙使用电脑小窗口的单人玩家。建议定位为“世界契约驱动的放置经营冒险”：自动经营维持进度，少量节点选择决定风险与收益，成功回归把临时成果转化为永久成长和故事证据。

产品特色要落在可观察的行为上：玩家进入一个世界就知道本局特别规则；有不止一条合理的资源投入路线；完成基本目标可以回归；额外目标需要真正付出代价；回来以后人物、档案或下一次准备发生变化。

“无限流”分成三件事：跨世界的共同主线、每个世界自己的任务机制、同世界的返场变化。长期内容来自持续制作世界与任务组合，不能用无限涨价或无限重复序章替代。

当前规则允许人员随时免费改为守备。由规则推断，可能形成“先全力生产，开战前切守备”的固定操作。这是要验证的设计风险，尚无大样本试玩数据。新路线也需确认能改变建设和任务选择，不能仅增加两个倍率按钮。

本轮隔离推演已确认一条零手采、只建避难棚的 72 秒/28 分回归路线；四轮可积累超过三项永久能力总价的积分。两个森林契约没有不同基础义务，外派守备在等待期间缺少实际防御代价。将这些作为 B 阶段对照，不能以“配置化已接入”推定策略深度已成立。

## 产品循环

```mermaid
flowchart LR
  H[主空间：上次变化与下一目标] --> C[选择世界、契约与有限准备]
  C --> A[自动经营：分配人力与建设]
  A --> D[节点决策：探索、事件、挑战]
  D --> A
  D --> R[基础完成：回归或追加目标]
  R --> S[结算：临时清空、永久与证据归档]
  S --> H
```

提出待验证的节奏目标：首次进入 30 秒内理解基本任务，2 分钟内出现第一个影响路线的选择；单次回看可在 10–30 秒内完成决策；一局先按 8–15 分钟的可推进时间设计。玩家离开时不会被强迫连续处理危险；上述时间是设计目标，不是现有实测结果。

## 产品验证与判断标准

产品计划保留规则推演与玩家试玩两类验收。本轮已有小规模可复现规则诊断和 UI 检查；尚无平衡穷举、三轮玩家试玩或长期体验结果。

| 要验证的假设                   | 以后如何测                                          | 初始判断线                                                           |
| ------------------------------ | --------------------------------------------------- | -------------------------------------------------------------------- |
| 自动经营替代重复点击仍有参与感 | 零手采局与主动参与局比较，记录做了哪些选择          | 零手采能完成基础任务；主动参与改善路线或收益，不成为唯一通路         |
| 提前开战有取舍                 | 在不同库存、生命、任务、人力约束下比较早战/等候结果 | 不同局面有不同合理选择；避免永远越早越好或永远不能早战               |
| 回归带来新目标                 | 连续三轮记录主空间变化与再入理由                    | 至少有新证据、机制、任务或准备选择；不只积分上涨                     |
| 第一屏支持决策                 | 新玩家看低保真稿后复述目标、缺口、风险与下一步      | 建议 5 人中至少 4 人能在 10 秒内正确说明核心信息；小样本只作定性检查 |
| 世界确实不同                   | 把世界名称和背景隐藏，描述各局决策                  | 仍能根据资源竞争、目标和风险分辨世界                                 |

暂不启用后台遥测；后续试玩先用本地、手动记录。长期耐玩不在本次规划中宣称已经成立。

## 文档维护规则

产品经理维护问题、优先级、状态与验收；叙事设计维护线索和人物因果；系统设计维护任务与成本；交互设计维护界面状态；工程只在实施阶段映射模块和兼容。这里是工作职责划分，本轮没有启动额外代理或外部服务。

每次评审更新决策表和关联条目。条目状态依次为“候选→待评审→确认→实现中→已实现→已验收”，自动检查与用户体验验收分列。“已写候选代码”不自动推进为“确认”。

本次用户明确授权启动首个实施切片。后续新世界、数值再平衡、完整音效美术和发布仍按各自阶段规划，不从这一授权中推断为已完成。
