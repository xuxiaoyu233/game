## 产品主张与玩家循环

玩家把同一个营地经营成不断扩张的文明聚落：开局能点击获得少量材料，建起设施后持续自动生产，通过等级/升星、研究和选址作出发展决定。中后期点击主要用于配置与选择，保留主动协助但不靠连点维持经济。人口以聚合数据表达，新增食物/住房/健康需求，日常自动管理；不做逐人搬运、强制转生清图或每日领取任务墙。最新[生存合同](生存经营与事件体系.md)补齐季节/自然死亡/重大事件与路线增益。

```mermaid
flowchart LR
    A[点击协助获得少量基础材料] --> B[选择空地并建设]
    B --> C[自动生产与加工]
    C --> D[判断材料 空间 劳力与运输瓶颈]
    D --> E[升级 升星 研究或调整生产]
    E --> F[同营地扩地与时代进步]
    F --> C
    C --> G[离线按同规则结算]
    G --> D
    F --> H[后续环境准备与可选防御]
    H --> D
```

## 点击与获取：明确三种操作

| 方案                         | 收益与代价                                                            | 取舍                              |
| ---------------------------- | --------------------------------------------------------------------- | --------------------------------- |
| 纯自动、只点建设             | 实现简单，但开局缺少直接获取的反馈                                    | 按本次用户问题补主动协助。        |
| 无限连点直接产料             | 反馈密，但容易让最优玩法变成长时间连点，建筑自动收益失去意义          | 不作为主经济。                    |
| 有限节奏的点击协助＋自动生产 | 保留即时入库，又能将主要成长转向设施/决策；需要明确共享节奏和保存合同 | 采用为首轮建议，数值/手感待试玩。 |

| 操作     | 玩家点击                                                    | 获得与反馈                                     | 边界                                                                    |
| -------- | ----------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------- |
| 直接采集 | 选林缘/石堆，在上下文面板点“采集”；农田建成后可点“协助收成” | 即时少量木/石/粮，地块一次轻反馈、库存真实增加 | 可选、全营地共享节奏限制，具体合同只见首版规格；不产板材/工具等加工品。 |
| 发展投资 | 点空地建设，或点设施升级/晋升/研究                          | 未来每秒产能、容量或功能提升，预览现在→之后    | 材料与合法性经同一命令检查，普通施工与即时付款分开。                    |
| 经营决策 | 选择训练目标、后期配给/生产模式与路线增益                   | 材料分配、稳定性、环境成本与目标推进改变       | 不将每次操作都伪装成“领资源”；不为已有收益重复领奖。                    |

原“点击只负责建设、完全不设手动获取”的限制按本次用户问题修订为**可选点击协助＋自动生产主力**。自动粮食无需逐田收获；离线结算无需点击领取；手动资源和自动资源进入同一库存，飘字不负责发钱。

首轮操作顺序：看见营地与下一个可做目标→点林缘采集并看库存变化→点空地建设农田→看到施工与自动增粮→建立木石/板材链→研究与升级→进入工坊并晋升→扩地、重载和回访接续。初始资源必须足够建基础链，不强迫点击补缺口；实际第一分钟体验由D1试玩记录，不宣称该顺序已经验证。

## 经济用途与节奏必须一并设计

| 层次                 | 材料去向/玩法目的                                       | 防止的问题                                                                    |
| -------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 基础粮木石           | 初始建设、升级、研究、扩地与晋升；粮食作为建设/研究补给 | C1新增原粮→口粮与人口自动消耗，提供初始缓冲和应急路径；不强制战斗或连点续命。 |
| 板材/工具/钢等加工品 | 后续建筑、旧设施改造、公共建设目标与可选防线            | 新材料必须有可达来源和实际用途，不连续增加只用一次的资源图标。                |
| 燃料/电力            | 对应已启用模式的持续消耗/能力约束                       | 高产有可解释成本；可以保留较低效旧模式，不因燃料短缺清除旧设施。              |
| 阶段目标             | 完成一项营地建设/改造后给明确场景变化或权限             | 不为延长时长设置无限捐赠箱、重复签到或反复领奖。                              |
| 内容末端             | 可继续经营/优化，清楚显示当前可用内容已达上限           | 不用无限科技/99级或强制转生冒充新玩法。                                       |

粮食在长线中的稳定用途仍需随每个内容包核查，尤其科技/晋升完成后不能只堆一座无用途的高等级农田。按C1接完整可达的食物/饮水/住房/劳力闭环，不再用只增研究费用回避用户的人口需求。原材料保持用于新链成本；回收不得形成无消耗正收益闭环。

节奏目标分层：一次有效点击或完成立即有真实反馈，前几分钟建立基础自动产线，约5–15分钟出现加工/升级/仓储取舍，工坊时代初目标约30–60分钟；后续晋升/时代时长先收真实体验再冻结。上述是调参目标，不是已测耗时。每个时代优先新增1–2种决策机制，其余节点围绕该机制扩展；不在一批同时开天气、电力、污染与战斗。

## 六个原分支＋民生扩展：长期内容模型

| 分支ID        | 技术路线                                           | 改变的决定                                       |
| ------------- | -------------------------------------------------- | ------------------------------------------------ |
| `agriculture` | 灌溉→轮作→土壤/抗寒→机械农业→受控环境→精准农业     | 同一农田如何升级、稳定产出与承受环境限制。       |
| `production`  | 木材加工→标准工具→勘探/铁工具→煤钢→电驱→回收       | 哪条链先投料，旧资源如何持续有用途。             |
| `logistics`   | 仓储组织→模块仓储→运输/加固→模块建设→配电→智能仓储 | 空间、容量、运输与能源分配如何支撑发展。         |
| `automation`  | 人工配置→机械作业→库存目标→自动物流→需求响应       | 用有限设置减少重复操作，保留效率/成本取舍。      |
| `environment` | 中性环境→预报→治理→发电/储能/清洁供给→生态修复     | 如何准备、供能和控制外部成本。                   |
| `civic`       | 住房/公共炊事/饮水→保鲜→保温→公共卫生              | 食物、床位、人口与健康如何持续支撑发展。         |
| `defense`     | 边界工事→加固防线→预警联动                         | 防御自愿开启；战斗节点不成为经济时代的必经条件。 |

时代候选为开拓、工坊、金属、机械、电气、生态精密。当前两时代是第一批内容边界；不是产品终点。等级/星级上限从内容表读取，前四阶段1–4星/10–40级保留起点，电气/生态阶段可评估5–6星/50–60级，不写死四时代、四星或40级为全产品上限。后两时代仅为候选，不预建电网/储能/回收状态和整套素材。

原目录下面共36个命名节点，另加[生存合同](生存经营与事件体系.md)六个民生候选，合计42。民生候选为basic-shelter/communal-kitchen/clean-water/food-preservation/insulated-housing/public-health，按C1–C3分批冻结，尚未装入游戏。原36项为：首批6项＋金属8项＋机械8项＋电气8项＋生态6项。数量是完整路线的内容骨架，后续可按实际体验合并/替换；不是一次开发36项的承诺。前置ID均为AND；不含时代门槛、建筑/材料条件，实施前需将那些条件一并落入唯一规则表。`—`表示无研究前置，不表示无需材料和设施。

### 科技扩展的统一规则

1. 每个节点至少改变一个可说明的决定：开放建筑/配方/晋升/模式/运输能力/抗性/控制能力；纯增产节点要与成本和布局取舍相连，不为凑数量重复+5%。
2. 材料研究仍是默认；不因节点多就增加第二科研币、科学家居民、研究经验或独立研究时钟。后期若确需实验室/研究点，在该批比较后再冻结。
3. 研究前置、时代门槛、建筑/材料条件分开定义，UI只投影；不以科技布局坐标或名称判断解锁。未来节点只有进入对应时代/模块后才能购买。
4. 时代入场只能依赖当前已可生产/研究的东西。例：工坊入场不要求2星；金属入场不要求金属时代才开放的Tool；机械入场不要求机械时代才开放的Steel。未来建议门槛用当前核心建设/研究/材料，不强制100%研究，更不要求防御分支全通。
5. 研究开放本地改造许可与本地付费改造分开；直接全局效果只发一次。星级、工作模式、研究完成各自职责清楚，避免同一能力重复收费/叠加。
6. 生产定义/成本仍归Config；目录只引用稳定ID与前置，效果使用有限类型（解锁、modifier、容量、模式等），不把任意函数塞进内容JSON。
7. 新时代引入新材料前做实际依赖闭包：来源→加工→仓储可支付→解锁→用途；没有来源或下一时代材料的成本不能发布。Power等设施能力不自动当可扣的实体库存。
8. 一项内容包包含机械定义/版本接续、展示绑定、真实目标与缺项；纯美术替换不改变机械存档。新材料进分组资源面板，不把顶栏无限加宽。

## 场景美术如何随完整产品扩展

同一营地、统一微缩画法。等级添少量细节段，星级改主体结构，研究添功能部件，时代改公共风貌；天气/污染/供能按真实状态加覆盖或动效。即使进入电气时代，未改造的旧仓库仍保留旧结构，不能全图自动换成现代建筑。

首批仍按五建筑两星级共10主结构预算，复用已备素材；后续每次只为采用的新建筑/星级补小样与缺项。六时代不等于六套画风，不先制作全部星级×等级×时代的全排列。具体目录/原图/图集/key/许可仍由美术规格统一管理。
