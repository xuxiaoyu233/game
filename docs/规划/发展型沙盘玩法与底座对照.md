# 发展型沙盘玩法与底座对照

日期：2026-10-17。本文记录调研依据与设计建议，不另维护实施阶段；当前进度只在根目录 `PLAN.md`。

> 本文保留 2026-10-17 初次调研与比较过程。当前实施行为以[首版规格](发展沙盘首版规格.md)为准；首版已将早期“工具”收敛为“板材”，不按本文草案额外加入工具制作、四个时代或邻接系统。

> 2026-10-18 状态校准：D0 与 D0-R 已完成约定本地浏览器验收，数据阻塞已收口，见[最新验收与全局评估](../证据/发展沙盘/D0-R/收口验收与全局评估-20261017.md)。下文“未运行/待验证”仅描述初次调研范围，不能覆盖后续验收。当前采用 CivIdle，D1 未实施；内容、UI素材、科技/等级及地图管理按[10-18 调研](内容与资源管理调研-20261018.md)与最新规格，执行顺序只看根 PLAN。

## 已确定的产品要求

- 用户选择基于现成开源项目改造，避免把生产、科技、地图等通用系统全部从零实现。
- 放置发展为主体：新建农田等建筑，扩建和升级后对应区域有可见变化；时代推进带来整个沙盘的变化与扩展。
- 不呈现具体居民，不做逐人需求、职业、寻路和搬运模拟。活动感来自作物、风车、水流、烟气与灯光等环境表现。
- 先完成发展循环，再做 PvE、敌人时代变化与攻击波摘要。
- 用户认可夜间矿场/工坊图的美术方向；该图目前是概念与样机背景，尚不是可动态建造的分层沙盘资产。

### CivIdle 的源码依据

核对版本：`e15fe039ed5c0794df05e52258bc9663761a140a`。

- [BuildingDefinitions.ts](https://github.com/fishpondstudio/CivIdle/blob/e15fe039ed5c0794df05e52258bc9663761a140a/shared/definitions/BuildingDefinitions.ts)：建筑具备 `input`、`output`、`construction`、`deposit` 等定义；已见 `WheatFarm`、`LoggingCamp`、`StoneQuarry`、`Warehouse`。可复用建筑生产与成本表达。
- [Tile.ts](https://github.com/fishpondstudio/CivIdle/blob/e15fe039ed5c0794df05e52258bc9663761a140a/shared/logic/Tile.ts)：地块有探索、矿藏与建筑；建筑记录等级、目标等级、库存、建造/升级/完成状态与优先级。可复用地块和建筑升级模型。
- [TechDefinitions.ts](https://github.com/fishpondstudio/CivIdle/blob/e15fe039ed5c0794df05e52258bc9663761a140a/shared/definitions/TechDefinitions.ts)：有石器、青铜、铁器、古典、中世纪、文艺复兴、工业等时代；农业、石器、伐木科技分别解锁相关建筑。可复用科技与时代组织。
- [TickLogic.ts](https://github.com/fishpondstudio/CivIdle/blob/e15fe039ed5c0794df05e52258bc9663761a140a/shared/logic/TickLogic.ts)：存在产出、储存、劳动力分配、停产原因等计算结构。**劳动力不是可以直接忽略的字段**；是否保留抽象数值或移除机制，需要追踪依赖后决定，不能只隐藏 UI。

## 建议的发展循环

`开垦 → 建造 → 自动生产 → 加工/仓储 → 扩建/研究 → 时代跃迁 → 新区域`

多座建筑可以并行生产。玩家决定土地与材料怎么分配，而非轮流点击每一块田收获；离线按同一套规则结算，回访显示产出、仓满或原料不足等原因。

首个切片建议五类建筑：农田、伐木场、采石场、工坊、仓库。木材与石材用于建设，工坊消耗材料制作工具，工具用于生产设施改造；粮食作为开垦/研究补给。具体配方、消耗数量、是否需要独立研究资源尚未定案，不直接复制现有技能的等级/经验数据。

选择至少包含三类真实取舍：

- 扩建更多田地，还是先升级灌溉，提高现有地块效率。
- 提高加工产能，还是增加仓储，使长时间离线更有收益。
- 优化现有区域，还是投入材料打开具有新资源的区域。

初版只加少量容易看懂的区域协作，例如灌溉设施服务周边农田。暂不让道路、搬运路径、几十种邻接系数共同影响产量；采用底座时先确认能否关闭这些机制及其依赖。

## 视觉成长与时代

| 层次     | 玩家操作                     | 场景反馈                                                 |
| -------- | ---------------------------- | -------------------------------------------------------- |
| 新建     | 在空地建农田                 | 空地出现翻土、田垄与作物                                 |
| 扩建     | 增加产能或开放相邻地块       | 农田面积、田垄数量、围栏范围增加                         |
| 技术升级 | 采用工具或灌溉               | 出现水渠、储水设施或风车，作物/建筑形态改变              |
| 时代推进 | 达到建设里程碑并完成关键科技 | 主要建筑、道路、设施和可见边界一起变化，并开放新生产能力 |

时代建议先以四段设想组织美术：开拓（木棚/小田/土路）、工坊（灌溉/磨坊/石仓/码头）、蒸汽（机械农场/工厂/铁路）、自动化（温室/模块设施/电力灯光）。**首个可玩版本仅做前两段**，后两段保留概念；时代命名也只是建议。

时代推进以关键科技、设施和资源链能力为门槛，不以累计点击或纯等待触发。尽量保留已有建设与其用途：旧田改造、新生产链接续旧资源，避免每到新时代整片建筑全部报废。初版不需要转生清档。

## 沙盘与素材组织

建议固定等距视角，先开放清晰的可建设区域；区域内可复用底座地块数据。自由摆放与固定区域填充存在取舍：前者更自由，但涉及遮挡、连接、非法放置和素材拼接；后者更容易维持当前概念图的完整构图。建议先做区域填充/有限地块选择，不提前承诺完整自由建造。

场景分成地形、建筑、装饰、轻动效和交互层。整张夜间工坊图可作风格参考与远景；不能把所有建筑烘焙在背景里，再靠整张换图实现任意建设组合。

网页版 ChatGPT 可以生成和编辑图片，官方也列出了背景、UI 资产和 sprite sheet 等用途，见[图像生成说明](https://learn.chatgpt.com/docs/image-generation)。用于本项目时建议：

1. 保留当前图作风格参考，固定相机角度、比例、地面接触位置、光向和颜色。
2. 按建筑分别生成透明背景图片，再做同建筑不同等级/时代的变体；不让 UI、数字与文字进入绘图。
3. 先完成五种建筑、两个时代的小样，实际叠在同一地形里检查比例、边缘与遮挡，再扩充素材。
4. 生成结果需检查实际透明通道、裁切、轮廓一致性和缩小后的可读性；不假设一次生成的图集就能直接用于游戏。烟、水和灯光可以由程序添加轻量动画。

## 首个可玩范围与 PvE 边界

建议范围：一张沙盘、两个时代、五类建筑、少量资源、数个可见升级、一次区域扩展、自动生产、存档和离线摘要。判断重点是“新建后能生产，生产能推动下一项建设，升级后看得出，回访后有明确决策”，不是内容数量。

PvE 等上述循环成立后再讨论。地图边缘可以留出未来防御设施位置，但本阶段不实现攻击者。后续可让侦察给出下一波敌人构成，设施自动防守，结算展示击退数、损失、奖励与原因；敌人随时代变化。离线攻击是否造成损失属于单独产品选择，当前没有授权确定。

## 尚待底座验证的关键问题

- CivIdle 能否在关闭在线市场、云/平台入口后本地运行，最小依赖有多大。
- 存档错误、重载、离线时间和版本迁移是否满足本地优先要求。
- 缩减劳动力、运输和复杂建筑后，保留的生产模型是否仍完整。
- 能否用自有分层美术替换原资产，保留可复用的地块与交互能力。

因此，建议先做 CivIdle 的本地精简可运行性验证，再决定正式迁移；当前不将“推荐候选”写成“已经选定或已经完成”。
