# 基础底座调研与采用决策

> 历史记录，已被 2026-10-17 的用户决定取代：现在允许更换框架，并要求采用开源项目作为真实底座。产品目标已改为无具体居民的发展型放置沙盘。当前比较见[发展型沙盘玩法与底座对照](发展型沙盘玩法与底座对照.md)，活动进度只看根目录 `PLAN.md`。下文“不换”“不整体采用”的结论仅适用于当时的旧约束。

更新日期：2026-10-14。本文记录“从零搭建太重、有什么可借鉴的基础底座”的调研结论与采用决策。结论：**没有可整体采用的开源技能放置底座；分层借鉴——机制参照 Melvor 与开源克隆，美术采用 CC0 素材，工程沿用现有栈**。调研方式为公开仓库检索与素材站点核对，未运行任何第三方游戏。

## 结论摘要

| 层       | 候选                                                          | 决策                                                                   |
| -------- | ------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 游戏引擎 | Godot/Phaser/Kaplay + Tauri、Rust+Bevy                        | **不换**。与“不换框架”决定冲突，且会丢弃已验证的 Runtime/存档/离线合同 |
| 玩法底座 | 开源 Melvor 克隆（见下表）                                    | **不整体采用**，只作机制与数据结构参照                                 |
| 机制参照 | Melvor Idle 本体（商业游戏）                                  | **参照机制**（技能/修饰符/离线计算组织），不照搬代码、数值或美术       |
| 美术     | Kenney CC0 素材包（OpenGameArt 分发）、game-icons.net         | **采用**：CC0 图标/UI 素材落地 `src/themes/assets/`                    |
| 工程栈   | Vite 8 + React 19 + TS strict + Tauri 2 + Vitest + Playwright | **沿用**。已是现代底座；“工程管理”痛点对症文档与门禁改革               |

**判断依据**：均为个人/小项目，缺乏存档兼容、迁移、离线结算与验收证据；引入它们等于把未验证结构设为底座，违背“保留已验证合同”的工程约定。Melvor 本体的 TypeScript 数据驱动 + mod.io 生态证明“技能/物品/配方全 ID 化数据”路线可行——本项目的 `skill-loop` 正是该路线，新技能扩展因此零引擎改动。

## 机制参照要点（来自官方公开资料，不照搬）

- 技能相互喂养：采集→加工→制造→消耗，跨技能物料流是核心（Melvor 官方商店页与社区维护的 wiki 入门指南均以此组织）。
- 离线成长有明确上限并可扩展；消耗品（食物）提供限时效果，形成重复消费端。
- 以上只作为设计方向；本项目的周期、XP、配方参数由自有台账设计并验证，不复制其数值。

## 美术与 UI 采用决策

- **CC0 素材**：Kenney（kenney.nl，CC0）像素 UI 包（750 assets，OpenGameArt 可下载）作面板/图标基底；game-icons.net（CC-BY）作类别图标备选。许可与来源随 `src/themes/assets/` 台账登记，不引入需署名的付费素材。
- **设计 token**：统一 CSS 变量（色彩/间距/圆角/阴影/动效时长），暖色暗色像素工坊风；Noto Sans 字体栈；两种窗口尺寸（420×600 / 360×480）下信息密度优先。
- **不引入 UI 组件库**：核心层禁令 + 小窗信息密度需要精确控制；自建 token 化面板即可。
- **AI 生成兜底**：CC0 未覆盖的少量技能/物品图标（七技能图标、熟鱼/木炭等）用多模态生成补足，统一像素风格后入 `src/themes/assets/`。

## 边界

- 不换技术栈、不换引擎、不引入 UI 组件库、不新增运行时依赖。
- 不复制 Melvor 的代码、数值、美术或专有文本；开源克隆只读结构，不拷代码。
- 素材许可变更时同步台账；生成素材注明来源与用途。
