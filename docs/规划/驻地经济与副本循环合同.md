# 驻地经济与副本循环合同

更新日期：2026-10-11。本文是《诸界救援局》驻地经营扩展的唯一玩法合同，供规则、内容、界面和故事共同引用；不是运行时脚本，也不增加第二份产品主计划。

## 产品循环

长期驻地持续生产、制作、训练并准备防守；有限队员出征，完成当前世界的救援、调查或运输合同；回归后按合同回收材料和档案，再解锁驻地的下一种行动能力。首版验证“出发准备 → 自动经营 → 袭击/副本决策 → 成果结算 → 永久能力变化 → 返场用途”。

本期交付按玩家能力分阶段：经济合同与路线推演、驻地作业、专业解锁、自动防守、首世界运输闭环、长线试玩。一个阶段必须通过后再扩展下阶段的机制；内容卡先于对应数值与 UI。

## 阶段 0 内容边界与经济合同

功能首批内容上限：三个专业方向（采集、工程、救护）；两条生产链（建设/防守、救援/运输）；四个配方；两种副本专属稀有材料；生产、防守、救援三类驻地设施；当前主线救援契约与一个首世界运输契约。

专业必须至少解锁作业、配方或任务行动之一，升级不只提供倍率。四类配方各服务加工、防守、救护、运输，不得同时解决所有路线约束。所有首级作业和修复需要可由初始驻地资源执行；副本稀有材料只用于进阶能力，任何基础恢复路径不能要求先获取自身解锁材料。

每个材料、配方、设施、岗位、契约和奖励在内容卡中记录稳定 kebab-case ID、来源、消耗、产物、执行人数、解锁条件、持久/临时边界、损失/恢复条件和 UI 预览要求。数值录入机械内容；主题文案进入主题/叙事内容。暂不引入玩家市场、随机词条、物品强化失败或任意脚本配方。

## 驻地合同

- 常驻状态：仓库库存、仓库上限、岗位分配、在制批次、专业经验/解锁、防线状态、袭击周期与累计损失预算。
- 人员归属：驻地居民与当前出征队员互斥；从一个岗位到另一个岗位先结算当前时段，再更新分配。活动副本期间，驻地生产与副本按已分配人员各自推进。
- 自动作业：玩家选择配方和数量上限或目标库存；每批启动时原子预留并扣除投入，批次完成时原子交付产物。输入不足、仓库满、人员不够或安全停点触发明确暂停原因。
- 库存预留：出征补给、在制批次、防守预算不得重复花费；可支付量为实际库存减去有效预留。取消批次只返还尚未消耗投入，完成批次不重复交付。
- 专业成长：合法、已完成的作业授予对应专业经验；失败或未完成批次不给经验。专业经验不因副本失败回滚；证据、界点及合同回收奖励仍由副本结算授权。
- 仓满：停止占用该产物的作业，禁止溢出丢失；允许通过建设扩容或合法消耗恢复。

## 驻地袭击合同

故事边界：袭击事实是玩家已提出的驻地玩法；首次袭击的具体来历和人物解释必须由故事内容卡审核，不能从“求援者被删名册”直接推断袭击者身份或动机。首版不揭露主线未知事实。

袭击由显式的驻地发展档位和可见周期决定，不按离线时长无限叠强。周期到期先结算至事件时刻，再确定本次防守结果。玩家预设人员、设施和防守补给，在线、后台、离线走同一纯规则。

每次袭击设确定的消耗和可修复损伤；同时维护从上次玩家确认/恢复后的累计损失预算。预算达到上限、预计下一次会越过上限或防线不足时，进入保护停点：不再结算下一次袭击，保留基础恢复生产，不生成排队的历史战斗。玩家查看结果并补充/修复后，明确确认恢复周期。

袭击不得删除角色、永久库存/技术/证据或建筑解锁。建筑可进入受损状态并停止对应能力，直到以公开成本修复。袭击奖励限普通驻地物资和防守经验，不能产出副本专属材料、线索或无限刷出的永久奖励。袭击预览显示下一次时间、敌对档位、投入、预计损耗和损失预算余量。

## 副本回收合同

每份契约只能声明一种已实现的回收政策，运行时、局前说明、局内摘要和结算共用相同政策与容量：

| 回收政策   | 玩家可带回的成果                                             | 首批用途                 |
| ---------- | ------------------------------------------------------------ | ------------------------ |
| 任务奖励型 | 契约明确列出的奖励、救援人员/故事证据                        | 现有主线救援契约         |
| 容量运输型 | 从本局可运输库存中选择，合计不超合同运力；证据按条件独立归档 | 首世界返场运输契约       |
| 完整回收型 | 仅合同标记的可回收清单，不含临时建筑和未标记物资             | 合同接口预留，首版不配置 |

回收政策在出发前冻结到活动契约，不能因剧情选择或随机事件改写。失败、撤离、成功的资源处理规则显式列出；已经到账的材料和奖励与 run sequence/已结算状态一起原子保存，重试不重复发放。随机事件可推进可返场支线，主线证据由固定条件授予。

## 时间推进与故障边界

驻地和副本沿用单运行时、单动作队列和单保存队列。由一次被注入的时间区间推演两个子系统，按最早的作业完成、袭击、制作交付、副本待决节点切分；事件先结算过去时间，再改变后续状态。副本到需要玩家决策时停住副本时间，驻地继续按自身安全规则推进。袭击进入保护停点时驻地危险推进停止，副本仍按自身规则继续。

存档目标 schema 9、内容目标 14.0.0、产品目标 0.9.0。schema 8 → 9 显式添加驻地初始状态；旧进行中副本使用冻结 v13 定义补算至迁移时刻，不追溯修改其契约、物资或奖励；驻地从清楚说明的初始状态建立，不从副本临时库存复制资源。迁移失败保留源存档与备份，不静默重置。旧版 0.7.1 与其存档目录继续隔离。

新增命令均由 `GameRuntime.dispatch`/当前唯一 ExpeditionRuntime 命令队列提交。规则保持纯函数；种子和时间由调用方注入；数值与内容 ID 需内容验证；不得将排程计时器或 UI 局部状态写成第二份权威存档。
