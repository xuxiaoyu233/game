## 稳定核心

- 单主活动，选择训练/生产对象后连续重复同一活动。制作材料不足时明确停止；不自动切到采集，不默认引入跨活动队列。
- 采集、制作是两类规则行为，不是永远只有两个技能。技能各有经验、活动/配方和与其他技能的用途关系。
- 首发建议“采掘＋金工”两项技能、两档生产与工具发展，具体名称/ID/参数在 P0 冻结。第一档先可玩，第二档证明成长与内容扩展。第三档只留资料接点。
- 旧“金属/零件/结构件/修理包＋单维修目标”是已撤回的默认样例；不继续照它限制产品。工具提升应服务后续技能/配方；故事任务不能成为常规成长唯一通道。
- 首轮默认连续制作的提案需在 P0 验收中明确。旧合同强制 remainingBatches 尚未实现，不视为不可改的存档承诺；有限批数以后再评审。
- 小窗口与低频回访是交互约束，不能据此削掉技能发展核心。故事库厚度不等于玩家需要频繁读长文。
- 精通、装备、出售、研究和战斗是可能加强核心的后续系统，分别评审，不预先做通用接口或整体复制 Melvor。

**S0 历史验收参考（已完成，不要重复执行，除非用户另行要求）：** S0 是工程整理阶段，交付模块/文档处置清单、唯一层与路径责任表、实际整理 diff 和检查证据。其原验收记录仍留在 PLAN，不作为当前待办。

**首次任务执行 S0：**

3. 故事文献目标为独立 story-library/；原始交付与工作副本按 .local-data/collaboration/ 分隔，证据/交接包在 artifacts/collaboration/。实际候选导入仍标未批准，不运行附件脚本。

5. 合并重复现行说明、把失效规划正文迁至历史并修链接/索引；保留仍有效原子合同。清理真正无引用代码，按职责拆分有证据支持的大模块；不要求把所有历史代码批量搬目录。
6. 保持当前 0.8 运行、历史加载与保存屏障行为。旧岗位/远征替换属于 P1，不在 S0 混入新玩法。工具链/依赖/旧 exe/原始 ZIP/用户存档不作为自动清理目标。
7. S0 原验收包括一次 check；影响 UI/入口装配加 e2e，影响 Rust/桌面加 native-check/native-build。历史结果见 PLAN；不要因此重跑 S0 或声称新玩法已验收。

## 工程边界

- 纯规则只在 src/domain；机械 ID/参数在 src/content；显示名、说明、颜色、故事文案在 src/themes。domain 不访问时钟/随机/DOM/网络/磁盘/React，app 不另写解锁计算。
- 沿用当前应用入口、Tauri 外壳和平台端口，一次一个 Runtime、动作队列和保存队列。允许替换旧人口/岗位、远征与 UI 实现，不新增第二入口或并行运行时。
- 保留启动补算、lease、保存失败重试、旧 ack 不清新 dirty、导入/关闭屏障、坏档/备份恢复合同。基础补算在 P1 正确实现，P3 只集中完善回访。
- 新档显式 namespace/profile/codec，浏览器 DB 与 lease 同时隔离；桌面固定受限 profile，不接受任意用户路径。不触碰旧 0.8 主档/备份，旧档不自动迁入；不兼容导入保留源。
- 开始/暂停/恢复/切换、原子扣料/产出/XP、缺料停点和工具下一完整周期生效按合同实现；在线/离线复用算法，长短推进一致。
- 有限定义/ID/前置/效果，启动组装校验唯一性、引用、文案覆盖与有效参数；实际新档可达性用真实规则验证。禁止 any、关闭严格 TS 或内容脚本解释器。
- 独立故事文献不含工程路径/类型/schema/生效参数，运行时不读 Markdown。包外审核映射编辑 ID→机械/文案 ID＋获得条件/可见范围/批准依据。
- 新增同类内容若必须复制算法、按中文名判规则或增加第二状态源，停止扩内容并拆掉耦合，再继续本阶段。
- 删除旧页面/规则前检查历史引用与存档合同。“重做”不授权删除用户存档、坏档或冻结迁移证据。

## 阶段边界和集中验收

| 阶段 | 范围                                                 | 退出条件                                                              |
| ---- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| S0   | 分层、路径、职责与实际瘦身，保留现有行为             | 处置清单与实际 diff 可审查，文档/代码引用完好，适用门禁通过；报告后停 |
| P0   | 两档共同蓝图、候选参数/推演、资料对照和替换/隔离方案 | 无来源/用途缺口、解锁自锁或阻塞 P1 的含糊行为；设计报告后停           |
| P1   | 第一档单活动、采集/制作/工具 II、隔离与恢复、最小 UI | 真新档无需灌 XP 可到工具提升，周期与保存安全，资料一致；报告后停      |
| P2   | 第二档活动/配方/工具 III、跨档用途与真实先后路线     | 第二档可达，不复制同类规则，比较相同终点的选择；报告后停              |

| P4   | 用户选定题材、事实修订批准后的一条短任务与正式档策略 | 复用已有经济，资料独立与批准映射完整；正式兼容选定后才实现；报告后停  |

阶段内只跑必要的定向检查；阶段末一次 ./scripts/project.ps1 check，UI 改动另一次 e2e；Rust/桌面改动加 native-check/native-build。S0 若改变模块装配/桌面实现，就在 S0 运行相关门禁；P1 若改桌面隔离就当阶段运行原生门禁，不推迟到 P3。纯文档不跑无关 E2E/原生。失败修复后复跑受影响范围，提交前遵守项目完整检查要求。

WorkBuddy 的“91% 补料”“必须活动队列”、工具磨损、采集 ≤50%、主动/挂机 ≤2×均非批准要求。旧版数值不直接用于新模型；不同技能 XP 速率比不等于主动/离线差距。制作中途材料用尽本身不能证明架构错误。
