## 已确定的产品方向

- 首版是本地优先、适合小窗口和低注意力回访的放置游戏。一次只能推进一个全局主活动：选择活动，获得材料和技能经验，解锁制作，在永久工具投资与消耗目标之间取舍，离开后回来理解进展。
- 两项技能先按采集、制作组织；原型资源候选为金属、零件、结构件、维修包。先核对报告里的具体名称/机制是否连贯，再从实际运行规则定义，不照搬数值。对玩家显示通用功能名称。
- 第一个纵切覆盖核心活动和隔离存档、真实新档可达、两条用途路线、回访摘要与小窗口 P1–P3。严格遵守根目录唯一 `PLAN.md`；更新状态只依据已交付和可重现的证据。遇到范围内常规实现选择自行决定并记录，不要只因未知的最终品牌而停工。
- 新名称、世界观、人物和主线由 WorkBuddy 另行从头研究。旧《诸界救援局》的“救援局”设定、失籍城、能芯/锚材、旧角色、旧主谜题等都不可作为新版默认名称、设定或 ID。不要做旧设定的换皮；尚未获批的故事段不应进入运行时。WorkBuddy 最终方案目前未返回，工程使用通用短任务占位或不接叙事事实。

## 工程边界与行为合同

遵守 `AGENTS.md` 和已有合同：

- 规则只进入 `src/domain`，保持纯规则；参数/ID 进 `src/content`；显示文案、通用名称、主题进 `src/themes`。UI 通过唯一 `GameRuntime.dispatch` 发命令。
- 沿用单 Runtime、单动作队列、单保存队列，以及离线补算、导入/关闭屏障、保存失败恢复语义。原型实验档必须使用明确隔离的 namespace/codec；不读写旧档或覆盖备份。
- 明确开始、暂停、恢复、切换语义；暂停按合同保留进度，切换正确结算旧活动与未完成周期，不能无因发奖。周期完成时原子校验和提交成本、产出、经验及解锁；离线推进与分片推进结果一致。工具升级从合同规定的后续完整周期生效，不追溯已流逝时间。
- 对机械定义做启动时/加载时校验，使用有限类型、显式版本与兼容策略；严格 TypeScript，禁止 `any` 和关掉严格设置。不用界面或文档绕过 domain 规则。
- 建立资源/配方/活动/技能/工具/任务之间可验证的引用与闭环。新档不用编辑器注入经验也能走到首个制作目标；检查守恒、不可达、死物品、材料卡死、周期卡住、重复领取和工具/目标两种路线。
- 内容资料与运行时完全分开：运行时不读取 Markdown 或故事文献包。若工程文档要约定未来接口，使用稳定编辑 ID 对稳定 `content`/`themes` ID 的包外审核映射，并写明故事获得条件、可见范围和用户批准依据。此阶段不要预造新故事映射或迁入旧剧情。
- 除非实际实现必须，不加依赖、通用后台、数据库或可执行内容插件。不为简单原型预建泛化系统。

## 推荐实施顺序与完成标准

1. **P1-A/B：** 新活动有限类型和类型化机械定义；隔离存档 namespace/codec 与启动校验。记录兼容/隔离边界，验证旧主档和备份保持原状。
2. **P1-C/E：** 单活动命令和纯规则、周期/升级/停点行为、失败恢复和一致性测试。
3. **P1-D：** 两项技能入口、当前活动条、资源/用途/下一解锁、实际制作路线。小窗口主操作可见，浏览和选中不暗中切换活动。
4. **P2：** 工具投资和维修目标都真实消耗共享材料且均可达；写出起始档、每条路线逐周期/逐等级库存推演，避免用一个静态回本数字声称长期最优。
5. **P3：** 离线/回访摘要能说明获得物、等级/解锁和精确停因；覆盖 420×600 主窗口和 360×480 压力窗口。浏览器结果不能充当 Windows 托盘、置顶、隐藏恢复或原生关闭验收。
6. 如有必要，更新根目录 `PLAN.md`、架构/工程文档和命名台账；不能另建相互冲突的主计划。

开始前不要重置、覆盖或格式化任何已有用户存档。新版本、正式迁移与生产数据目录要等实验合同通过评审后再定；不要擅自升级正式产品/schema 版本。不要创建新 GitHub 仓库，不自动推送 Git，不发布、启用账号云同步或系统自启动。
