## 会话和并行方式

分层、目录和保存位置以[架构说明](../架构说明.md)为唯一合同，阶段与门禁以 [PLAN](../../PLAN.md) 为准。

- 当前 Codex/集成者先核恢复版本和唯一 PLAN，再按新工作包分工；用户验收审美与真实玩法。旧 V2 交接仅作历史证据，不再据此给 CodeBuddy 派活。共享目录一次一个写入任务，跨层影响随结果报告。
- 2026-10-23 本机只读回执：根 main 的受跟踪文件干净，46 个未跟踪文件位于 `flowline-workbench/`；被忽略的 `next/` 中另有当前营地源码与素材。旧“大量未提交”属于历史时点，不把根 Git 干净误读为营地已归档。不得 reset/clean/覆盖；仅从根 HEAD 建 worktree 不等于拿到完整输入。
- 每项交接写任务/阶段、输入 HEAD/资料版本、可写文件、负责人和交付路径；“另一个窗口”或“只负责工程”不足以保护并行写入。
- 在本机协作时，不同任务使用独立 checkout/worktree 和分支；不能同一目录里同时切分支或改 PLAN。两个聊天窗口不会隔离文件。

阶段开始说明输入版本/HEAD 与负责目录；阶段结束回传差异和未定项。Codex 汇总唯一 PLAN/工程映射，用户验收后再进入下一阶段。

## 检查与权限

不按每次改动跑固定检查，不以补测试独立推进；阶段末只对实际工程和影响范围集中验证。旧根门禁不套到上游新工程。规则、纸面推演、浏览器、原生构建和实机验收分别记录。具体检查只见 PLAN。

根入口/桌面壳保持原状，新底座隔离验证，每个工程内部只有一套推进与保存链。不清理用户存档，不自动提交/推送、发布、启用云同步或自启动。
