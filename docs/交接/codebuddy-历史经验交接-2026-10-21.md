## 4. 可复用工程经验（按 A 架构 / B 验证 / C 前端视觉 / D 协作）

### A. 软件工程与架构

**A1 成熟底座隔离改造，不为套合同重写上游**
情境：next/civ-idle 基于 CivIdle。问题：旧根原型规范（目录/门禁/单活动合同）与新沙盘冲突。做法：保留上游目录/ID/调度与合法操作路径，新增代码自行分离规则/数值/展示；两套工程各自跑自身检查路径。原因：重写底座成本极高且会引入新缺陷；合同差异用「适用范围」条款解决而非代码返工。证据：`[规范条款]` `AGENTS.md` 的适用范围段 + D0 交付文档；`[执行结果]` `next/civ-idle` 至今沿用上游 `src/scripts` 骨架与独立 namespace（仅本机未提交）。反例：不得以此为由关闭类型检查或建第二状态源。当前结果：schema5/`d1-c-1` 稳定演进。归属：**game 专用**（已写入 AGENTS/工程规范）。

**A2 单一事实源：派生逻辑只在一个模块实现**
情境：资源图标映射在 HUD、技能页各一份；作业映射又出现第三份。问题：三处漂移即三份 bug。做法：收敛为 `camp-resource-icons.ts` / `camp-skill-icons.ts`（含回退链），页面只 import。原因：本项目 `shared/**` 是规则层，展示映射放 UI 层非组件文件；重复定义是隐性技术债。证据：本会话收紧批的 diff 与 42/42 合同。反例：不为"少一个文件"把规则数据塞进展示层。归属：**已被工程规范覆盖**（"派生逻辑单一出处"），本条是其在图标域的实例。

**A3 存档与内容变更：版本号、ID 集合指纹、迁移分支三件套**
情境：根原型曾出现"版本号相同但键集漂移"导致存档无法启动。做法：ID 集合变 → bump 版本 + 更新 keyset manifest + 加加法迁移分支；禁用静默重置/沿用旧产量补算。原因：版本号只表示"存档自称属于哪个内容版本"，不证明键集完整。证据：`[执行结果]` 提交 `dbbd9b0 fix(persistence): repair same-version save key drift` 与 `7ea78a8 chore(content): gate content ID key sets`（本轮已复验存在）；`[规范条款]` 工程规范「内容添加流程」小节。归属：**game 专用**（已在规范）；跨项目可迁移的是「版本≠键集完整」这一判断。

**A4 静态分层 bug 会复发：顶层区块统一进层叠组**
情境：技能列表/页签被场景层盖住，数月后树视图"布局正确、命中正常、像素不显示"。做法：所有顶层区块共享 `position:relative; z-index:1` 选择器组，新增即加入。原因：`position:fixed; z-index:0` 的场景层会让静态流内容画在其下；`elementsFromPoint` 命中且背景不透明仍可能不显示，用 DOM 检查无法发现，必须看像素。证据：`[执行结果]` 提交 `e9cc465 fix(ux): lift shell content above the era scene layer` 与 `43b2cea fix(tree): lift the tree region above the fixed scene layer`（同类 bug 相隔数月复发，均已复验存在）；`[规范条款]` 工程规范的层叠组小节。归属：**game 专用**（已入规范）；可迁移判断：「命中测试通过 ≠ 像素可见」。

**A5 瘦身要先分清"无人读取"与"保留不留档"**
情境：`town-landscape.png` 标 reserved 但仍被打包（两条打包路径：`scripts/prepare-atlases.mjs` 与 `vite.config.ts` 的 Spritesmith 插件）。做法：移文件到 `src/textures/reserved/` + catalog 改 `integration: reserved-not-shipped` 并去掉 `frame`/`atlas`，图集 8.21→5.35MB。另一类：32 张早期原型小图只被 catalog 段落引用、代码零读取——**没有删**（改 catalog 35 条风险 > 收益）。原因：删除与排除是两种动作；前者要保留记录，后者只需停止打包；且构建后要先清 `dist` 才能反映新图集（旧 hash 产物会残留）。证据：`[执行结果]` `docs/证据/文档与工程收紧-20261020/README.md`、`next/civ-idle/scripts/prepare-atlases.mjs` 的 RESERVED 集、`src/textures/reserved/`（均仅本机未提交）。归属：**可补充 skills 候选证据**（`coding-engineering` 的项目瘦身类）。

**A6 死代码/死样式清理用"引用计数 + 截图对照"，不凭感觉删**
情境：CSS 存在整块被更高优先级规则取代的旧样式与 6 组零命中选择器。做法：先 grep JSX/JS 引用计数，再删，再构建 + 实机截图对照；保留仍被复用的通用卡类（`.camp-skill-card` 7 处使用）。原因：删错样式的代价是视觉回归且难以定位。证据：`[执行结果]` `docs/证据/文档与工程收紧-20261020/README.md` 第 1/2 节、`camp-navigation.ts` 中零引用的面板模式状态机已不存在（第二轮复核确认 removed）。归属：**game 专用做法**，方法可入 `coding-engineering` 候选证据。

### B. 开发效率与验证成本（用户重点关注的过度验证）

**B1 分层验证：低成本即时 → 里程碑集中 → 发布/高风险全量**
事实：`[规范条款]` AGENTS.md 与 `docs/工程规范.md`「工作流」小节已规定「日常 `check:quick`（格式/类型/Lint）不跑测试；阶段末一次适用门禁 + 影响 UI 加浏览器冒烟；涉及保存/兼容才查重载与迁移」。`[执行结果]` 我的实践：批次内每完成一项跑 `check:quick`（约 10 秒），全部完成后跑一次 `build` + 合同 + 两尺寸走查。**这不是"少测试"**，而是把测试成本移到它能拦住问题的时刻。
反例与边界：修 bug 后只复跑失败项及受影响路径，不从头重复全套（工程规范「工作流」小节）；若修改触及保存/迁移/规则，必须补对应合同测试——本轮未改规则，故未新增单测，只在门禁跑既有 42 项。

**B2 我实际发生过的过度验证（反例）**
`[自查]`+`[执行结果]`（用户 2026-10-20 反馈"感觉 UI 还需要很大的进步"后，我在交付里自列的三条）：
- 同一批内重复跑全量合同测试 4 次以上（每次约 0.5 秒 + 起进程开销），其中 3 次无代码变化；
- 为"看一眼效果"反复构建 + 截图 6+ 次，其中若干次仅 CSS 微调；
- Node 20 缺 `stripTypeScriptTypes` 时，为跑 42 项合同测试临时写 esbuild 垫片（`next/civ-idle/.cache/run-contracts.mjs`）——**一次性成本合理**，但每次重建后都重跑全套则无收益。
结论：停止条件应为「本批改动的影响面已覆盖」，而非"再跑一遍更保险"。

**B3 测试太晚的反例（说明不能一律推迟）**
`[自查]`+`[执行结果]`：
- V2 声称"点击区对齐"只凭截图，未做点击实测 → 返工一份自查文档（U3）；
- 技能页重构后未先查 `publicArtUrl`/mask 尺寸 → 图标被 padding 拉伸成色块，靠截图才发现（见 C3）；
- CSS 选中态被全局 hover 覆盖 → 若上线前只跑构建不跑浏览器，白字落纸底不可读（见 U8）。
判断：**影响可见呈现的改动，阶段末配一次真实浏览器走查**（成本 ~1 分钟），但不必逐控件铺用例；仅文案/数值微调可按影响面决定是否走查。**不是"每次展示层改动都强制全量浏览器测试"**（见 §7 过度规定审查）。

**B4 环境差异要么解决要么明写，不假装通过**
`[执行结果]` 本机 Node 20.19.4，合同测试需 Node ≥22.18；`npx node@24` 拉取失败。做法：`next/civ-idle/.cache/` 垫片 + 在每批交付文档注明「Node 24 原生方式仍需复核」。原因：把垫片结果写成"合同通过"会误导后续门禁判断。`[未解决]` 第二轮仍未在 Node 24 原生加载器下复核，属未关闭项。

### C. 前端、交互与视觉审美

**C1 游戏 UI 三问：主体是谁、一个对象几个主操作、数值变化是否被看见**
`[执行结果]` 本会话把技能页从"四卡平铺"改为"技能轨 + 单技能主面板 + 当前动作卡 + 动作行 chip"，三个反复出现的缺陷（推荐卡与列表行两个开始按钮、等级缺口死按钮、strip 与建议重复）都源于违反这三问。`[推断]` 参考 Melvor（左技能栏 + 单技能窗口 + 动作格）与 RuneScape（等级徽章），但不搬左侧竖排（本项目顶部已有导航）。适用范围：放置/成长类界面；反例：工具型后台不适用"一个主操作"。**注意：「一个对象一个主操作」是本项目语言合同条款（`docs/内容资料库/界面语言与信息层级.md`），不是通用设计定律。**

**C2 反馈层要轻且互不覆盖**
产物飘字（0.9s）、数字缓动（420ms）、周期闪烁（0.4s）、升级脉冲（0.9s）+ 提示（1.6s）分处资源芯片/当前卡/徽章，同一时刻只一类主导；`prefers-reduced-motion` 下数值直接落值、CSS 动画关闭。原因：反馈的目的是让"积累被看见"，不是抢注意力。

**C3 图标用 mask + 表层取色，尺寸与槽分离**
`CampArtIcon` 以 CSS mask 渲染 catalog SVG，颜色由所在表面 token 决定；图标槽（外层底）+ 图标（内层 15–20px）分离——曾因把 padding 加在 mask 元素上导致背景铺满、mask 拉伸变形。技能轨按技能着色（伐木绿/采石灰/农事金/木工褐）提高辨识。归属：可入 skills 候选 `desktop-gui-verification` 证据（界面呈现核验）。

**C4 对比度与可达性要实测，不靠"看起来够"**
`[执行结果]` 本轮实测 18 组色对，发现 4 组不达 4.5（ETA 3.20、锁定 chip 4.06、推荐/升级 4.40），调深后全部 ≥5.4；焦点环 `3px solid #235f75` 与相机钮一致；`role=tablist/tab/tabpanel` + 方向键 + roving tabIndex；数字 `tabular-nums` 防跳动。原因：纸色低对比体系极易在小字号上失守。证据：UI 打磨交付「验收补完」表的对比度行。

**C5 审美反馈要转成可执行规则，而不是换配色**
用户对 V1/V2 的否定（"画面/交互不达预期"）没有可执行信息；我据此提炼的是结构问题（信息层级平铺、无反馈、多主操作），而不是再换一版暖色/冷色。教训：**审美不通过时先问"哪一类信息没被看见"**。

### D. AI 工程协作

**D1 开工先读工程与工作树，再谈设计**
证据：U1（方向错位）、U7（并行写入）、A1（底座边界）。做法：每批先读 PLAN 最新入口 + 目标文件实际内容 + 工作树状态（`git status`、关键文件哈希/mtime）；不以 README 结论代替源码。归属：**候选 `coding-engineering` 的 E-ffbfbdf30b2b 已覆盖该方法**（"reading repository instructions and worktree state, preserving existing changes, reusing project quality commands and scoping verification to the work package"），本交接补充 game 侧实例即可，不新增正文。
