# 故事资料库总索引与编辑规范

> **当前入口版本：1.0；更新时间：2026-10-11。** 本文件规定故事资料的归属、权威顺序、状态标记和工程化变更流程。历史方案保留来源，不自动成为当前正史或游戏功能。

**下一版创作决策：** 用户要求从头替换《诸界救援局》的名称与故事框架。下表“当前批准正史”只指仍运行的 0.8 版；新框架尚未选定，旧名称、人物、组织与主谜题均不强制继承。WorkBuddy 负责独立调研候选，Codex 复核修改，用户选定后再形成下一版责任资料。

`README.md` 是仓库读者的发现入口；本文件是故事资料的治理入口；`PLAN.md` 是唯一的当前实现计划。不要再建立平行的主故事索引、实现计划或重复资料库副本。

类目、资源名称、生产链和成长/科技的工程对应由[内容资料库](内容资料库/README.md)管理，故事事实仍只在本索引的责任资料维护。已选下一阶段为单主活动原型，故事经短任务逐步接入；旧版批准记录保留，不自动约束新创作。任务新增事实、证据与永久奖励仍需先评审。

## 下一版独立故事文献包

交接要求见[WorkBuddy 提示词](交接/WorkBuddy-故事与命名调研提示词.md)。先形成独立 `story-library/` 候选包，内部相对链接均在包内；来源、研究解释、虚构设定、人物/世界关系、命名与技术设定分开标状态。包可脱离游戏仓库阅读，不包含代码路径、TS 类型、存档字段、XP/配方周期等生效机械参数或工程进度。

完整调研成果目前尚未生成。旧设定含产品身份与机械 ID，不能据此宣称独立文献库已经完成。评审通过后，由本索引导航至新资料的唯一责任目录；候选包不另成为生效正史。包外接入表由工程维护，记录故事版本、编辑 ID、机械/文案 ID、获得条件、可见范围与批准依据；叙事事实不能由运行时代码或中文名称自动推断。

## 内容状态与读者可见范围

故事状态与实现状态分开记录，避免把“写进文档”误报成“进入游戏”。

| 状态类别 | 允许值                                               | 判定依据                                                                 |
| -------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 故事状态 | 当前正史 / 候选 / 历史归档                           | 用户批准、明确标注的提案，或已冻结的旧产品资料                           |
| 实现状态 | 未计划 / 规划中 / 已实现 / 自动检查通过 / 待人工验收 | 对应代码、`PLAN.md` 验收记录和实际运行证据；自动检查不替代设备验收或试玩 |
| 可见范围 | 作者掌握 / 角色相信 / 玩家已观察 / 本局临时现象      | 写明信息由谁掌握、在哪个条件下获得，以及哪些结论仍未证实                 |

同一事实可以是“当前正史、尚未实现”，也可以是“已实现、仍不能证明作者尚未揭示的真相”。不得把角色信念写成客观事实，不得把历史归档文字改称当前正史。

## 交叉追溯合同

需要维护的关系按以下链条可回溯：

**来源与阅读范围 → 路径/世界/人物 → 任务/事件 → 证据与问题 → 人物行动/关系变化 → 机械 ID/展示文案/存档事实。**

交叉记录至少包含稳定编辑 ID、关系起点和终点、关系类型、触发条件、状态、依据或阅读范围、玩家可观察后果、实现映射。未实现时明确写“无运行时映射”；文学参考只支持被实际阅读的部分，不把简介或摘要伪装成全文阅读。

`SRC`、`READ`、`PATH`、`W`、`Q`、`BEAT`、`CHAR`、`REL` 等是文档编辑 ID，不是存档字段。显示名称可评审更改，稳定 ID 不复用；只有进入代码合同的 ID 才纳入机械内容版本与存档兼容性审查。

## 变更流程与验收

1. 先确认修改对象属于当前正史、候选、当前实现还是历史归档，并编辑其唯一责任文档。
2. 新增史料或文学依据时，在来源台账记录出处、实际阅读范围、可信边界和转译用途。
3. 修改跨文档因果时，更新交叉索引和相关世界/人物/任务卡；核对引用 ID、关系词和本地链接。
4. 要进入游戏时，另行修改 `src/content`、`src/themes` 或 `src/domain`；评估内容版本、存档迁移和失败恢复，更新唯一 `PLAN.md` 的验收状态。
5. 运行 `npm run check:narrative-docs`。完整工程变更运行 `./scripts/project.ps1 check`；UI/桌面行为按[工程规范](工程规范.md)追加对应验收。

文档门禁通过只证明索引和引用结构可追溯，不证明文学效果、历史解释、平衡性、桌面行为或玩家可玩性。
