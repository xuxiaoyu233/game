本页只做**导览**：告诉你哪份文件说了算、哪些是历史。阶段、顺序与门禁只维护在根 [PLAN](../PLAN.md)，本页不写计划、不记进度。

## 一句话现状

技能/作业放置成长为主体，场景随真实进度完善；桌面网页版，单营地长期进度。已落地：四技能/10 作业、八建筑/六资源/五 Tab、工坊与本地 2 星、技能页“技能轨 + 单技能主面板”、资源芯片与数值反馈。存档 schema5 / content `d1-c-1`。

## 三类文档的效力

| 类别 | 位置 | 效力 |
| --- | --- | --- |
| 当前合同 | PLAN、架构说明、工程规范、语言合同、适配规格、美术规格、内容资料库 | 约束当前实现；冲突时以 PLAN 为准 |
| 交付证据 | `docs/证据/**` | 只证明“那时做了什么、测了什么”；不改写后续结论 |
| 已撤回/历史 | `docs/设计/ui-v3`、`docs/设计/长期发展与休闲组合规格.md`、`docs/交接/CodeBuddy-V2长期小镇与组合成长.md`、`docs/历史资料`、`docs/证据/历史` | 保留来源与取舍，**不作为当前任务或审美基准** |

撤回项的共同原因：2026-10-20 用户明确“技能放置成长为主体、场景是进度结果”，此前“完整院落 + 手动选地建设 + 批量推广 + C2 三选一”的顺序不再成立。配色/组件可以复用，任务不得照此组织。

## 内容资料库与代码的唯一性

- 机械数值、文案、配色、素材各有唯一来源：数值在 `next/civ-idle/shared/sandbox/**` 与 `shared/logic/Config`，文案在玩家界面与语言合同，素材在单一 catalog，配色在 `src/css/sandbox-tokens.css`。
- 文档里的表格是**提炼**，与代码不一致时以代码为准，并回来改文档；不要把同一张数值表复制到第二份文档。
- 交付文档只写“本批改了什么、怎么验证、还剩什么”，不复述规则。

## 维护规则

1. 新增交付 → 在[证据总索引](证据/README.md)加一行；不新建第二份计划。
2. 新增或撤回设计方向 → 改本页“三类文档的效力”与对应目录 README 的一句标注，不要在每个文件里各写一份。
3. 文档声称“已实现/已验证”必须有证据；构建通过不等于审美通过，浏览器证据不等于其他平台证据。
