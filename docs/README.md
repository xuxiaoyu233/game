# 文档地图

先读根目录 [README](../README.md) 了解产品，再读 [PLAN](../PLAN.md) 确认当前分支、实现、验证范围和唯一执行阶段。本页只导航与界定职责，不复制进度。

## 按任务进入

| 要做什么               | 先读                                                                  | 再定位                                                                                                                   |
| ---------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 开始一项工程任务       | [AGENTS](../AGENTS.md)、[PLAN](../PLAN.md)、[工程规范](工程规范.md)   | 本次 Issue/PR 的输入 HEAD、范围、验收与负责人                                                                            |
| 理解系统边界与保存位置 | [架构说明](架构说明.md)的分层、路径章节                               | `src/main.tsx` 组装，`runtime` 队列/屏障，`platform` 适配                                                                |
| 修改活动机制           | [当前游戏行为合同](规划/轻量放置核心合同.md)                          | `src/domain/skill-loop/`、对应测试与 runtime 接线                                                                        |
| 增加同类内容或改数值   | [内容资料库](内容资料库/README.md)                                    | 入口选定的 `src/content` 定义、`src/themes` 文案与兼容检查；旧 v1 仍有组合/迁移消费者                                    |
| 修改存档与迁移         | [架构说明](架构说明.md)的数据路径、[工程规范](工程规范.md)            | `src/persistence/skill-loop-codec.ts`、`skill-prototype-save-migrations.ts`，以及平台保存合同                            |
| 验证修改               | [工程规范](工程规范.md)的检查与工作流                                 | `package.json`、`scripts/test-area.mjs`、`.github/workflows/quality.yml`；按实际执行分别记录静态/单测/E2E/原生/实机/试玩 |
| 研究或接入故事         | [故事治理](故事资料库.md)、[独立故事包](../story-library/README.md)   | 候选与已批准事实分开，进入游戏前维护包外映射                                                                             |
| 查为什么这样设计       | [本轮治理审计](审计/2026-10-16-治理审计.md)的决策、外部比较和历史纠偏 | 已有版本化证据；高影响的新决定后续按需写 ADR                                                                             |

常用任务应能从本表直接定位责任文件，不要求依次读完所有入口。实际的 30 秒/3 分钟/10 分钟可用性尚未经过新人计时测试。

## 信息职责

| 信息                   | 权威责任与生命周期                                                                                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 当前方向与执行阶段     | 根 `PLAN.md`。具体任务、负责人和进展进 Issue/PR；不在架构和资料库复制阶段表。                                                                                               |
| Reference Architecture | 架构说明负责本项目的模块/数据路径，工程规范负责工程约束。七层是项目模块边界，不是所有放置游戏的必然结构。                                                                   |
| Durable Framework      | 目前尚无独立、完整的通用方法层。后续从已验证合同提炼活动并发选择、Source → Transform → Sink、统一时间推进、存档迁移与验证方法；不把当前技能、资源或单活动选择当成普遍规律。 |
| Concrete Game Instance | `src/domain`、`src/content`、`src/themes` 和对应实例设计资料。运行行为以入口实际装配的代码为准，资料中的数值注明版本/用途。                                                 |
| Evidence / Decision    | 有输入版本、方法和局限的研究/验收与重大取舍。证据只证明其记录范围，不自动继承到最新 HEAD。                                                                                  |
| Execution              | 本次 Issue/PR。旧交接与 S0–P4、S1/S2 表仅为过程来源；未完成项由当前 PLAN 重新排入后才可执行。                                                                               |
| History                | 有明确消费者或独有证据才保留在 HEAD。其余按逐项审计考虑 Git 历史，不再复制完整旧 PLAN 或增加多层历史索引。                                                                  |
