# 工程规范

本规范适用于本地桌面技能放置游戏及保留的旧产品兼容代码。原型名字和主题可替换，技术标识、路径与存档协议变化须显式审查。唯一实施顺序先 S0 分层/路径/职责与瘦身，再进入玩法阶段。

## 命名与结构

| 对象                       | 规则                                                                           | 示例                                                                      |
| -------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 文件夹、普通 TS 文件       | 英文 kebab-case                                                                | `save-codec.ts`                                                           |
| React 组件文件、组件、类型 | PascalCase                                                                     | `GamePanels.tsx`、`GameState`                                             |
| 函数、变量、属性、方法     | camelCase                                                                      | `advanceTime`、`lastSimulatedAt`                                          |
| 模块常量                   | UPPER_SNAKE_CASE                                                               | `BASE_GAME_DEFINITION`                                                    |
| 机械内容 ID、主题 ID       | 英文 kebab-case，创建后保持稳定                                                | `extractor`、`supply-cache`                                               |
| 机械内容/主题文件          | 新建不带版本号，版本只进定义元数据；既有文件（含 legacy 与在用的 v1/v2）不改名 | 新建 `supply-cache.ts`，不再 `expedition-v15.ts`                          |
| 单元测试                   | 与被测文件同目录 `.test.ts`                                                    | `engine.test.ts`                                                          |
| 浏览器验收                 | `tests/browser/*.spec.ts`                                                      | `game.spec.ts`                                                            |
| 文档                       | 一个主题一个文件；日期前缀只用于证据/记录，并归入 `docs/历史资料/`             | `docs/2026-10-12--工程重整方案.md` 批准后归档进 `docs/历史资料/工程记录/` |
| Rust 源码/函数/变量        | Rust snake_case；结构体/枚举 PascalCase                                        | `save_store.rs`                                                           |

UI 中文文本不作为 ID。存档保存 ID 和事实，不保存中文名称、图标、计算结果或主题。
文件命名和依赖边界由 `check:architecture` 自动检查；类型/变量命名、Promise、React hooks 由 ESLint 检查；格式由 Prettier 和 rustfmt 检查。

## 单一事实源职责

每个关注点只有一个权威文件；其他位置只放指针，不复制正文。新增或移动文档、规范前先确认权威位置，再更新指针。

| 关注点                     | 唯一权威                              | 其他位置          |
| -------------------------- | ------------------------------------- | ----------------- |
| 给执行者的硬约束与入口     | `AGENTS.md`（≤ 25 行）                | —                 |
| 分层、目录、数据路径、协作 | `docs/架构说明.md`                    | AGENTS.md、README |
| 编码、命名、检查规则       | 本文件                                | AGENTS.md         |
| 阶段、依赖、验收、进度     | `PLAN.md`                             | README、阶段证据  |
| 玩法行为语义               | `docs/规划/轻量放置核心合同.md`       | PLAN              |
| 内容候选与台账             | `docs/内容资料库/`                    | —                 |
| 故事文献                   | `story-library/`                      | —                 |
| 阶段证据                   | `.cache/evidence/<阶段>/`（忽略 Git） | PLAN 只留结论指针 |

## 代码约束

- 使用 TypeScript strict、exactOptionalPropertyTypes、noUncheckedIndexedAccess；外部 JSON 从 unknown 开始验证。
- 游戏状态只读；规则纯函数产生新快照；时间由调用者注入。购买前先用旧产量结算。
- 余额和产量保留小数，显示层格式化；禁止为了显示将存档取整。超出安全数值范围显式拒绝，不写 Infinity/NaN。
- 同一动作的扣费、数量、解锁记录一起提交。失败不部分修改状态；时间结算独立保留。
- 外部副作用通过 ports；浏览器和桌面分别适配。浏览器不调用原生接口，规则不依赖平台。
- 类型正确不能替代数据验证。定义、主题、存档各有验证器；内容版本变更需设计迁移和补算边界。
- 错误必须可见、可恢复。保存失败保留内存进度和 dirty 状态；不清空用户存档。不使用空 catch 隐藏核心保存失败。
- 游戏核心、内容、主题、存档和运行时不引入外部业务库。扩大模块边界需同步更新规则与架构说明并说明理由。

## 依赖方向

`main.tsx` 是组装入口。`app` 只呈现运行时快照、主题和规则定义；`runtime` 调用 domain/persistence/platform ports；`persistence` 只验证规则数据；`platform` 实现副作用。规则层不向外反向依赖。测试可跨层组装完整合同，生产代码不能。

## 工作流

分层、目录、当前/目标保存位置以[架构说明](架构说明.md)为唯一合同。README 提供入口，PLAN 管唯一阶段进度，本规范不另维护路径表或任务状态。

S0 先完成有证据的盘点和实际整理，保持当前行为；通过阶段验收后再开始 P0。每项迁移/删除先说明原/目标路径、静态/动态/历史/测试/构建引用、原因与回退；不因旧文件或大文件直接删除，也不靠删测试或放宽门禁完成瘦身。移动 Windows 目录前核对绝对源/目标与边界。

每项协作声明输入 HEAD/资料版本、可写文件、整合负责人和交付位置。同一工作树一次一个写入任务，独立 checkout/worktree 才能隔离工程改动；共享入口、保存合同、门禁、锁文件和根文档由一个负责人串行整合。跨层必需修改列入本阶段任务清单，不要求对常规可逆改动反复询问用户。

原始交付、工作副本、独立故事正文、审核映射、交接包和缓存各用架构说明指定的位置。原型 DB/lease/profile 与环境一起隔离；工程文件不能充当用户存档目录。写完目录图不等于 S0 已执行瘦身。

1. 明确需求、原子行为和验收条件，优先复用既有接口。
2. 修改最小责任范围，新的机械内容和主题分别修改配置。
3. 跑格式、类型、静态检查、边界检查和相关行为测试。
4. 涉及界面跑浏览器验收；涉及 Windows 外壳跑 Rust 检查/测试和原生构建。
5. 更新文档的真实实现状态和限制。保持单一计划，避免散落多份相互冲突的路线。

推荐提交格式 `feat(domain): add ...`、`fix(runtime): ...`、`docs: ...`、`chore: ...`。小而完整的提交；锁文件随依赖提交。当前不配置强制 Git hook，标准命令和 CI 是检查入口。

## 自动检查

`check` 覆盖格式、类型、ESLint、文件命名/依赖边界及单元行为；`e2e` 覆盖真实浏览器的主题、购买、恢复、多标签页和错误导入；`native-check` 覆盖 rustfmt/clippy 与文件替换失败行为。CI 配置提供相同门禁，远程 CI 是否通过以实际运行记录为准。

## 故事资料与运行时代码的边界

类目、命名、资源来源/用途、生产链与成长候选统一见[内容资料库](内容资料库/README.md)。编辑资料、生效机械定义和展示文案各有责任源；文档不直接驱动运行时。科技树入资料库不等于加入首版系统，新行为仍须规则合同与兼容审查。新活动语义见[轻量放置核心合同](规划/轻量放置核心合同.md)，唯一实施顺序仍在根目录 PLAN。

故事资料的入口、正史/候选/历史状态、来源追溯和变更流程统一见[故事资料库总索引](故事资料库.md)。仍运行的 0.8《诸界救援局》设定与文案分别由[故事与内容设定集](故事线设定集.md)和[游戏故事内容索引](诸界救援局/内容索引.md)冻结保留；下一版名称、世界观、人物与主线从头设计，独立故事包与包外接入映射按[交接说明](交接/README.md)分工。旧版《失落航标》完整资料仅在 `docs/历史资料/失落航标-v12/` 维护。`docs/副本资料库/README.md` 是旧链接导航，不是第二份资料源。

Markdown 记录创作事实、证据、来源和候选关系，不是运行时输入。游戏行为以 `src/domain`、`src/content`、`src/themes` 和 `src/persistence` 为准；文档中的 ID 只有被代码消费并完成兼容性审查后才成为机械内容。历史 ID 不自动沿用到当前产品。新增或变更故事资料时，应更新责任文档和交叉索引；若要进入游戏，还需同步更新代码映射、内容版本/存档迁移评估及 `PLAN.md` 验收记录。

资料改动至少运行 `npm run check:narrative-docs`；它检查本地 Markdown 链接、核心编辑 ID、交叉关系词汇和索引中声明的实现路径。完整工程变更按本规范运行项目 `check`；叙事文档检查通过不代表内容已进入游戏或通过玩家试玩。
